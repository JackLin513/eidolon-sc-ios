# 自带密钥只存在用户的浏览器里，服务器不保存

原先用户填的自带密钥用 `EIDOLON_SECRET_KEY` 派生的密钥加密后存进数据库，跟着账号走。有些用户不愿意让服务器保存自己的 key，所以改为只存在用户自己的浏览器里（`localStorage`，按用户分开存），每次回合或通话时随请求发给服务器。请求一定要经过服务器：提示词里有私有的剧情库（ADR-0003），不能交给浏览器拼；工具调用和写记忆在后端做；通话的音频经 WebRTC 送到后端的管线，语音识别和语音合成都在服务器上调用。所以这项改动的意义是 key 不再落库、不进备份，而不是服务器从此碰不到 key。服务器只在内存里持有 key：文字回合持有到这一回合的后台任务（记忆、对话标题）都做完为止，通话持有到挂断、最后一轮的后台任务都做完为止。服务器也不再记下用户自带的 LLM 用的是哪个服务地址、哪个模型。

## 修订（2026-10-26）：酒吧的光顾持有到这次光顾结束

酒吧的一次光顾跨好几次请求（进门、每次上酒、「再试一次」），自带的 LLM 密钥只在进门时随请求发来，服务器在内存里持有到这次光顾结束（玩完、离开、被新的光顾顶掉或超时作废），两次请求之间也在。上酒和「再试一次」不再带 key。

## Considered Options

- **默认存本地，另外提供「跟账号同步」**：多设备用起来方便，但加密存储、备份这套都得留着，还要多维护一条路径；对外也只能说「默认不存」，在意这件事的用户并不会因此放心。
- **存进 IndexedDB，用不可导出的 WebCrypto 密钥加密**：挡不住 XSS，因为注入的脚本照样能拿这把密钥解密，而且 key 每次都要以明文发给服务器，拦截请求同样能拿到。它只能防有人直接拷走浏览器的数据文件，多出来的复杂度不值。
- **严格的 nonce CSP**：能挡住内联注入的脚本，但 Next 的 App Router 要用 nonce，就得把所有页面改成动态渲染，落地页的静态渲染和首屏优化（ADR-0016）都要放弃。现在改加一个宽松些的 CSP：允许内联脚本，但只能加载本站的脚本、只能向本站发请求（立绘素材的地址 `EIDOLON_STAND_ASSETS_URL` 除外，立绘和招呼要从那里加载；这个地址部署时才知道，所以 CSP 由前端的 proxy 在运行时加上，不写死在构建里）。React 默认会转义输出，全站唯一一处插入原始 HTML 的地方内容是固定的，出现 XSS 的风险比较低。
- **上线时把已存的 key 一次性发回浏览器**：用户不用重填，但要多写一段只用一次的代码，而且违背了「存进去就拿不回来」。

## Consequences

- 上线时删掉已存的自带密钥，所有用户都要重填一次。备份里加密的旧 key 要等那些备份过期（ADR-0012，最多 30 天）才消失，旧备份不改。这修订了 ADR-0012 里「恢复备份以后要能解开自带密钥」那一条。`EIDOLON_SECRET_KEY` 仍然要保存，因为后台保存的部署者 key 和封禁名单还用它。自带密钥本身不再依赖这个变量，不设它也能用。
- 换设备、换浏览器或清除浏览器数据，都要重新填。主动登出或删除账号时清掉这个浏览器里的 key；其他设备上的 key，服务器无法清除。
- 浏览器端一旦出现 XSS，脚本就能读到 key。我们接受这个风险，用 CSP 缓解。
- 限额豁免按这次回合或通话实际带了哪些 key 来判断。管理者看不到用户填没填自带密钥，只能从用量里看出有多少回合和通话用的是自带密钥。
- key 会出现在请求体和服务器内存里，所以服务器的日志和报错不能带出 key：第三方库的调试日志要关掉；服务商的报错原文里如果出现 key，转述前要替换掉。

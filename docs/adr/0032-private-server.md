# ADR-0032：一个自托管的私有服务只管「包从哪来」和「公告在哪看」

日期：2026-11-06
状态：已接受

## 背景

内容包几百 MB（剧情、立绘、酒吧各一份），一直是人工搬运：Mac 上导出 `.eidolonpkg`，用 `devicectl`
或隔空投送传到手机，再从设置里导入。自己用还行，把包发给朋友就成了教学：先想办法把文件传过去，
再一步步教他导入；包发出去以后也不知道留在谁手里。公告更是没有地方发。

端上的判断一直是「单人单机、没有账号」（ADR-0001，`docs/roadmap.md` 的「永久不做」里也写着登录与
多用户）。但「给朋友发内容包」这件事，恰好需要知道对方是谁、包里哪一份是最新的。

## 决定

1. **只有一个服务端，而且它是可选的。** `server/` 里的 FastAPI + SQLite 跑在一台自己控制的机器上
   （容器、开机自启、前面挂证书走 HTTPS）。它只做三件事：邀请码注册、令牌登录、发内容包和公告。
   App 不连它照旧能用——对话、记忆、好感度全在这台手机上，服务器不存任何对话、记忆和好感度。
2. **账号靠邀请码，令牌存钥匙串。** 注册要一次性、有有效期的邀请码；登录用用户名密码换一个不透明
   令牌（180 天滑窗续期），服务端只存它的哈希。没有 OAuth，没有 Sign in with Apple——这个 App 没有
   付费开发者账号，拿不到它们。
3. **包和公告是服务器唯一的内容。** 下载支持 `Range`，断了接着下，下完校验 sha256 再走原有导入流程；
   公告在 App 里读（对话页首的铃铛），已读游标只记在这台手机上。
4. **管理动作在 App 里，权限在服务端。** 管理员在 App 的「管理」页生成邀请码、停用账号、发公告、
   重新扫描包目录。角色没有任何接口能改，只能在服务器上用一条命令授予；每个 `/v1/admin/` 接口自己
   校验角色，普通账号调用一律 403。界面上藏不藏只是体验。
5. **服务端是一个可以照抄的部署单元。** 只需要 `server/` 这个目录：主机名、端口、数据目录、管理员
   账号全在部署时的环境变量或本机文件里，仓库里不写任何一台具体机器的信息。

## 后果

- **推翻了「永久不做：登录 / OAuth、多用户、邀请与封禁」。** 现在这句改成了「永久不做：作为对公众
  开放的服务部署」。它不改变 App 的运行前提：手机仍然是独立的，服务器只是分发的一部分。
- 仓库里多了第一段常驻运行的服务端代码，多一个要维护、要备份、要升级的东西——怎么部署、怎么升级、
  日志在哪、坏了怎么重启写在 `docs/server.md`。
- App 本体的更新仍然由使用者自己签名安装，这个服务只解决内容包。
- 服务器挂了、家里没网、朋友没登录，都只影响「下载包」和「看公告」两页，不影响和她说话。

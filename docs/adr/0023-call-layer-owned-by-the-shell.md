# ADR-0023：通话层由 App 外壳持有

日期：2026-10-31
状态：已接受

## 背景

现在的通话是对话页用整屏覆盖打开的一个页面：`ChatView` 自己拨号、持有 `CallSession`、处理事件、画结束卡，离开这个页面（返回列表、去设置、进历史、换衣装）就失去它。这与手机通话该有的样子不符——通话应当待在后台，翻完别的东西再回到它，期间她说的每一句都还在。

上游已经为此改过架构（ADR-0018「通话属于导航外壳」）：通话层属于导航外壳，不归某一页；页面之间换页不挂断，收起时只留一条通话条。上游的 `nextLayer` 把「未出现 / 展开 / 收起」作为纯状态转移写下来，并规定新的一通总是展开、同一通从拨号转接通保持收没收起、结束总是展开。

本仓库（ADR-0001/0015）的通话会话与状态机已经在核心层；缺的是把它从对话页手里交给 App 外壳。

## 决定

1. **一通电话由 App 持有。** `AppModel` 持有一个通话控制器，里面是唯一的一通电话：`CallSession`、当前 `CallState`、通话的角色、接通与结束的时刻、她正在说的那句话、只看文字与麦克风静音，以及通话层收没收起。对话页只调用它、画它，不再 `fullScreenCover` 一个通话页。
2. **通话层挂在根视图上。** `RootView` 在页面内容之上叠一层通话层，只要有一通电话存在就保持挂载：收起时整层移到屏幕外、不可命中，但不销毁，所以她的立绘、台词、只看文字与静音都留着；展开时滑回来。拨出第一通电话之前这一层不存在，返回之后销毁。
3. **收起与展开是核心层的纯规则。** 新增「通话层呈现状态」：未出现 / 展开 / 收起，转移规则照上游 `nextLayer`：
   - 新的一通从展开开始；
   - 同一通从呼叫转接通，保持当前收没收起；
   - 任何原因结束都回到展开（结束卡必须被看到）；
   - 收起只在进行中可用，展开只在进行中且已收起时可用；
   - 通话条只在「进行中且收起」时显示。
   App 只调用这些规则，不自己拼条件。
4. **通话条放在每一页顶上。** 她自己的对话页里在导航栏下方、不写名字；列表、设置、酒吧、别的角色的对话页以及历史、换衣装这些整屏页在页面顶部并先写她的名字；展开的通话层里不画通话条。通话条整条是一个按钮，点它回到通话，没有挂断。通话条所在的整屏页或弹层在通话层展开时自行让开（关闭自己），因为通话层画在它们下面，不这样做它们会挡住展开的通话。
5. **页首的「换衣装」换成「收起」。** 换衣装已经在 #37 移进对话页的「⋯」菜单；通话层页首左边的键与上游一致是收起，iPad 或外接键盘的 Esc 同样收起（结束卡上则是返回）。
6. **只有一通电话。** 从列表进入另一位角色的对话时，如果有通话在进行，先问「结束通话并进入？」；确认则按制作人挂断、照常落记录与事件，然后进入，且不显示结束卡；取消则留在列表，通话继续。设置、酒吧、历史、换衣装不打断通话。
7. **结束即展开，返回即离开。** 她挂断、时长或回合上限、麦克风被拒、掉线，任何结束原因都让通话层展开并显示结束卡；对话页在通话结束的那一刻重新读一遍对话记录、好感度与冷却（不在屏幕上时，下次打开自然读到最新的）。结束卡的「返回」把整层收起、回到当前页面。
8. **动效。** 收起与展开是同一个滑动（约 410ms、`timingCurve(0.24, 1, 0.4, 1)`，与上游 `ease-call` 一致）；系统开启「减弱动态效果」时不滑动。第一次拨出也从底部滑上来。

## 后果

- 通话期间立绘渲染器常驻（收起时暂停绘制），换来的是收起后回来一切原样；返回或通话被清除时才销毁。
- 每一页都要记得放通话条；漏放不会挂断电话，但会少一条回到通话的路。这一处由 `CallBar` 自己判断「进行中且收起」，页面只负责摆位置。
- 通话的状态从视图搬进控制器，控制器属于 App；视图只读它。这让「离开页面就丢状态」的问题从根上消失，也让以后在别处拨号成为可能。
- 这份 ADR 取代当前「通话盖在对话页上、离开即失去」的做法；与上游 ADR-0018 的取舍一致。

# ADR-0028：玩法页、礼物、抽奖、重置卡与成就放在端上

日期：2026-11-04
状态：已接受

## 背景

上游把礼物、抽奖、重置卡和成就做成服务端玩法：抽奖次数、背包、重置卡、成就进度、阶段解锁和奖励都在 FastAPI 的数据库里，由后台任务和事务保证一次只发一次；前端只展示。本仓库是手机独立运行（ADR-0001），没有登录、多用户、后台和运行记录，因此这些状态与规则必须搬到本机，并与现有的好感度、对话、通话、酒吧和内容包接上。

## 决定

1. **一级入口是「玩法」tab。** 根导航改为「对话 / 玩法 / 设置」（ADR-0027），酒吧从对话列表搬进玩法页；礼物和成就是玩法页的两张卡。设置成为独立 tab。
2. **礼物目录随内容包走。** `characters/gifts.json` 与 `gifts/<id>.webp`、`gifts/reset-card.webp` 由导出工具生成；内容包是礼物名称、稀有度、类别、下架和暖礼物标记的唯一来源。旧包没有礼物目录时，礼物页说明并关闭抽奖，对话不受影响；已经持有的礼物仍可送。
3. **数值逐字照上游。** 普通/少见/稀有 +0.3/+0.5/+0.7；喜欢 +0.3；暖礼物在经期或经前 +0.3；冷却中一律 +3.0，到 10 解除冷却；每日 2 次、最多 7 次、北京时间 0 点补、1% 重置卡、69/25/5 稀有度。礼物不占每日好感度上限，也不写回合、标题、追踪或记忆。
4. **送礼写成对话事件。** 事件带礼物 id、是否喜欢和当时的好感度变化，进入当前对话；当前对话已结束或不存在时新开一段并设为当前。聊天和对话列表显示「你送给{名字}一份{礼物}」，它是分隔线而不是用户消息；她下一轮或下一次搭话才回应，提示词旁白逐字照上游，暖礼物在提示词生成时按事件当天重算周期。
5. **成就进度、阶段和奖励同一事务。** 回合（打字和通话都算）、礼物、抽奖、通话时长和档位到过推进进度；天数按北京时间、同一天只算一次。第 n 阶段给 n 次抽奖，可以超过每日 7 次上限；每角色四个成就全部阶段解锁算集齐，给 1 张重置卡，一辈子一次。奖励按 key 记入 `gift_rewards`，重复调用不重复发；任一写入失败，动作、进度和奖励一起回滚。
6. **旧数据只补算一次。** 首次运行带成就的版本时，从现有消息、通话记录、礼物事件和好感度档位补算；旧通话没有时长按 0，抽过几次奖从 0 起。补算与奖励同一事务，失败不阻塞对话，下次启动重试；第一次补算出东西时显示一次性汇总，看过写标记。
7. **通话时长从接通到挂断。** `call_ends` 记 `connected_at` 与 `duration_s`；没接通的通话不写时长，旧行按 0，不做近似补算。
8. **酒吧第一次光顾完成额外给 1 次抽奖。** 与酒吧自己的「当天」（设备时区）不同，防重复按北京时间的一天记在 `gift_rewards`；到 7 次上限时不发也不记。结束卡只在真发到时显示「抽奖机会 +1」。这是对 ADR-0021 修订的再次修订。
9. **重置卡单独可用。** 它把所有低于信任（冷淡、疏远，含冷却中）的角色拉回 50 并解除冷却；信任及以上不动；没有可拉回的人不扣卡。使用不写对话事件、不触发成就、不清当天增益。
10. **状态只在本机。** 抽奖次数、背包、重置卡、成就进度与奖励不进数据包、不进统计、不写活动记录；删除历史对话不回收藏成就，调试改好感度不推进档位成就。密钥仍只在钥匙串。

## 后果

- 玩法完全离线，抽奖和成就不会跨设备同步；单机自用可以接受。
- #73 原写「新增 ADR-0027」，但 0027 已用于页面框架（`0027-page-chrome-newest-system.md`），本篇顺延为 0028。
- 2026-11-04（#94）：根导航增加「朋友圈」占位 tab；日历和她的周期搬进玩法，玩法页变为五张卡。玩法数据的规则不变。
- 内容包、用户库 schema 与导出工具都增加礼物/成就相关内容；旧内容包仍能用，只是没有礼物。
- 成就的奖励写入必须留在触发动作的同一事务里，后续任何计数入口都要走同一个 `AchievementStore.keep`。
- 提示词新增礼物旁白和「先回应制作人说的话」提示；oracle 的六个原有场景不受礼物影响，礼物旁白由核心逐字测试补。
- 真机验收覆盖抽奖/背包、送礼分隔线、重置卡、她的成就面板、玩法成就、补算汇总、通话中禁送礼、VoiceOver、大字号、暗色和减少动态效果。

# ADR-0026：调试模式直接改本机数据，当前对话改为显式指针

日期：2026-11-02
状态：已接受

## 背景

真机验收对话引擎时，有些状态很难自然到达：某条记忆影响了她的回答、好感度停在某一档、对话刚被她结束。以前只能反复聊天、故意说越界的话或等冷却，或者把手机里的 SQLite 拿出来改。前者慢且不可重复，后者容易改坏。

这些操作会故意越过 `GLOSSARY.md` 写死的领域规则：「已结束的对话……结束不能撤回」「好感度……用户不能删除或重置」。如果不把例外写清楚，未来读代码的人会以为这些路径是 bug。

另外，「当前对话」原本是隐含规则——创建时间最新的那一段。要把一段历史对话重新设为当前，只能篡改它的 `created_at`，这会伪造对话的开始时间。

## 决定

1. **调试模式是设备本地的运行期开关，默认关闭，所有构建都有。** 它存在 `UserDefaults` 里，不跨设备；不引入 `#if DEBUG` 门槛。正常模式的界面和行为完全不受影响，关掉后聊天页不出现调试入口。
2. **入口只在角色对话页。** 设置里是开关；打开后对话页的 `⋯` 菜单末尾出现「调试」，弹出一个 sheet。设置页本身不提供改数据的操作。
3. **只做三件事：**
   - 列出**当前打开的那段对话**产出的记忆，勾选后批量删除；
   - 把好感度设成 0–100 的任意值，并按规则重算冷却；
   - 恢复已结束的当前对话，或把历史对话设为当前（必要时同时解除结束）。
4. **核心接口带 `debug` 前缀，是唯一的写入口。** 它们不经过判断模型、不调用对话/语音/生图服务，不写消息、对话事件、回合追踪、标题或统计；删除记忆和恢复对话只改既有的本地行。正常路径永远不调用这些接口。
5. **好感度的语义：** 数值夹在 0–100；`updated_at` 设为当前时间；`cooling` 由数值推导（0 开始冷却，0 以上结束冷却）；当天增益额度清零，下一次回合从干净的一天开始。改完不显示好感度变化的浮标。
6. **恢复对话要删掉 `ended` 事件。** 这条事件不只给人看：下一回合的提示词会把它作为旁白告诉角色「你结束了和制作人的对话」。只清 `ended_at` 会让她刚被恢复就被告知自己结束过。`hung_up` 事件不动。
7. **当前对话改为显式指针。** 用户库 schema v14 新增 `current_conversations(character_id, conversation_id)`，迁移时为每个有对话的角色指向当时最新的一段。创建对话时同步更新指针；`currentConversationID` 读指针；历史列表用指针判断「当前」并把当前排在最前；删除时用指针保护当前对话。没有指针的旧库或直接写库的测试回落到最新一段。
8. **写操作在回合进行中或通话进行中禁用。** 回合结束会写好感度和 `ended_at`，通话也在写同一个库；同时改会让改动被覆盖或状态打架。读取和浏览不禁用。
9. **正常模式仍然遵守领域规则。** 已结束的对话不能输入、好感度不能改、当前对话不能删除——这些约束只在调试页显式打开时由带 `debug` 前缀的接口绕过。

## 后果

- 用户可以在本机把数据改成正常规则不允许的状态（当前指向旧对话、已结束对话重新可输入、好感度被改过）。没有撤销，也不写审计日志；这是有意为之的开发工具行为。
- schema v14 是一次数据模型改动：`currentConversations` 成为「当前」的唯一来源。历史列表的排序从「创建时间最新」变成「当前优先，其余按创建时间」；正常创建对话时两者一致。
- `ConversationLifecycleTests` 里靠直接插一行「更晚的对话」来让旧对话变历史的测试需要改用 `beginNewConversation`，因为指针不会跟着裸插入移动。
- 调试页不做 UI 自动测试；按现有做法在真机手工验收。
- 如果以后不想要这个入口，可以在 UI 层加编译条件隐藏，核心的 `debug` 接口不需要动。

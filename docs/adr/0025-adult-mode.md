# ADR-0025：成人模式按内容年龄放行，并修正普通亲昵误判

日期：2026-11-02
状态：已接受

## 背景

上游判断模型只有一套全年龄规则：性骚扰或露骨的性暗示、辱骂、威胁都算越界；两次越界或累计伤害到阈值，她就会结束对话。端上照抄了这套规则（ADR-0004、ADR-0016）。

问题是它把两件事混在一起：

- 双方愿意、不带性意味的普通亲昵（拥抱、牵手、靠肩）也会被误判成越界，一次扣 10 好感，第二次结束对话；
- 内容包里明确 18 岁以上的角色，双方愿意的亲密内容也被算成越界，没有成人模式可用。

同时，上游规则对未成年角色的保护不能因为本地分叉而失效。内容包的 `characters.json` 已经带有结构化 `age`；当前内容包 29 位角色全部有年龄，其中 12 位 18 岁及以上。

## 决定

1. **年龄只认内容包的结构化 `age`。** 不解析人设文本、不用生日年份推断、不提供运行时改年龄入口。`age >= 18` 才算成年；缺失或小于 18 一律按未成年处理（fail closed）。
2. **成人模式是全局设置，默认关闭。** 只对成年角色生效；App 传「设置开启且当前角色成年」，核心层收到后仍按角色年龄复核，避免调用方漏传。
3. **基础判断题干修正对所有角色生效。** 双方愿意、不带性意味的普通亲昵不算 `out_of_line`；真诚表达喜爱或提出亲密请求不算 `manipulation`。这不依赖成人模式，修的是当前的拥抱误判。
4. **成人版判断题干只给成年角色。** 双方愿意的亲密或性内容不算 `out_of_line`；不受欢迎、被明确拒绝后仍推进、带强迫或威胁意味的内容，以及辱骂、威胁、人身攻击，仍然算越界。不新增判断字段；System One、Jev/Cloudflare 和对话模型判断器只换题干，JSON 契约不变。
5. **结束规则和好感阈值不变。** 真正的越界仍然两次结束、`fedUpAt` 仍然生效；成人模式通过让双方愿意的亲密内容得到 `out_of_line = false` 来避免误结束，而不是关掉边界。
6. **好感阶段只影响反应，不影响对话是否结束。** 成人模式下，冷淡/疏远可以害羞、犹豫、半推半就；信任以上更自然。回复提示词只在该角色成年且模式开启时加入这一段。
7. **文字和通话共用同一份有效成人模式。** 通话仍然保持短句、TTS 和挂断规则。
8. **不改写历史。** 已结束对话不自动恢复，旧消息、旧好感、旧越界计数不回填；只影响未来回合。

## 后果

- ADR-0004 的「逐字照抄」不再覆盖判断题干的普通亲昵修正和成人版；这是本地产品行为的分叉，需要在上游同步时单独维护。
- 未成年角色和缺年龄角色完全不受成人模式影响；内容包维护者必须提供准确年龄。
- 判断题 JSON 不变，四个判断服务继续共用同一套读取逻辑；只增加 age/turn 通知和 prompt 变体。
- 用户仍可打开/关闭成人模式；关闭后旧消息照常显示，之后的回合回到基础题干。
- 本地一次性解封数据不属于产品行为，不提供自动恢复或年龄编辑入口。

# 通话在端上自己实现

不跑 WebRTC 也不跑 Pipecat：麦克风经 `AVAudioEngine` 送 Soniox 实时识别，回合由 `EidolonCore` 的对话引擎产生，日语按段流式送 Fish Audio 播放，下一段在当前段播放时就开始合成。起止完全信 Soniox 的 endpoint 事件，不另加本地 VAD。静默接通，没有开场白。

她说的时候麦克风是关的：她的声音从扬声器出来，开着麦克风会被识别成制作人说的话，她就会回答自己；关麦也意味着**打断不在本次范围**（要打断就得处理回声消除），制作人这时说的话等她说完了再答。上游「最后一句话之后再等 4 秒算补充、补充丢弃整条回复重答」的做法这次没有做，识别到 endpoint 就直接进回合。

通话的结束按上游 `call.py` 的顺序判定，时机是每回合结束（含她说完了语音）和计时器到点却没有人说话时：她挂断 → 时长到顶 → 回合到顶，命中一个就进入结束流程。结束前先把已经排队的语音播完，再显示说明、写对话事件与追踪；一次通话只结束一次，结束之后不再接新回合。她的挂断只结束这通电话，不把整段对话标成结束，回聊天页还能继续打字；打字时她说的是「不想聊了」，通话里达到警告 / 结束阈值时说的是「要挂电话了」。

上限是可配置的（`CallLimits`：时长与她的回合数，缺省表示不限），从接通起算；本张票里仍是暂定的 60 分钟、不限回合，#25 把默认改成 10 分钟 / 40 回合并放进设置。

**后果**：回声消除、打断延迟、Fish 重连都要自己调；上游的轮次策略改动需要手工同步。

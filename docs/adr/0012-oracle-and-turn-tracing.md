# 用上游做对照组，并保留回合追踪

provider 全部协议注入，用假 provider 跑单元测试；另有对照工具：同一段输入分别喂给上游 Python 和端上引擎，把组装出的 prompt 逐字 diff。端上每回合落一份本地追踪（完整 prompt、判断模型原始输出、检索候选与 rerank 分数、降级原因、各段耗时），限制条数，可在设置里查看和导出。耗时按阶段记：等上一回合的记忆写完、判断、检索、对话模型首 token、整回合；旧追踪没有这些字段也照样读。通话结束的追踪另记每回合从识别完到回复、到首句、到第一段声音的耗时，因为 Fish 的合成和播放发生在回合入库之后，不属于回合自己的 trace。

**后果**：端上引擎必须能在没有 UI、没有麦克风的情况下运行（见 ADR-0013）。

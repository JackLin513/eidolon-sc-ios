# ADR-0041：成人模式下的原作亲密剧情召回

日期：2026-11-14
状态：已接受

## 背景

原作里与制作人有关的亲密场景只存在于剧情库（`episode_passages`），角色卡、facts、world 里没有。文字聊天里用户提到「之前那晚」时，判断模型常把这一回合读成 `need=memories`；但记忆库只存制作人的长期事实，往往没有对应记忆，于是既没有用户记忆，也不会去检索剧情，回复就丢掉了原作里的关系和气氛。

不能把 H 场景直接写进人格卡：会剧透、会占用大量 token，也会让非成人模式读到。也不能把剧情检索塞进普通 `references`：那会绕过成人模式开关。

## 决定

1. 只在 `adultMode == true` 时启用。
2. 只在判断结果为 `need == .memories` 且本轮没有可注入的用户记忆时触发（过去事件，但记忆里没有）。
3. 内容包可选提供 `characters/adult_episodes.json`，用 `routes` 按角色声明各自路线的场景 id；没有这个文件、或该角色没有路线声明，就不召回。
4. 只在该角色有 cast 的场景里检索，并且必须经过 rerank；分数低于 references 阈值、reranker 缺失或失败时都不注入，最多取 2 段。
5. 注入为 `# 回忆中的原作剧情` 的剧情参考，明确标注「原作剧情，不是这个存档的用户记忆」；不写入 memories，不改变记忆库。

## 后果

- 普通模式、没有重排模型、或没有剧情命中时，行为完全不变。
- 内容包作者需要维护场景 id 和路线归属；MLTD 等没有剧情库的包不需要提供这个文件。
- 这是「回忆气氛」而不是「复述原文」：提示词要求自然承接关系与气氛，不逐字照搬露骨台词，也不替制作人补写原作没有的选择。
- 已覆盖测试：成人模式注入、非成人模式不注入、非本角色路线不注入。

## 考虑过的选项

- **把 H 场景写进角色卡**：剧透、token 与分级都不可控。
- **让判断模型在 `need=references` 时检索**：会绕过成人模式开关，且普通引用会暴露给非成人对话。
- **不要求 reranker，直接取相似度最高**：容易把不相关或跨路线的场景塞进上下文。

# ADR-0024：文字氛围模式的回复格式分叉

日期：2026-11-01
状态：已接受

## 背景

ADR-0004 要求端上的提示词逐字照抄上游，让上游可以当对照组。但上游只有一套短句回复格式：文字对话和通话共用「一两句短口语」，解析器也只认 `<ja>` / `<zh>`。文字聊天因此被压得很短、很公式化，检索和记忆接通后仍然没有动作、环境、体温和停顿。

这条限制无法靠调整采样参数解决：要让文字聊天有氛围，就得让模型写更长的台词和场景描写；这需要新的提示词，也需要解析器、存储、界面和朗读认识 `scene` 块。上游没有这套行为，所以 **richText 分支必然偏离 ADR-0004**。

## 决定

1. **只在文字氛围模式下分叉。** 发送回合时增加回复风格：`text`（默认，上游格式）、`richText`（文字氛围模式开启时的文字回合）、`call`（通话与通话中打字）。`text` 与 `call` 的提示词仍逐字使用 `ReplyFormatInstructions.text` / `directed`，不跟着改。
2. **richText 是仓库自有的提示词。** 它要求 2–4 个块、每个台词段 2–3 句（最多 4 句）、场景块 1–3 句中文；保持角色口吻，允许身体接触和贴身细节，但不强制每段露骨。它是产品行为的一部分，不属于上游移植。
3. **线上格式增加 `<scene>…</scene>`。** 场景块只写中文、不带语气提示、不朗读；台词段仍是 `<ja>…</ja><zh>…</zh>`。解析器把回复解析成有序的回复块。
4. **Oracle 只覆盖不分叉的路径。** 六个 oracle 场景显式使用 `text` / `call`，继续与上游 `identical`；richText 用独立的 golden test 锁定，不参与上游 diff。
5. **默认开启。** 用户可以在设置里关闭，关闭后文字回合回到 `text`；已经写入的场景块照常显示。

## 后果

- ADR-0004 的「逐字照抄」不再覆盖 richText；以后同步上游格式改动时，只改 `text` / `directed`，richText 单独维护。
- 上游没有 richText 的对照组，格式保留率只能靠 golden test 和真实模型多轮测试；模型不遵守 `<scene>` 时，解析器按未知内容丢弃，不会崩溃。
- 通话永远走 `call`，场景块即使越界出现也不发声、不显示，保持通话的短句节奏和 TTS 延迟。

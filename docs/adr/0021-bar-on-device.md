# ADR-0021：酒吧（VA-283）放在端上

日期：2026-10-28
状态：已接受

## 背景

上游 eidolon-sc 合并了酒吧的两份规格（`.scratch/bar-visit/spec.md`「光顾」、`.scratch/bar-room/spec.md`「店面」）。上游的实现是服务端玩法：

- 光顾状态放在 FastAPI 进程内存里，每位用户同时一次，30 分钟不动作废；
- 四个接口（`GET /api/bar`、`POST /api/bar/visits`、`.../serves`、`.../retry`、`DELETE`），进门和上酒用 SSE 推 `visit`/`line`/`memo`/`waiting`/`retrying`/`failed`/`done`；
- 限额（每小时光顾次数、自带 LLM 不计数）、运行记录、看板、后台开关、账号、多标签互斥；
- 原版音频用一次性命令 `eidolon bar upload` 传到立绘存储桶的 `bar/` 前缀；
- 画面是 Next.js 里的 640×360 像素页面，素材在 `frontend/public/bar/`，字体「缝合像素」只在那一页加载。

本仓库（ADR-0001）是手机独立运行的 iOS 客户端：不跑 FastAPI / Next.js，没有登录、多用户和后台。ADR-0004 要求对话引擎与提示词逐字复刻上游；ADR-0012 要求提示词的差异由 oracle 逐字比对。

## 决定

1. **能逐字复刻的逐字复刻**：饮品目录、口味、来意与话题、写死的句子、点单抽取、判定、醉、备忘、名字检查、输出解析、提示词（`bar_prompt.py` 的每个块、顺序、两处缓存标记）与前端的纯函数（分页打字、调酒台、配方书、点唱机、缩放、设置、教程流程）都照上游的规则与常量搬到端上。提示词进 oracle：新增酒吧场景，端上与上游 `bar_prompt.prompt` 的产物逐字一致。
2. **依赖服务器的端上重做**：
   - 光顾状态放进端上的 `BarVisit` actor（`EidolonCore`），同样「同时一次、30 分钟不动作废、离开作废」；没有 HTTP/SSE，改成端上的异步事件流，语义照上游（句子按到达顺序、点单句扣到名字检查之后、`retrying` 清句子、`failed` 停住可「再试一次」、告别兜底照样玩完）。
   - 不做限额、运行记录、看板、后台开关、账号、多标签互斥；酒吧模块直接调端上的对话模型。
   - 奖励缩到端上真有的东西：当天（设备时区）第一次玩完记一笔 `rewarded`，好感度按每杯平均上升（最多 +0.5，从不降）；端上没有礼物/抽奖系统，不发抽奖，也不为它先建一套计数。
   - 光顾记录写自己的 SQLite 表（用户库 schema 升一版），只记结果不存台词。
3. **来意不接日程**：端上没有日程（README「还没做 / 已知」）。来意只从清单里抽，避开最近 3 次、`not_for` 照旧；日程相关的规则与原文不搬。
4. **「当天」按设备时区**：`ENTER` 的日期、当天角色、当天第一次玩完都用设备当前时区的日历日；这与 App 里「她的今天」（东京，`TodayPrompt`）是两件事，不互相复用。当天角色的种子是设备当天日期（`SHA256("/" + 日期)`），玩完过一次之后从全部角色里均匀随机。
5. **旧内容包不进店**：内容包格式低于 3（没有酒吧数据）时照 ADR-0003 整包拒收，要用酒吧就得先重新导入一个格式 3 的内容包；端上不存在「内容包能用、只是缺酒吧数据」的状态，所以也没有「需要更新内容包」这一层入口提示。酒吧素材包缺失时，入口显示「还没有导入酒吧素材包，进设置导入」，装好之前不进店。
6. **素材走导出包，不进仓库**：酒吧的画面素材与字体来自上游 `frontend/public/bar/`（其中外框在原版素材基础上由上游脚本再加工），原版音频来自本机原版提取目录（同上游 `frontend/scripts/bar-assets.py` 与 `bar upload` 的来源）。两者都由 Mac 上的导出工具打成**酒吧素材包**（`.eidolonpkg`，`kind: bar`），在 App 里和内容包、立绘包一样导入；仓库里只放导出脚本、清单和测试。理由同 ADR-0020：第三方素材与运行时版权、包体大小、更新互不拖累。
7. **画面用 SwiftUI 像素层**：照上游的 640×360 逻辑坐标搬到 SwiftUI，整体按 iOS 的可用区域缩放（iPhone 上是小数倍、像素化），所有文字用「缝合像素」在自己的像素画布上二值化后与画面一起放大；她的立绘复用通话层的 `StandRenderer`（ADR-0017），像素化、裁在客人窗里，按每句的情绪换动作。

## 后果

- 端上不需要网络服务，酒吧和文字、通话一样单机可用；代价是光顾不能跨设备、不能刷新接着玩（与上游一致：刷新即作废）。
- 酒吧多了三类内容：内容包里的饮品/来意/句子配置（格式版本 3）、酒吧素材包、用户库里的光顾记录；都需要导入路径、迁移与测试。
- 没有限额和运行记录，端上多玩几次没有成本保护，这在本机自用的前提下可以接受；以后要加限额时，接缝是 `BarVisit` 的进门动作。
- 上游前端里的 React 组件不能直接复用，只复用纯函数规则；画面上游验收过的手感（拖材料、小数缩放的像素字）需要真机验收。

## 修订记录

- 2026-10-28：奖励从「1 次抽奖 + 好感度」缩为 `rewarded` 标记 + 好感度（端上没有礼物/抽奖）；「当天」从北京日期改为设备时区，当天角色的种子随之改为设备当天日期；补「旧内容包不进店」与素材包缺失的行为。原因见 #52 的规格复核：原决定把上游的服务端概念搬到了没有对应系统的端上。
- 2026-10-29：第 5 条改成实际做法——格式低于 3 的内容包在导入时就被拒收（ADR-0003），「需要更新内容包」的入口提示永远到不了，留着只会让人以为有一个不存在的状态；素材包缺失的入口提示照写。

# 判断模型改用 System One（默认阿里云百炼）

取代 ADR-0005 里「端上不复刻 System One 协议」的结论。现在默认用百炼的 `decision-model-preview`，一次 `POST {base}/systemone` 问完六道题：好感五档、出戏、操纵、需要查资料、回顾剧情、关于制作人。答案不是结论而是概率，按模型族的阈值读：五档取概率最大的那一档，两档并列按「无影响」，是非题达到阈值才算「是」；检索需求按 recall → references → memories → nothing 的固定顺序定。题目文本、五档情景描述、四族阈值表逐字照抄上游，集中在一处只读文本（`JudgeQuestions.swift`、`SystemOne.swift`）。对话模型只管说话，判断不再受它的 JSON 服从度影响。设置里可以在「阿里云百炼」和「对话模型」之间切换；百炼需要业务空间 ID、地域、模型名和密钥。

**为什么改**：上游的六道题和阈值是调校过的，chat 模型一次性判断好感度时服从 prompt 的程度不稳定，出戏和操纵两个判断也做得糊；照抄协议才能得到上游相同的手感。百炼国内可直连，不需要代理。ADR-0005 留的 `JudgeProvider` 协议正好让两者并存，切换只是一项设置。

**代价**：多一个服务的账号、密钥与费用；地址要按「业务空间 ID + 地域」拼，配置比填一个 chat 地址麻烦；模型族不认识时退回 Jev 的阈值，可能和上游对该模型的调校不一致；`model_not_found` 之类的错误要靠可读提示告诉生产者；仍要在 5 秒内答完，超时与非 2xx 都按判断失败降级——好感不变、仍按 `references` 检索、回合继续、原因进追踪（ADR-0011）。

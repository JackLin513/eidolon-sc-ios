# ADR-0031：面对面是对话的语境，不是新页面

日期：2026-11-05
状态：已接受

## 背景

文字对话默认是「发消息」的媒介：她在气泡里说话，照片是「发」来的附件。制作人感觉照片和对话有隔离感，希望有一种「你们就在同一个空间」的说法，照片也顺理成章变成「他拿相机拍她」，而不是她自拍发过来。

现有零件里，通话层已经有全屏立绘、台词卡和打字输入；但通话带着麦克风、挂断、冷却和时长，不适合拿来当「换个语境聊天」。照片生成则完全不必知道镜头是谁——只差提示词。

## 决定

1. **它只是对话页上的一个开关。** 不新增页面，不新增对话引擎，不改消息结构。输入框上方新增一行工具栏，第一个按钮是「面对面」，以后的功能也放这里。
2. **开关属于对话。** 对话表加一列 `face_to_face`（schema v22），新对话默认关；离开再回来、打开历史对话都保持当时的语境；删对话一起删。还没开始的新对话，开关状态随第一条消息写进新对话。
3. **开关只改语境，不改记录。** 打字回合仍是同一段对话、同一份记忆和好感；`NowPrompt.Talking` 多一个 `inPerson`，告诉她「你们正面对面说话，不是发消息，也不是打电话」。
4. **照片的镜头跟着语境走。** 面对面时，制作人要照片 = 他拿相机拍她：提示词让她默认写 `shot: other`，像他看着镜头按快门；他明确要自拍时才写 `selfie`。没配生图时说「没法拍照」而不是「发不了照片」。画什么仍由她的标签决定，生成引擎、额度、成人规则都不变。
5. **通话不受影响。** 通话本身就是当面/实时语境，不读这个开关；判断模型、记忆和回合格式也不读。
6. **切换在回合之间生效。** 正在回复时开关禁用，避免同一回合的语境半途改变；历史消息不重写。

## 后果

- 面对面不会改变他说的话被理解的方式（判断只看文字），只改变她如何理解媒介和照片的拍摄者。
- 开关是每段对话的，不提供全局默认；想做「所有对话都当面」就在每段对话里打开。
- 工具栏从此是对话页的扩展点，加功能不再挤进输入框。

# 镜像拿不到的剧本和立绘文件，改从游戏的资源服务器拉

ADR-0004 和 ADR-0011 让原文剧情和立绘都依赖 ShinyColorsDB，当时把「自己写下载器解包游戏资源」留作镜像失效时的后备。现在把这条后备做了，但只做文件这一半：镜像的 viewer 或 CDN 拿不到某个剧本或立绘文件时（没有、连不上、发来的不对），改从游戏自己的资源服务器 `shinycolors.enza.fun/assets` 拉。镜像本来就是从那里原样转存的，实测剧本和立绘逐字节相同，路径也一样。新卡的文件常常官方先有、镜像后收录，这条路平时也有用。

先问镜像、拿不到再问官方。镜像照旧是主力，对官方服务器的请求只在镜像缺文件时发出，和镜像共用每秒一次的节奏。

官方服务器按路径加盐的 sha256 存文件，JSON 和 atlas 用游戏自带的固定 key 做 XOR、再 gzip；`?v=` 只是破缓存用的，不带也返回最新版，所以不需要拉 26 MB 的资源清单。没有的路径不返回 404，而是 200 加游戏首页 HTML，维护时可能也是这样。所以镜像连不上时，官方的「没有」只有在它这次已经发来过文件之后才算数，不然当作镜像的错误，免得维护期把一批剧本标成没有。

## Considered Options

- **官方优先、镜像兜底**：原文直接取自源头，但每次同步都要大量请求官方服务器，更直接地碰 enza 利用规约第 9 条（禁止用工具获取信息）。
- **连目录一起换成官方**：卡、剧情和卡的对应、标题、衣装名都是游戏 API 的 master data，要登录态才能拿，不做。

## Consequences

- 这条后备防不住 ShinyColorsDB 整个站挂掉：要拉哪些文件仍然由镜像的 API 决定（卡和剧情的目录、相册、衣装列表），API 挂了就不会去问官方。要防住这种情况，得自己存一份目录数据，留到以后。
- 游戏停服时官方服务器也会一起消失，那时反而可能只剩镜像。
- 游戏改了文件名哈希或加密方式，官方这条路就断了；镜像还在的话不影响同步，只是少了后备。
- 从官方拉到的剧本照样不进仓库、不公开，沿用 ADR-0003。

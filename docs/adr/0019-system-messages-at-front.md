# 多条 system 消息合并到最前

端上拼出的提示词与上游逐条相同（ADR-0004）：人设与设定、制作人档案、检索到的资料与「此刻」都在 system 消息里，其中「此刻/好感度/检索结果」那条在历史之后、制作人这句话之前。但端上直连的 OpenAI 兼容服务（SiliconFlow 等）只接受一条 system 消息，而且必须在最前。`OpenAICompatibleChatProvider` 因此在发请求前把所有 system 块按原顺序用空行合并成一条，放在最前；各块的文字与块之间的顺序不变，只是位置变了。

**考虑过的选项**：把后段的 system 改成 user 或 assistant 消息（角色变了，模型行为可能不同）；要求换一个支持多条 system 的服务（换模型就坏）；在拼提示词时就把内容并进第一条 system（与合并等价，但让提示词组装去感知某个服务的限制，破坏与上游逐字对照）。

**后果**：`tools/oracle/run.sh` 比对的是组装完成、尚未合并的消息列表，所以这条合并不影响 oracle；服务对 system 位置的敏感度覆盖不到，只能靠真机观察。合并由 `mergeLeadingSystemMessages` 开关控制，别的服务或测试可以关掉。

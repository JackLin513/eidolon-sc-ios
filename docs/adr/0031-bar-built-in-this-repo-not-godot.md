# 酒吧在本仓库里用现有的前后端做，不用 Godot、不开新仓库

酒吧是一个像素风的视觉小说加调酒的玩法，曾考虑用 Godot 做、放进新仓库或拆成 monorepo。最后决定作为玩法页的一个子页，用现有的 Next.js 前端和 Python 后端做：立绘必须是通话层那套 Spine 3.6 素材，而官方 spine-godot 只读 4.x 导出的数据，我们又没有编辑器授权去重新导出（ADR-0009）；登录、限额、抽奖、好感度、判断模型都已经在这里，Godot 的 web 导出要另外打通，包也有几十 MB。本仓库本来就前后端同处，不需要再开 monorepo。

## Considered Options

- **Godot web 导出，嵌进玩法页**：做游戏更顺手，但播不了 3.6 的立绘，要么换成静态图，要么等哪天能重导 4.x。
- **新仓库**：游戏代码和主应用分开，但接口、登录、部署都要跨仓库对齐，而这个游戏的胜负和奖励本来就要服务器判。

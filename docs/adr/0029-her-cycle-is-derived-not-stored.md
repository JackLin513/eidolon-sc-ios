# 她的周期不存库，由种子、纪元日和冻结的权重表现算

每位用户的每位角色各有一个周期（见词汇表「周期」）。她真实的周期不写进库：从一个固定的纪元日起，第 0 个周期的开头往前随机偏移，第 k 个周期的长度和经期天数只由（种子, k）的哈希加上一组权重表决定，逐个累加到今天。种子在有 `EIDOLON_SECRET_KEY` 时用它经 HKDF 派生的钥匙对用户和角色做 HMAC，仓库公开也没法照代码算出她的周期；没设密钥时直接哈希，照常开。这样同一天无论什么时候算结果都一样，过去的周期永不改变，开关关上再打开她也还在本来的位置，删账号、导出导入都不用管她的周期。

## Considered Options

- **每个周期开始时抽一次、存进库**：可以随时改参数而不影响已经过去的周期，但要多一张表、一个按日推进的写入，删账号和数据包都要多照顾一类数据；按「统计和遥测要轻」的原则不划算。

## Consequences

- 纪元日、权重表、抖动范围、哈希方式和 HKDF 的 info 等于冻结了：改任何一个，所有她的周期都会整体跳一次，用户已有的记录和她对不上。代码里在这些常量旁注明。
- 部署者改 `EIDOLON_SECRET_KEY`、用户删账号重注册、把数据包导入另一个账号或部署，她的周期都会重抽；用户的记录照常带走，只是和新的她对不上。接受，不做迁移。
- 日期按制作人档案的时区算；改时区最多让她整体挪一天。

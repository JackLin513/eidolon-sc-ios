# 搭话是独立的记录，不是没有用户那一段的回合

角色要能在用户没和她说话时自己先开口（搭话）。我们没有把它当成一种只有她那一段的回合，而是让它和回合、对话事件并列，做第三种记录。「回合」从用户那一段开始，这一点词汇表和代码里处处都用到：回合号和对话标题的「第 3 个回合」数的是用户那一段，历史截取从用户那一句切，对话事件按用户那一段的时间排，统计、判断模型和好感度也都看用户说的话。把搭话算成回合，这些地方都得改，而且每改一处都要再问一遍「没有用户的话时怎么办」。单独做一种记录，这些地方就都不用动，只需要在用到搭话的几处（历史、对话记录、对话列表最后一句、运行记录）把它接进来。

## Considered Options

- **没有用户那一段的回合**：模型和前端都只认一种「她说的话」，但「回合」的定义要改，所有从用户开始计数的地方都要跟着改。
- **一种对话事件**：对话事件本来就不是回合，不经过判断、不计入限额、不变成记忆，这些都对得上。但对话事件记的是这段关系里发生的事，比如挂断、结束、送礼，界面上显示成旁注；搭话是她说的话，有日语和字幕，要像回复一样显示。

## Consequences

- 搭话放进给模型的历史时，跟着它后面的那个回合一起截取；用户还没回的搭话一律带上。写法要所有 LLM 服务都能接受，因为自带 LLM 的用户可能用任何一家，有的服务不接受连着两句都是她的、或者以她开头的历史。
- 搭话会不会被用户看到要记在服务器上（没看过的搭话），因为服务器离线判断发不发时要用到。对话本身仍然没有已读和未读。

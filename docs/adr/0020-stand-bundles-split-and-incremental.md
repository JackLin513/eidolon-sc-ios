# 立绘拆包：全量立绘包与增量更新

取代 ADR-0018 里「立绘素材随内容包分发、先打默认衣装加几套」的结论。立绘改为和内容包分开的独立归档：内容包只带故事内容；立绘包第一次导全量（29 个角色、1522 张卡、2034 套衣装），之后追加只导增量。立绘包默认全量，导出工具保留 `--stand-cards N` 缩小。App 设置里两个独立导入入口（剧情内容 / 立绘素材），各自原子安装、互不覆盖；旧设备升级时把 `current/stand` 自动迁移到独立立绘目录，旧立绘继续可用。

增量靠本机的立绘清单：App 维护 `stand-index.json`（衣装编号 + 文件大小/校验值），导出工具用 `--device` 通过 `devicectl` 自动拉取，或 `--have` 手动给一份；只把缺失/变更的素材和更新后的衣装清单打进增量包。增量包导入时合并，不删已有衣装；全量包替换立绘目录。内容包继续全量更新，但不再包含立绘，所以剧情更新只传小包。每个包本身仍然全有或全无（ADR-0003），增量包只是在立绘目录上合并，不会把内容包和立绘包绑成一次安装。

设置里的立绘预览复用通话页的 `OutfitPickerView`：点卡片只预览，「穿这套」才持久化；换装后保留当前立绘指令。缩略图先保持端上生成，实测 62 张卡的手感后再决定是否把上游缩略图打进包。导入 GB 级包时提供进度、防锁屏和临时包清理。

**考虑过的选项**：继续把所有立绘放进内容包（每次剧情更新重传 2.4 GB，不选）；每角色只打 6–8 张卡（数据不对齐上游，不选）；立绘改成运行时从上游 CDN 按需下载（更接近上游，但破坏离线包模型，不选）；手机上加 HTTP 接口给 Mac 读清单（多一套监听/鉴权，不选）；缩略图也打进包（先实测端上性能，暂不做）。

**代价**：两种包、两个导入入口、独立立绘目录、增量清单/合并/迁移，代码与格式都比单包复杂；2.4 GB 全量导入要几分钟，峰值占几 GB；62 张卡的端上缩略图首屏偏慢；增量依赖手机清单，不同步时要回退全量；包继续变大时要处理 ZIP64。

详细设计、数据布局、导入流程和验收见 [`docs/design/stand-bundles.md`](../design/stand-bundles.md)。

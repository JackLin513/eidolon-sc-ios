# 酒吧（VA-283）在端上

上游两份规格（「光顾」`.scratch/bar-visit/spec.md`、「店面」`.scratch/bar-room/spec.md`，对照的上游 tip `cd3e854a`）在 iOS 端上的落地：结构、接缝、常量、状态契约、素材包与导出、与上游的对照。取舍与边界见 ADR-0021；票是 #52 的子 issue。

**上游是唯一的规则来源。** 本文只写端上要做的事和端上与上游不同的地方；凡是写「照上游」的，实现前先打开对应上游文件核对一遍，不要凭记忆写。

## 一份内容的三种包

| 包 | manifest `kind` | 内容 | 版本 | 导入 |
| --- | --- | --- | --- | --- |
| 内容包 | `content` | 剧情库、角色、世界设定、节假日，以及 `drinks`、`bar_visits`、`bar_lines` 和角色的酒吧五列 | 格式 **3** | 设置 → 剧情内容 |
| 立绘包 | `stand` | Spine 衣装（ADR-0020） | 不变 | 设置 → 立绘素材 |
| 酒吧素材包 | `bar` | 上游 `frontend/public/bar/` 的 `img/` 与 `fonts/`（缝合像素 + OFL），以及原版音频（`bar_audio.json` 清单里的曲目与音效） | **1** | 设置 → 酒吧素材 |

- 三种包各自原子安装，互不覆盖；装到一半失败不留下半个目录。
- **内容包低于格式 3**（没有酒吧数据）：整包都不读（ADR-0003），启动时就要重新导入内容包，酒吧入口到不了；端上不存在「内容包能用、只是缺酒吧数据」的状态。
- **酒吧素材包缺失**：入口显示「还没有导入酒吧素材包，进设置导入」，装好之前不进店（画框、像素字都来自这个包，端着空壳进去没有意思）。
- **入口卡**：端上好感和礼物没有开关，所以只有两种状态——今天还有奖励（「今天第一次光顾有奖励」）、今天已经领过（「今天的奖励领过了」）。奖励在端上只有好感度，卡片文案不要提抽奖。

- **酒吧素材包部分缺失**（清单里有、包里没有）：不拒绝安装；缺的图回退成占位块、缺的曲子从点唱机里去掉、缺的音效静音，其余照常玩。导出工具的清单校验负责在 Mac 上把这些报出来。

## 提示词与她的资料

- 酒吧有自己的一套提示词，不和文字回合共用前缀；**不给工具、不检索记忆和剧情库、不调判断模型**，只依赖对话模型。整次光顾的「这次光顾的块」不变，每次调用只追加「这次要写什么」，前面写好的台词按 user/assistant 接上。
- 思考强度跟设置里的「对话模型 · 文字回合」那一项，不新开设置。两处缓存标记的位置与上游 `bar_prompt.py` 相同（共用块末尾一处，末尾那条 user 一处）。
- **「此刻」照上游 `her_now.CARRIES["visit"]`**：只带**好感度档位那几句 + 东京的今天**（她的生日、其他偶像的生日、节假日、往年今天的演出）；不带时间、不带制作人的生日与上次往来、不带日程、不带周期。端上没有日程与周期，来意只从清单抽。
- 进门时按话题检索她的资料（复用文字回合的检索接缝）：重排后取前 3 条，不设阈值；同一位角色、同一个话题只查一次（进程内缓存），向量化或重排失败就不带资料进门、下一次再查。

## 一次光顾的状态机

状态：`进门中 → 写台词 → 等上酒 → …（重复）→ 已告别`，以及旁路 `出错停住`、`已作废`。

推给画面的事件（顺序即契约）：

1. `visit(visitID, characterID)`：进门成功，抽好的角色。先推它，别的都在它之后。
2. `line(speaker, emotion, ja, zh, isOrder)`：一句完成的台词，按到达顺序。情绪七种之一，不在七种里按 `calm`。
3. `memo(text)`：紧跟点单句之后，同一单只推一次。
4. `waiting`：这次调用写完了，等她这杯酒。
5. `retrying`：这次调用失败、正在重来；**画面清掉这次调用已经推过的 `line`/`memo`**，回到调用之前。
6. `failed(message)`：重试后仍失败；停在这次调用之前，等「再试一次」或离开。
7. `done(reward)`：告别写完（真写或兜底句），这次光顾结束；`reward` 只有「好感度有没有加」，没有抽奖。

规则：

- **上一杯**：先推一句制作人的「请慢用」（`line`，speaker 为制作人），再开始下一次调用；判定只认端上按规则算出来的那份，界面不显示档位。
- **调坏的**：对不上任何配方就不能上，可以重来；上错的那杯不能重做，按上错继续。
- **清句子回放**：`retrying` 时画面不只删掉这次调用推的句子，还要把她那句话之前的一页和她的心情放回来（上游 `lib/barScene` 的 mark / resume）。
- **调酒台怎么开**：这一单最后一句点过去才开；打开时文本框显示这一单的备忘（制作人口吻），备忘与「等她上酒」谁先谁后都可以（上游两种顺序都接受）；上酒之后台子收起、杯子倒掉。
- **点单句扣留**：带 `order="true"` 的那一两句（没标就取最后一句）先不推，名字检查过了再推，紧跟 `memo`。重写只取点单句，不重推前面的句子。
- **重写**：不该说名字的说法里出现任何饮品的英/日文名（不分大小写、全角半角）就重写一次；该说名字的没说出目标名字也重写一次；还不过换 `bar_lines` 里这种说法的模板句（打比方的模板句改按「条件叠加」算）。
- **重试**：超时、模型报错、格式不合格各算一次失败；重试 **不重抽点单卡**。`retry()` 只在 `failed` 后可调，否则是错误。
- **告别兜底**：告别那次调用两次都写不出来：反应用该档位的兜底句、告别用醉没醉那组，**照样算玩完、照样发奖励**。
- **离开 / 断开**：画面离开时结束这次光顾（作废）；调用进行中断开同样作废；告别调用写完之前断开不算玩完。作废都不写记录、不发奖励。
- **同时只有一次**：再进一次，旧的作废。
- **30 分钟**：最后一次动作到现在超过 30 分钟就作废。计时用墙钟；App 回前台、每次操作前都检查，不能只靠定时器（iOS 在后台会挂起定时器）。
- **App 被杀**：光顾只存在内存里，被杀即丢失，不写记录（与上游重启一致；端上不需要额外持久化）。
- **面板切换**：进店期间切到别的页面等于离开。
- **切后台与锁屏**：不算离开（用户定，与上游「断开即离开」不同）。正在写的那次调用会被系统挂起或掐断，回来时按这次调用**失败**处理：推 `failed`，可以「再试一次」接着走，不重抽点单卡、不作废这次光顾；如果离开前台已经超过 30 分钟，回来整次作废（这一条优先）。

## 当天、角色与种子

- 「当天」一律按**设备当前时区**的日历日（`yyyy-MM-dd`）。这和 App 里「她的今天」（东京，`TodayPrompt`）不是同一件事：前者是制作人的一天，后者是她的日程与生日；不要互相复用。
- 当天第一次玩完前，来的人是**今天的角色**：用 `SHA256("/" + 设备当天日期)` 作种子，在内容包角色的顺序里取一位；同一天怎么重进都是她，换一天换人。玩完过一次之后，从全部角色里均匀随机。
- 冷却中、好感度低的角色不剔除。
- 「当天第一次玩完」「奖励」都看进门那天（设备时区的日期），跨零点按进门那天算。

## 记录与奖励

- 用户库 schema 8：`bar_visits`（角色、进门与告别的时刻、进门那天、来意、话题、每单的 JSON、醉没醉、有没有发奖励），不存台词。
- **玩完**是一个事务：新增一行 + 加好感度一起提交；任何一步失败都不留下记录。`rewarded` 为真的条件是：这一天（设备时区）没有更早玩完的行，并且好感度加成功。
- 奖励只有两样：`rewarded` 标记与好感度（**端上没有礼物/抽奖系统，不发抽奖**）。结束卡写好感度上升；没有上升时只写告别。
- 好感度：每杯按判定分取平均，最多 +0.5，从不降；**冷却中也加**、加过解冻线就解除冷却、不受每日上限、不留对话事件。
- 中途离开、失败结束、超时作废：什么都不写、什么都不给。

## 端上特有的行为

- **音频**：`AVAudioSession` 用可混音的分类（`.ambient`），尊重静音开关；进店放点唱机的曲子，离开、进后台、拨打电话时停；音效与 BGM 不与通话语音抢占。
- **屏幕方向**：进店时请手机转到横屏、离开时转回竖屏（`BarOrientation`，转不动时不影响别的）；竖屏（宽度小于高度，比如系统锁了方向）时盖一层「请横过来玩」的提示。横屏时按安全区缩放，整张 640×360 等比放大、像素化。
- **竖屏提醒与安全区**：画框贴安全区，不留黑边也不裁切；缩放取放得下的最大倍率。
- **立绘**：复用通话层的 `StandRenderer`，像素化、裁在客人窗里；没有立绘包或角色没有立绘时客人窗空着，台词照常。
- **教程**：只在这一台设备上记住看过一次（用户库 `app_state` 的 `bar.tutorial`；这台设备只有一个用户，不按用户分键，上游 `eidolon.barTutorialSeen.<用户>` 也没有素材包版本这一层）；店门口可以重看；跳过和看完同样记为看过，中途离开不算看过。有音频时，走完和跳过都先去选曲界面，Ready! 之后才到门口；没有音频（素材包里没有曲子）时不讲点唱机那一节，教程直接到门口。跳过去哪由教程自己答（`BarTutorial` 的 `.skip`），界面不另写一份。
- **文字**：她的台词日语 + 中文字幕，制作人的只有中文；吧台上没有选项，没有输入框。
- **不留痕**：酒吧不写对话记录、不写记忆、不写对话事件，也不进对话列表；文字回合和通话里的她不知道酒吧里发生过什么。
- **无障碍**：像素字放大不糊靠 2 倍画好再阈值 + 最近邻（`.interpolation(.none)`）；屏幕整张缩放的倍率**一般不是整数**（贴安全区优先，见上），上游浏览器里也是这么缩的；按钮至少 44pt 的点击区（可以画得小，热区大）。

## 测试接缝

1. **状态机**（`BarSession` + `BarVisit`）：注入时钟、随机源、模型替身和临时用户库，从 `BarEvent` 流断言行为。覆盖：进门事件顺序、点单句扣留与备忘、重试与 `failed`、`retry` 不重抽、告别兜底、离开/超时/断开/被杀、当天角色与种子、时区、杯数、醉、判定、名字检查（三种触发与模板句）、玩完事务与奖励（同日只有一次、好感度冷却）。
2. **配置校验**（`BarContent`/`DrinkCatalog`/`BarTastes`）：用真实内容包与坏包各跑一遍；配方匹配覆盖 28 款、大杯、可选 Karmotrine、Flaming Moai 是调坏的、瓶装。
3. **视觉纯函数**：逐条对照上游 vitest 的用例（缩放、打字分页、调酒台、配方书、点唱机、设置、教程流程）。
4. **提示词**：`tools/oracle/run.sh` 的 `scenario-bar`（三种末段）与上游 `bar_prompt` 逐字一致；其余六个场景不许被带坏。
5. **真机验收**：一次完整光顾（含教程、换衣装后的立绘、缩放、音频、竖屏提醒）由人看过。

## 哪些是上游的，哪些是端上决定的

**照上游逐字的**（实现前打开上游文件核对，不要凭这份文档想象）：常量表的全部数字；七个事件与它们的语义；点单抽取、判定与「错在哪」、醉、备忘、点单卡；名字检查与重写、模板句；提示词的结构、两处缓存标记、不给工具、不查记忆与剧情库、思考强度跟文字回合；资料检索的查询、前 3 条、按角色 + 话题缓存、失败不带资料；「请慢用」；调坏可以重来、上错不让重做；酒吧不写对话记录/记忆/事件；教程流程与画法；画面坐标与视觉纯函数。

**端上自己定的**（上游没有这些概念，或者端上没有上游的对应系统；改动要在这里留痕）：

| 端上的决定 | 上游的对应 | 为什么 |
| --- | --- | --- |
| 「当天」按设备时区 | 北京日期 | 端上只有制作人这一台设备，没有服务器时区 |
| 当天角色的种子是设备当天日期 | 用户 id + 日期 | 端上没有用户 id，同一台设备本身就是一个用户 |
| 奖励只记 `rewarded` + 好感度 | 1 次抽奖（受每日上限 7）+ 好感度 | 端上没有礼物/抽奖系统，不先造一个 |
| 旧内容包（格式 < 3）入口提示更新，不进店 | 不存在 | 内容包是离线导入的 |
| 素材包缺失/缺件按项降级 | 存储桶随时可读 | 素材是导进来的包 |
| 音频用 `AVAudioSession`（可混音、尊重静音开关、进后台停） | 浏览器音频 | 端上音频会话 |
| 切后台、锁屏**不算**离开（已确认保留）；在途调用回来按失败处理；回前台超过 30 分钟才作废 | SSE 断开即离开 | iOS 的后台是系统挂起，不是用户离开；回来还能接着玩 |
| App 被杀：进行中的光顾丢失、不写记录 | 重启后内存里的光顾丢失 | 同上 |
| 教程「看过」记在用户库 `app_state`（`bar.tutorial`） | `localStorage`（`eidolon.barTutorialSeen.<用户>`） | 端上存储；这台设备即一个用户 |
| 按钮热区不小于 44pt；立绘复用 `StandRenderer` | 网页热区；网页立绘 | 端上 UI 框架 |

# 08: 拍板：三份规格的实现顺序、开关和上线

Type: grilling
Status: resolved
Blocked by: 02, 03, 06, 07

## Question

已定按「玩法页 → 日历 → 日程」的顺序各开 `feat/` 分支。要定：

- 每块从哪里开分支、谁建共用的接缝（玩法页的栏位、结构化生日数据、「此刻」里的新几句）；计划分支怎么处理。
- 开关：日历、日程各要不要部署者开关，还是跟着好感度和礼物；默认开还是关。
- 后台、看板要不要加东西（比如本周发布了哪些工作、排了多少）。
- 数据包导出导入、删账号、统计、隐私政策和其他对外文档怎么带上日程。
- 上线步骤：迁移、备份、公告草稿、README 截图。

每张票都调用 grilling 和 domain-modeling。

## Comments

- 票 06 定下：日程要有部署者总开关（和好感度、搭话同一类），关掉时玩法页不显示日程，提示词也不带，已经存的不删；用户这边没有开关。这张票要定的是开关放 `.env` 还是后台配置、默认开还是关。用户的方向是功能尽量做成能开关、像插件一样的。日程规格还要带上：`REACH_OUT_RULES` 里「只说平常的事」那条随日程改写。
- 票 07 定下：日历要用她们的颜色（月历上角色生日的蛋糕图标、日程的圆点和底色，每项单独注入 `herVars`），这超出了 DESIGN.md 的 The Her-Colour-Only-Here Rule，要先改这条规则。日历规格先上线，改规则就放进日历规格，日程规格接着补「格子块、选中时亮起的格子」。日程规格还要带上对话页更多菜单里的「她的日程」。

## Answer

2026-10-23 的 grilling 定下：

- **规格和票**：这张票关掉后，在计划分支上用 `/to-spec` 一次写完三份规格；拆票（`/to-tickets`）等开那一块时再拆，因为前一块合并后代码会变。
- **分支**：每块从当时的 main 开 `feat/` 分支（`feat/play-hub`、`feat/calendar`、`feat/schedule`），第一个提交从计划分支取来自己那份规格；第一块另外带上地图和 `GLOSSARY.md` 的改动（照每日任务那次的先例）。第三块取完规格以后，删掉计划分支（本地和远端）。
- **共用的接缝**：
  - 玩法页的卡片和子页注册由玩法页规格来建，日历只是加一张卡。
  - `characters.toml` 的结构化生日、DESIGN.md 里她的颜色那条规则，由日历规格来做。
  - 日历规格在 `about_turn` 里、`now_prompt` 旁边建一个「此刻要添的几句」的接缝，每句自己判断出不出现；先放当天的节假日和同伴生日两句，日程规格再往里加日程。
  - 周视图由日程规格来做（票 03）。
- **开关**：
  - 日历不加开关，一直开着；她知道节假日和生日也一直生效。这样好感度关掉时，玩法页至少还有日历一张卡。
  - 日程照搭话的写法：`.env` 里加 `EIDOLON_SCHEDULE`，不填时为 1（打开）；后台配置页加一张「日程」卡可以改。日程不调用模型、不依赖判断模型，和好感度、礼物各开各的。
- **后台和看板**：配置页只加上面那张开关卡，不列本周发布了哪些工作。看板「好感度」标签里加一格「本周排了日程的人数」，标签不改名。这一格不新增遥测记录，打开看板时直接对日程表查一次本周的数；不跟时间范围走（和好感度那一组一样）；日程开关关着时不显示。用户在意数据库负担（以后可能有 2000 到 3000 位用户），统计只留这一个数，以后判断「日程能不能取代每日任务」时用。
- **数据和对外文档**（各写进对应规格的最后一张票）：
  - 日程不进数据包（每周作废）。`docs/data-package-format.md`「不在数据包里」那一句和 README 的数据包那条补上日程。
  - 用户的日程表登记进 `database.py` 的 `USER_DATA`，每周的工作表登记进 `NOT_USER_DATA`，删账号和删除全部数据会一起删掉日程；删一段对话不碰日程。
  - 隐私政策：「存了什么」加「日程」一项，「管理者看不到」补上日程；日历的筛选只存在本机，不加条目。
  - 使用条款「玩法」那条补一句日程（没有奖励、每周作废）。
  - `docs/configuration.md` 的中、英、日三份加「日程」一节；README 中、英、日三份的功能列表加日历和日程，礼物那条改成「玩法」。
- **上线**：
  - 玩法页和日历都不改库，部署前不备份；日程加了新表，部署前手动备份一次。
  - 公告：玩法页上线时发一条短的（礼物搬进了玩法）；日程上线时发一条，顺带提日历。草稿由 agent 写进最后一张票，用户自己去后台发。
  - README 截图：玩法页上线时把 `docs/images/gifts.webp` 换成玩法页；日程上线时加一张排了日程的日历周视图。

# 10: 拍板：下线每日任务

Type: grilling
Status: resolved
Blocked by: 09

## Question

2026-10-23 重画目的地时定下：日程上线以后整块下线每日任务，成就留着。不是改头换面接到日程上：每日任务的界面、进度表、看板「每日任务和成就」里的三格、隐私政策和文档条目全部拆掉；日程不接手发抽奖，日程的回报只有好感度（票 09）。单独一块（`feat/retire-daily-tasks`），等日程合进 main、部署以后再开，不塞进日程那一块。要定：

- **抽奖次数怎么补**：拆掉以后抽奖只剩每天发的 1 次加成就；用户倾向把每天发的次数调大（`DRAWS_PER_DAY`），调到几，`MAX_DRAWS`（7）要不要一起动，词汇表「抽奖」那条里「做每日任务得到的不受上限约束」怎么改。
- **成就共用的东西留下**：幂等的发奖励入口、「发生了什么」记账入口、导航「礼物」上的点都是每日任务建的、成就在用，拆的时候留着；拆掉以后每日任务的代码和表（进度、到账记录）是删掉还是留着不用，已经写进库的每日任务记录和运行记录怎么处理。
- **界面**：玩法页里「每日任务与成就」那张卡（票 02）改成「成就」；礼物子页里每日任务那一节拆掉，成就那一小节的位置；「0 点换新」那句随之去掉。
- **看板**：「每日任务和成就」小节改回「成就」，三项任务的格子去掉；汇总表里每日任务的列要不要清；要不要在「本周排了日程的人数」旁边再加一格（票 09 定的好感度那格如果要加，在这里一起）。
- **对外文档**：隐私政策「每日任务和成就」那条改回「成就」，使用条款、`docs/configuration.md` 三语、README 三语里提到每日任务的半句都改；要不要发一条公告（每日任务下线、每天发的抽奖变多）。
- **顺序和分支**：票 08 定的「第三块取完规格以后删掉计划分支」改成第四块；这一块要不要先让日程跑一两周再开（票 08 留的「本周排了日程的人数」那格正好看）；部署前要不要备份（改了表就要）。
- **词汇表**：「每日任务」条目删掉；「成就」「看板」「运行记录」「数据包」「统计」里提到每日任务的地方改掉。
- **规格**：单独一份 `.scratch/retire-daily-tasks/spec.md`，和另外三份一起用 `/to-spec` 写，还是等日程部署后再写。

每张票都调用 grilling 和 domain-modeling。

## Answer

2026-10-23 的 grilling 定下。单独一块 `feat/retire-daily-tasks`，整块拆掉，成就留着，日程不接手发抽奖。

- **抽奖次数**：`DRAWS_PER_DAY` 从 1 调到 2，`MAX_DRAWS` 留 7、抽奖台的 7 个圆点不动（上限从「一周的量」变成「三天半的量」，接受）。按票 11 的尺子，认真处的人信任到亲近约 11 天、到亲密约 25 天，仍在目标附近。按现有补发逻辑，部署后的下一个北京 0 点起生效；新用户第一份也是 2 次；部署那一刻今天做了一半的任务不补发。
- **删干净**：`DAILY_TASKS`、`DailyTask`、`DailyTasks`、`Rewarded.daily_tasks`、`GET /api/gifts` 里的 `daily_tasks` 和 `renews_at`、运行记录的 `daily_task` 种类、前端 `lib/dailyTasks`、`DailyTasksSection`、相关文案和 README 截图脚本里每日任务的假数据，全部删掉。库里启动时一次迁移：删 `daily_task_progress` 表（同时从 `database.py` 的 `USER_DATA` 除名），删 `daily_task` 种类的运行记录和 `record_rollups` 里同种类的汇总行，看板不为旧记录留特判。`gift_rewards` 里每日任务的到账记录留着：是幂等发奖的凭证，成就还在用同一张表。
- **留下的**：往来记账模块（`happenings.py`，成就在用）、幂等发奖入口 `Gifts.reward`、导航「礼物/玩法」上的点、次数超过 7 时「+n」的显示（成就给的仍可超上限）、`TaskOpenIcon`（成就「集齐」那一行在用）。
- **界面**：玩法页「每日任务与成就」卡改名「成就」，路由 `/play/tasks` 改成 `/play/achievements`，旧路径跳转。卡上的状态平时写「已解锁 n 个阶段」（用现有的 `tally`），有新解锁时换成「n 个新解锁」。子页只剩成就那一块，页首返回键照旧；「去对话」「挑一件」随任务一起去掉。抽奖台那句改成「明天 0:00 再发 2 次，最多攒 7 次」，DESIGN.md 里「每日任务给的」改成「成就给的」，每日任务那一条删掉，成就、重置卡条的位置描述随之改。
- **看板和配置页**：「每日任务和成就」小节改回「成就」，去掉三项任务的格子，不加别的格；显示规则不变。配置页「好感度和礼物」卡的说明去掉「每日任务」半句。
- **对外文档**：隐私政策那条改回「成就」，「运行记录」「看不到」两条去掉每日任务，改「最后更新」日期；使用条款「玩法」那条去掉每日任务；`docs/configuration.md` 三语删掉「每日任务」那一条，「关掉时」、后台表格、「看不到的」各改半句；`docs/deploy.md`、`docs/data-package-format.md` 各一处；README 三语功能句改成「解锁成就能多得抽奖次数」，玩法页截图重拍，图的 alt 随之改。`.scratch/daily-tasks/spec.md` 的 Status 改成 retired，开头加一句指向这份规格。
- **公告**：发一条短的：每日任务下线了，每天发的抽奖改成 2 次，成就照旧。草稿写进最后一张票，用户自己去后台发。
- **顺序、备份、计划分支**：日程合进 main、部署之后马上开，不等「本周排了日程的人数」跑一两周（下线已经定了，不以那格数据为条件）。删了表，部署前手动备份一次。票 08 的「取完规格以后删计划分支」顺延到这一块：第一个提交取来自己那份规格以后，删掉本地和远端的计划分支。前后端一起部署。
- **词汇表**：放在这一块自己的第一张票里改，不在计划分支上现在改（计划分支的词汇表随玩法页进 main，那时每日任务还在线）。届时删「每日任务」条目；「抽奖」里「做每日任务得到的不受上限约束」改成「成就给的不受上限约束」；「数据包」「运行记录」「看板」各去掉每日任务那半句；「成就」「统计」不动。
- **规格**：现在就和另外三份一起用 `/to-spec` 一次写完（`.scratch/retire-daily-tasks/spec.md`）。按「拆什么」写，不按文件路径写：玩法页那块会把礼物页拆成子页，位置以玩法页规格为准；这块第一张票照先例先对照当时的 main 核对一遍。

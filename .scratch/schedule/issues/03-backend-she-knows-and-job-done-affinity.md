**What to build:** 她知道本周（和已保存的下周）所有保存过的她的工作并以此说话，排给她的工作做完了好感度悄悄上升。**她怎么知道**：通过日历那一块建的「今天的几句」接缝加一组句子（签名加「这位用户给这位角色保存过的本周和下周的放置」，或在引擎里拼「此刻」的那个方法另拼一组，这张票定、写进实现说明），回合（打字、通话）和搭话三处不另改；没有保存过的就一句不写。不另起一节，就写在「此刻」里：先一句引子「制作人给你排了这些工作（日程定了就不会再变；制作人在对话里说取消或改期，你还是按日程上的来）：」；每项一行「周三（昨天）下午：拍摄广告——说明」，日子由代码换成今天 / 昨天 / 明天 / 前天 / 后天，其余写「周X」，下周的加「下周」，多段的写「上午到下午」「一整天」，过去的末尾「（做完了）」；正在进行的不在列表里重复、单独一句「现在（下午 12–18 点）你正在<名称>：<说明>。说话可以带着这个状态（抽空回、在休息），不用每句都提，说过就不再反复说。」，0–6 点没有正在进行的；规则几句只在有日程时写（制作人排的、可按关系抱怨或期待、私人的也算他给你留的时间、做完的可以自己说过程和感受、不编后续的安排和结果、只在相关时提起不在开头说、同一项说过不再主动提、别的偶像的安排你不清楚），文案照规格「她怎么知道」。时区用这次回合 / 搭话的有效时区（搭话没有设备时区就是档案 → 上海）。不进记忆；换周后上周的不再读。别的偶像的放置不在她的提示词里。**搭话** `REACH_OUT_RULES` 改两处：由头那条改成「先接着你们最近聊过的事，或者他最近的近况；其次是你这周的工作（如果有）；再其次才是现在的时间、他的生日」；「只说练习、拍摄……这类平常的事」那条改成「说到你自己那边：日程里有的就说日程里的；没有的话只说练习、拍摄、事务所的工作这类平常的事，或者世界设定里有日期的 live 和新歌；不要编具体的剧情，也不要说别的偶像做了什么」。搭话什么时候来、来几次都不变；「正在开会」不改接通、不改回复时机。**做完的工作加好感度**：好感度模块加 `JOB_DONE_STEP = 0.5`，不分时长、类别；最后一个时间段结束那一刻算做完（起始段 + 时长的段末，按制作人当时的有效时区），多段的中途不算；读的时候补算、不加常驻循环：好感度和日程两个开关都开着时，读到这位用户的日程（读接口、组回合 / 通话 / 搭话的提示词时读放置）就把所有已到期、还没算过的放置算一遍，每项加一次、写上已算过的时刻，同一个写事务里完成所以并发读也只算一次；关着期间什么都不做、很久以后再打开一次补上。走和礼物一样的路（`receive_gift` 那条路径的通用化）：冷却中也加 0.5（不是冷却中礼物的 3）、到解冻线就解除冷却、不受每天上限约束；返回的变化不显示：不留对话事件、不出胶囊、不写运行记录。总原则改述进每日任务规格那条：系统发的东西不直接加好感度，加好感度的只有她的感受：回合、礼物、做完的工作。不加「这周排得满 / 很闲」的提示。日程关着时整组句子不写、不补算。见规格「她怎么知道」「做完的工作加好感度」和 Testing Decisions 对应两段。

### 实现说明（票 03）

**接缝**：没改 `today_lines` 的签名，在引擎拼「此刻」的方法里另拼一组。`ConversationEngine._now_prompt` 多收一个 `her_jobs: HerSchedule | None`，在 `now_prompt`、`today_lines` 之后接 `schedule.schedule_lines(her_jobs)`；打字回合、通话回合（`_reply`）和搭话（`reach_out`）都经过它，三处只是各自先 `await self._her_jobs(conversation, device_timezone)`（搭话传 `None`，有效时区就是档案 → 上海）。`HerSchedule` 是「当地此刻、制作人的本周、她的放置（`HerJob`：工作、周、周几、起始段）」，由 `Schedules.hers(user_id, character_id, device_timezone)` 给，只读本周和下周、`weekly_jobs.character_id` 是她的那几项；日程关着时 `None`，一句不写。回合里先读她的工作再读好感度，所以这一回合的档位已经算进刚做完的工作。

**补算**：`Schedules` 多收 `affinities`（`assembly.py` 里挪到引擎前面建，传给引擎）。`read` 和 `hers` 都是「先读，有要写的才开写事务」：读的那一步里 `_counted` 查这位用户所有 `counted_at` 为空的放置，用 `time_of` 看最后一段是不是 `past`（按这次的有效时区），有就返回 None 走写事务，写事务里每项调 `Affinities.job_done` 再写 `counted_at`。写任务串行，所以并发读只算一次。只在 `Affinities.on`（好感度开关）为真时数，日程关着时 `read` / `hers` 直接返回 None，不数。不限周：换周后上周没算的也补上。

**好感度**：`receive_gift` 的身子抽成 `Affinities._raise(db, user_id, character_id, step)`，`step` 收「是否冷却中」给步子；`receive_gift` 传 `_gift_step`，`job_done` 一律 `JOB_DONE_STEP = 0.5`，返回值丢掉（不留对话事件、不出胶囊、不写运行记录）。

**其他**：`REACH_OUT_RULES` 改了两处。`tests/test_schedule_saving.publish` 加了 `character` 参数。每日任务规格那条总原则改述成「系统发的东西（抽奖次数、重置卡）不直接加好感度；……加好感度的只有回合、收到的礼物和排给她的工作做完了」。GLOSSARY 的「好感度」「工作」「日程」已经写了做完加好感度，没改。

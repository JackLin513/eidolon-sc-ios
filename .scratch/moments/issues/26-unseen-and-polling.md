# 26: 没看过的动态：导航上的点和轮询

**What to build:** 有新动态露出，或者她回了他的评论，导航「朋友圈」上就出现一个小点，最多晚一分钟，在任何页面都看得到。打开朋友圈页，点就消失；在哪台设备上打开都算。其他偶像的赞和评论陆续露出时，不点亮这个点。开着朋友圈页时，新露出的动态、赞和评论不用刷新，最多晚一分钟出现。规格见 `../spec.md`：「接口」里讲时间线和「有没有新的」的两处；「前端」里讲点和轮询的两处。

**Blocked by:** 23, 24

**Status:** ready-for-agent

- [ ] **上次打开的时刻**：用 14 建的每位用户一行里的「上次打开朋友圈页的时刻」。第一次给他排计划、建这一行的时候，记成那一刻，所以没打开过的也从那时算起。
- [ ] **读时间线就算看过**：读时间线的同时，把「上次打开」记成这次读的那一刻。
- [ ] **「有没有新的」接口**：只回一个布尔。有动态或她的回复，露出时间在上次打开之后、在现在之前，就是真。其他偶像的赞和评论不算。朋友圈对他关着时拒绝（409）。
- [ ] 不在每条动态上记看没看过。
- [ ] **前端**：
  - **点**：「朋友圈」上一个点，样子和「对话」上的一样（6px、`bg-foreground`），导航栏和 dock 都有。当前在朋友圈页时不出。读屏名字跟着变。
  - **轮询**：
    - 外壳每 60 秒的那次轮询多拉一次「有没有新的」：标签页在前台时才拉，切回前台马上拉一次，朋友圈关着时不拉。
    - 朋友圈页开着时，同一个轮询改成重读时间线；重读也算打开过。
  - 打开朋友圈页后，本地先把点清掉，下一次拉的时候以服务器为准。
  - `navShell.test.ts` 测：有新的时「朋友圈」上有点，在朋友圈页上没有。
  - `DESIGN.md` 补上这个点。
- [ ] **测试**，照 `test_unseen_reach_outs.py` 的写法：
  - 新露出的动态、她的回复会让它变成真；其他偶像的赞和评论不会。
  - 读时间线就变回假；在另一个客户端读也算。
  - 没打开过的，从第一次排计划算起。
  - 关着时拒绝。
- [ ] **验收**：在本地构建版上用 Playwright 看：
  - 停在设置页时调一次「跑一遍」，造出一条动态，一分钟内「朋友圈」上出现点；
  - 打开朋友圈页，点消失；
  - 停在朋友圈页时再造一条，它一分钟内出现在页面上；
  - 切到后台标签页时不拉，切回前台马上拉。
- [ ] `sh scripts/affected-tests.sh <基点>` 通过，推送后 CI 全绿。

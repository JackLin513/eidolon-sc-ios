# 01: 调研：动态的地点池从哪来、用哪家地图

Type: research
Status: open
Blocked by: none

## Question

动态旁边要显示一个地名，点开能看地图。地名不让模型编，从一份整理好的地点池里挑，要多、不重复，最好有原作的圣地。要查清楚：

- **原作圣地**：日本粉丝考据出来的《偶像大师 闪耀色彩》圣地巡礼地点（舞台原型、MV 和剧情里出现过的实景、283 事务所附近的原型）有哪些、可信的来源在哪（考据博客、まとめ、聖地巡礼マップ一类网站），能整理出多少个，各自属于哪位偶像或哪个组合。
- **剧情库里的地名**：仓库里的剧情库（见 `GLOSSARY.md` 的「剧情库」，以及剧情相关代码）里出现过哪些真实地名、店名、地区，抽出来的办法和大致数量。
- **地点池怎么做得够大**：除了圣地和剧情，有没有现成的东京地点数据（OSM 的 POI 类别、观光名所清单、开放数据）能按类别（咖啡馆、公园、神社、商业街、海边……）批量取，再按偶像的性格和日常筛。几百个够不够撑「30 天、28 位、不重复」。
- **地图服务**：
  - 只要「地名 + 点开看地图」，OSM 够不够：Nominatim 的使用政策（频率、User-Agent、能不能用于公开服务）、日文地名的覆盖、点开时跳 openstreetmap.org 还是别的前端。
  - Google Maps：Places API / Maps URLs 的现行价格和免费额度、申请条件；如果只用「拼一个 Maps URL 让用户点开」是不是根本不需要 key。
  - 结论里给出建议：地点池预先整理成仓库里的数据文件（像 `characters/jobs.toml` 那样由维护者维护），还是运行时查地图服务。

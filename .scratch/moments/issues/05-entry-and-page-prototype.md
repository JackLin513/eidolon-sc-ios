# 05: 原型：入口和朋友圈页面

Type: prototype
Status: resolved
Blocked by: none

## Question

- **入口**：导航第四项「朋友圈」，还是「玩法」页里的一张卡？用户觉得移动端底部导航三项已经有点挤，倾向玩法卡；用 impeccable（或相关技能）在移动端和桌面端评估两种做法，给出建议。注意术语表里玩法的定义是「和角色往来之外的事」，选玩法卡的话要不要改这个定义。
- **有新动态时怎么提示**：导航上的点（照「没看过的搭话」记在服务器上），玩法卡上的标记，还是不提示。
- **页面长什么样**：一条动态的卡片（头像、名字、文字、配图、地名和天气小字、发的时间），赞的人一行、评论区，制作人怎么赞、怎么写评论，她的回复「过一阵才露出来」时等待中是否有任何痕迹。按角色筛选要不要。
- 遵守 `frontend/AGENTS.md` 的「shadcn 纪律」和 `DESIGN.md`。原型放在 `prototype/moments-page` 分支，用假数据。

## Answer

原型在 `prototype/moments-page` 分支（origin），`/play/moments?variant=A|B|C`，底部切换条切入口和「造新动态」。用户 2026-10-31 选定：

- **入口：导航第四项「朋友圈」**，电脑的导航栏和手机的 dock 都加，顺序对话、朋友圈、玩法、设置，图标 Lucide `Aperture`。dock 宽 390px 时四项不挤；朋友圈是和角色往来，不进玩法，玩法的定义不用改。部署者关掉或用户关掉自己的朋友圈时这一项不出现，导航回到三项。原型借用了 `/play/moments`，实际要有自己的第一级地址（比如 `/moments`），进外壳的去处规则（换页不挂断）。
- **新动态的提示：导航「朋友圈」上的点**，样子同「对话」上的点（6px、`bg-foreground`），在朋友圈页上不出；没看过的记在服务器上，照「没看过的搭话」，前端随现有的轮询读。
- **页面：A「时间线」**。一栏（同玩法页 `max-w-3xl`），一条一行：左边头像，右边名字（Row name）、文字（Body）、配图（窄的缩略图，点开用 `ImageViewer` 放大）；下面一行 Meta 字号的「时间 · 地名 · 天气图标加整数气温」，地名点开在新标签页开 openstreetmap.org；行尾一个「⋯」，弹出「赞」「评论」。有赞或评论时下面一块 `bg-muted` 圆角：第一行心形加赞的人的名字（制作人赞了排最前，写「制作人」），细线下面是评论「名字：内容」，她回制作人写「她 回复 制作人：内容」。点「评论」在这一条下面展开输入框和发送键。
- **她的回复还没露出来时：什么痕迹都不留**（不要「正在输入」，不要「已读」）。
- **不做按角色筛选**（每天最多 3 条、只留 30 天，一栏翻得过来）。
- 没选的：B「卡片 + 详情面板 + 头像筛选」、C「按她分两栏、铺她的壁纸」。

# 07: 拍板：发布节奏和调度

Type: grilling
Status: resolved
Blocked by: none

## Question

已定后台定时生成、只给最近活跃的用户、每位角色每天最多 1 条、每位用户每天合计最多 N 条（默认 3）。还要定：

- **最近活跃**怎么算：7 天内有过回合？通话、送礼、打开朋友圈算不算？
- **一天里谁发**：合计上限 N 比「有过回合的角色」少得多时，每天挑哪几位——好感度高的优先、今天做完了工作的优先、生日的必发、轮流避免总是同一位？好感度档位具体怎么影响频率（照搭话的 `INTERVALS` 那样按档位给间隔，还是给权重）。
- **几点发**：按东京时间在一天里怎么分布（早上、午休、下班后、深夜），做完工作的那条在工作最后一个时间段之后发。制作人的时区要不要考虑（他夜里收到也不提示）。
- **提前生成还是到点生成**：到点才生成文字和配图，还是提前一批生成好、到点露出来（生图排队，部署者 key 默认同时只生成 1 张）。
- **和搭话、照片抢生图队列和对话模型**：动态的生图排在用户要的照片后面吗？
- **开关和条件变化**：部署者没配生图时只发纯文字；部署者没配对话模型或关掉朋友圈时不发；用户关掉自己的朋友圈、好感度掉到疏远、进入冷却时，已经生成好还没露出来的动态怎么办。
- 部署者在后台能调的数：N、每天评论回复上限、活跃天数，哪些要暴露，默认值。

## Answer

用户 2026-10-31 拍板（grilling 两轮，建议全部采纳）：

- **最近活跃**：照搭话的「联系」，7 天内和任意一位角色有过回合或接通的通话；送礼、打开朋友圈不算（打开页面不写库）。
- **一天里谁发**：够格的角色（有过回合、信任及以上、不在冷却中）每天按档位掷一次：亲密约 80%、亲近约 50%、信任约 25%，生日当天必发。掷中的超过 N 位时先留生日的，其余随机。不记轮转。今天有没有工作不影响发不发，只影响写什么。概率是代码常量，上线后看数据再调。
- **什么时候排计划**：东京每天 0 点后第一次 tick，给活跃用户排当天谁发、几点发；当时不活跃、白天才回来的用户（或部署者白天才打开），在他够格后的第一次 tick 排，只从当天剩下的时间里抽。当天才第一次聊、才升档的角色等第二天。计划存进库，重启后接着读。
- **几点发**（东京时间）：没有工作的那条按时段加权抽：早 7–9 点权重 2、午休 12–13 点 2、下班后 18–24 点 4、深夜 0–2 点 1；同一位用户的几条至少隔 1 小时。不看制作人时区（没有推送，只是导航上的点）。
- **做完工作的那条**：工作按做完那一刻（日程按制作人时区算）落在东京哪一天就算哪一天的；她在当天最后一项做完后 30 分钟到 2 小时内发，一条串起做完的几项。到点时她今天还有没做完的工作，就推到最后一项做完之后；推过东京 0 点也照发，仍算排它的那一天。
- **到点生成**：到点才生成文字和配图，生成完就露出来，显示的时间就是露出的时间；赞和评论从这一刻往后错开。条件只在生成那一刻判断。
- **生成那一刻的条件**：部署者开着朋友圈、配了对话模型；用户没关自己的、没被封禁、管理者没禁止他用部署者的 key；她不在冷却中、信任及以上；这位用户当天没到 N 条。不满足就跳过，不改期。部署者没配生图时只发纯文字。
- **失败**：对话模型出错或输出解析不了，跳过，当天不补、不重试，运行记录里记失败。文字成了、配图失败或超时，照发成纯文字（提示词里要求文字不依赖配图）。
- **停机**：错过的不补，照搭话。
- **生图队列**：配图在部署者的 key 上排队，用户要的照片插到等待中的配图前面，正在生成的不打断；配图时限 10 分钟（含排队），超时按纯文字发。不用用户自己的 key。
- **一次生成几条**：每分钟一次 tick，到点的按时间先后逐条生成，不并发。不计入用户的任何限额。
- **露出以后**：其他偶像的赞和评论生成时一起定好，照各自的时间露出，不受之后好感度、冷却影响。
- **部署者能调的**：照搭话的 `_Item` 做一项「朋友圈」：开关、每位用户每天合计 N 条（默认 3，最少 1）、每位用户每天她回评论的上限（默认 10）。活跃天数 7、各档概率是代码常量。

# 10: 拍板：地点池怎么整理

Type: grilling
Status: resolved
Blocked by: none

## Question

调研定了地点池是仓库里的数据文件（示意 `characters/places.toml`），运行时不查地图服务，点开跳 openstreetmap.org 的标记链接，不申请 Google key。还要定：

- **字段**：地名（日文、中文？她在动态里怎么写、页面上显示哪种）、经纬度、类别、有关的偶像或组合、圣地的出处（哪张卡面、哪段剧情），要不要「适合的时段、季节」。
- **来源和许可**：圣地（粉丝考据，40–60 处）、Wikidata（CC0）、OSM（ODbL：要署名，派生数据库要同许可）、各区开放数据，各取多少；ODbL 的署名和同许可要求能不能接受（天气署名已定只进 README 的致谢），不能接受的话只用 CC0 和手工整理的。
- **规模和分配**：300–500 个，按类别和偶像怎么分；后加入、没有考据点位的偶像怎么补。
- **谁来整理、怎么校对**：代理按来源出初稿、用户校对（像照片的外貌 tag 那样），还是只人工挑。
- **点开地图跳哪家**：openstreetmap.org、Google Maps URLs，还是别的；大陆用户能不能打开（调研没核实）。

起点：远端分支 `research/moments-place-pool` 上的 `.scratch/moments/research/place-pool.md`（第 1.4 节圣地样例、第 3 节扩充来源、第 6 节数据文件形状）。

## Answer

用户 2026-10-31 拍板（grilling 两轮；除了地图链接，建议全部采纳）：

- **点开跳哪家地图**：默认 openstreetmap.org 的标记链接；后台加一项（ADR-0013 的 `_Item`，放在「朋友圈」那组里），部署者可以换成 Google Maps URLs 或高德（`uri.amap.com/marker?position=经度,纬度&name=地名`），整个部署统一用一家，用户不能自己选。日本在中国境外，三家都直接用 WGS-84 坐标，不用转换，也都不要 key。实测（2026-10-31，本机不走代理）：大陆的 DNS 把 www.openstreetmap.org 污染成了 Facebook、Twitter 的地址，打不开，`osm.org` 也跳到它；Google 超时；高德、百度、Apple（跳到 maps.apple.com.cn）、必应都能直连。高德的东京地图细到いろは坂、九頭龍神社一级，电脑网页先弹登录框（能关掉），手机上会拉起 App。所以用户大多不开代理的部署，最好改成高德。
- **来源和许可**：OSM（Geofabrik 关东抽取文件离线筛，主要取咖啡馆、店铺这类小地点）、Wikidata（CC0，神社、公园、名所）、粉丝考据的圣地，三样都用；不用各区开放数据。按自己的标准人工挑几百个，按 OSMF 的指引算非实质性摘录。数据文件开头注明「Contains data © OpenStreetMap contributors, ODbL」，README 的「致谢」加一行，界面上不加。
- **地理范围**：东京都（含多摩）加一日游的近郊（横浜、鎌倉、江ノ島、幕張、川越一圈）。不收老家和外地（佐世保、富山、神津島、成田机场……）。
- **地名语言**：只写日文原名，和地图、招牌一致，片假名店名也照写；不设中文译名字段。她在正文里怎么提这个地方，留给「拍板：一条动态里有什么、素材怎么挑」随动态的语言一起定。
- **圣地是记号不是类别**：照实际地点归类，带 `source`（卡面名 + 考据链接）和 `idols`；有 `source` 的就是圣地，挑的时候给 `idols` 里的偶像加权。只收有对照照片、能复核的考据；动画版圣地、已拆已关的不收。她只是借景，不说「这是我那张卡拍的地方」。
- **字段**（数据文件 `characters/places.toml`，写法照 `jobs.toml`，启动时读入校验）：`id`、`name`（日文，显示）、`area`（区市町村，消歧和给她参考，不显示）、`lat`、`lon`、`category`、`note`（一句中文，告诉她这是什么地方）、`idols`（可选，只给圣地和角色资料写明的地方）、`source`（可选，圣地）、`seasons`（可选，只给明显分季节的）、`slots`（可选，比如夜景只排晚上）、`checked`（核对日期）。不加生图用的 tag 字段，她写配图时看 `note` 自己写景物；室内还是室外由类别决定。
- **类别**（14 类，标识用英文）：咖啡馆·甜品·餐厅；公园·河边；神社·寺；商店街；杂货·服装街区；书店·图书馆；商场·车站大楼（含电影院）；海边·湾岸；水族馆·动物园·游乐园；美术馆·博物馆·天象仪；展望台·夜景；温泉·钱汤；季节名所；演出场馆（只收 `world.json` 里真实的 live 场馆，只给「往年今天的演出」用）。便利店、家庭餐厅、学校、私宅、夜生活街区不收。
- **工作对上地点**：`jobs.toml` 加可选字段 `places`（类别列表），没写的工作发动态不带地名（练习室、事务所、摄影棚、录音棚、医院、见面会都不写）。要写的：晨跑→公园·河边；外景拍摄→海边；夜景拍摄→展望台·夜景、商店街；逛街→商店街、杂货·服装街区、商场；去咖啡馆→咖啡馆；出去吃饭→咖啡馆·甜品·餐厅；看电影→商场·车站大楼；一日游→近郊；去公园散步→公园·河边；做喜欢的事→不限。
- **偶像的喜好**：`characters.toml` 加 `place_likes`，每位 2–4 个偏好类别，挑候选时加权，别的类别仍可能挑到；不像 `liked_gifts` 那样要剧情出处。
- **规模**：约 400 个。圣地 40–60，演出场馆按 `world.json` 有多少收多少，其余按剧情库的场所分布分（咖啡馆、公园、神社、商店街多，温泉、天象仪少），每类至少 10 个。
- **谁整理、怎么校对**：实现阶段的一张票。代理从上面三种来源出初稿，坐标取自来源，不让模型估；在 `E:/tmp/` 生成能逐条点开地图的 HTML，用户像校对外貌 tag 那样过一遍，`place_likes` 和 `jobs.toml` 的 `places` 在同一份里一起校对。

术语表加了「地点」一条。

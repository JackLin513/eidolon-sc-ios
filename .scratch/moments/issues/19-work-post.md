# 19: 工作那条

**What to build:** 她做完制作人排的工作后不久，发一条动态说今天的工作：一天有几项就串成一条，地名从这几项工作会去的地方里挑。工作那条发在她当天最后一项做完后 30 分钟到 2 小时之间，绝不会在她还没做完时就发。没排日程、或者部署关了日程时，照常发日常那条。规格见 `../spec.md`：「节奏：到点的跑一遍」里讲工作那条和到点的两处，「写一条动态」里讲素材和地点候选的两处。

**Blocked by:** 14, 17

**Status:** ready-for-agent

- [ ] **排计划时定是哪一条**：
  - 她今天有排给她的工作已经做完或将要做完，就是工作那条，否则是日常那条。
  - 一项工作算哪一天，看它做完的那一刻（日程按制作人的时区算）落在东京的哪一天。
  - 日程关着（`EIDOLON_SCHEDULE`）时都是日常那条。
  - 今天有没有工作，不影响她发不发，只影响写什么、几点发。
- [ ] **几点发**（加进 14 的排计划纯函数）：工作那条在她当天最后一项做完后的 30 分钟到 2 小时内。
- [ ] **到点时**：她今天还有没做完的工作（排计划之后制作人又给她排了），就推到最后一项做完后的 30 分钟到 2 小时。推过东京 0 点也照发，仍算排它的那一天，也计入那一天的 N 条。
- [ ] **素材**：
  - 给今天做完的全部工作，每项写名字和 `note`。
  - 现在只能取到今天做完的最后一项，要加一个取全部的办法，按东京日期划。
  - 工作那条不给资料种子。
- [ ] **规则**：把今天做完的几项串成一条。
- [ ] **地点候选**：只从这几项工作的 `places` 类别里挑；写了 `nearby` 的，不限类别、只挑东京都以外的地点（15 定的写法）。这几项都没写 `places`，就不给候选，这条不带地名。
- [ ] **她生日那天**：照样分工作那条和日常那条来排时间、给素材，另外照 14 告诉她今天是她的生日。
- [ ] **测试**：
  - 排计划的纯函数：用 `FakeRandom` 逐个给数，测最后一项做完后的时间区间、跨东京日期的工作算哪天。
  - 经过「跑一遍」，排日程照 `test_schedule_*` 的写法：
    - 做完工作的那天是工作那条；到点时还有没做完的就往后推；推过 0 点仍算那天。
    - 请求里有做完的全部工作、没有资料种子；候选只来自工作的 `places`，没写就没有候选。
    - 日程关着时是日常那条。
- [ ] **验收**：在本地构建版上排一项马上就会做完的工作，推进时间、调一次「跑一遍」，看时间线上那条动态写的是工作。
- [ ] `sh scripts/affected-tests.sh <基点>` 通过，推送后 CI 全绿。

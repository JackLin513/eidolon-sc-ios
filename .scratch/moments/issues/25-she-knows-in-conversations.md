# 25: 她在对话里知道朋友圈

**What to build:** 之后和她打字、通话时，她知道自己最近 3 天发过什么、制作人赞没赞、评论了什么、她自己怎么回的。她可能主动问「昨天发的看到了吗」，搭话时也可能拿刚发的动态当由头。他没赞也没评论时，她不抱怨、不追问；亲近、亲密时可以带一点期待，最多提一次。规格见 `../spec.md`「此刻：『朋友圈』场合和『你最近发的朋友圈』」；来历是 `08-producer-interaction.md` 和 `13-post-prompt-and-eval.md`。

**Blocked by:** 23, 24

**Status:** done

- [x] **新的一节「# 你最近发的朋友圈」**：
  - 打字、通话、搭话都带。光顾不带；「朋友圈」场合也不带，因为发动态有自己的「最近 5 条」。
  - 放在每回合变的那条系统消息里，跟在此刻那一节后面（ADR-0020），这样不破坏前缀缓存。
- [x] **列哪些**：她自己最近 3 天里已经露出的动态，最多 3 条，一条一行。例如：
  `昨天 21:14　<日语正文>（配图：<note>）　制作人赞了；他评论「…」，你回了「…」`
  - 时间按制作人的时区写，和此刻的其他行一样。
  - 正文只放日语原文，不放字幕；配图写中文的 `note`。
  - 他没赞也没评论时，明写「他还没赞也没评论」。她的回复还没露出的，只写他评论了什么。
  - 别的偶像的赞和评论不带。
  - 没有动态时，整节省掉。
- [x] **这一节末尾跟一句规则**：可以自己提起；他没赞没评论的，不抱怨也不追问；（只在亲密、亲近两档）可以带一点期待，最多提一次。这句跟着这一节走。
- [x] **搭话**：`REACH_OUT_RULES` 的由头顺序里，在「这周的工作」后面、「时间、生日」前面插一项：「你最近发的朋友圈（比如问他看到没有）」。
- [x] **关着时**：部署者关了朋友圈，或者这位用户关了自己的，这一节和搭话里那一项都不出现。
- [x] **测试**：
  - 打字、通话、搭话的请求里有这一节，光顾的没有；最多 3 条、只算 3 天内露出的。
  - 每一行的写法：赞了、评论了、她回了；回复还没露出；都没有。
  - 规则那句只在亲密、亲近两档带期待。
  - 关着时没有这一节；搭话由头里的那一项随开关出现和消失。
  - 先例：`test_her_now.py`、`test_dynamic_context.py`、`test_reach_outs_in_turns.py`、`test_reach_outs.py`。
- [x] **验收**：在本地构建版上造一条动态，赞一下、评论一句，然后在对话里问她「昨天发了什么」，用真模型看她答得上来。
- [x] `sh scripts/affected-tests.sh <基点>` 通过，推送后 CI 全绿。

### 实现说明（票 25）

- **新模块 `recent_moments.py`**（在 `moments` 下面，因为 `moments` 导入了 `engine`，`engine` 读此刻时不能反过来导入它）：
  - `RecentMoments(db, clock, is_on).hers(user_id, character_id)`：部署者关着（`config.moments.enabled`）或他关了自己的（`read_switched_on`）时为空；否则她 3 天内（`WITHIN`）已露出的最近 3 条（`AT_MOST`），早的在前。
  - `moments_section(moments, now, timezone, tier)`：整节文字，没有动态时为 `None`。时间按制作人时区写「今天/昨天/前天 HH:MM」，再早写「M月D日 HH:MM」；正文和评论里的换行压成一个空格。末尾一句 `BRING_UP`，亲近、亲密两档再加 `LOOKING_FORWARD`；没开好感度时按信任算。
  - `read_switched_on`、`picture_note` 从 `moments.py` 搬过来（原来叫 `_switched_on`、`_note`），`moments.py` 改成从这里导入，行为不变。
- **`her_now.py`**：`Carries` 多一栏 `moments`，打字、通话、搭话为真，光顾和「朋友圈」场合为假；`HerNow` 多一个可选参数 `moments: RecentMoments`，`read` 按这一栏读，结果放在 `KnownNow.moments`。
- **`engine.py`**：回合和搭话里，这一节跟在此刻那一节后面（`_moments_told`），都在每回合变的那条系统消息里（ADR-0020）。搭话的规则拆成 `REACH_OUT_RULES`（不带那一项，和原来一字不差）和 `REACH_OUT_RULES_WITH_MOMENTS`。
- **`assembly.py`**：`HerNow` 带上 `RecentMoments(database, clock, lambda: config.moments.enabled)`。
- **判断题**：
  - 搭话由头里那一项，只在这一节真的有动态时才出现，不是只看开关。开着但 3 天内没发过的话，提了反而会让她编一条出来。关着时这一节必然为空，所以「随开关出现和消失」照样成立。
  - 配图只在真出过图时写 `note`（`moment_images` 有这一行）。图没生成出来，制作人在时间线上看不到，她就不该说「配图里」。不过票 23 回评论的提示词和发动态的「最近 5 条」照旧不看有没有出图。两处口径不一致，要统一的话改 `moments.py` 那两处（`_reply_material`、`_before`），这次没动。
  - 票里只举了「赞了 + 评论 + 回了」和「都没有」两种写法。其余补成：只赞写「制作人赞了，没评论」；只评论写「制作人没赞，评论「…」」，后面照样接「，你回了「…」」；赞了也评论了、她还没回，写「制作人赞了；他评论「…」」。
- **测试**：`tests/test_moments_she_knows.py`。打字走真的赞、评论、她的回复，搭话走 `ReachOuts.run_due`，看真请求；行的写法、3 天和 3 条、只算她自己的、各场合、两档期待、两个开关，经装配好的 `HerNow` 看（照 `test_her_now.py`）。通话和打字在引擎里是同一条路，通话只在 `HerNow` 那一层验了场合。
- **验收**（本地后端，`EIDOLON_MOMENTS=1`，真对话模型）：库里放一条「昨天 20:14」带配图的动态（练习回来路上的晚霞），接口赞一下、评论「真好看！下次一起去看吧」。问「你昨天在朋友圈发了什么呀？」，她答「あっ、見てくださったんですね……！レッスンの帰り道に、空がすごくオレンジ色で……」；追问「那我在下面的评论你看到了吗？」，她答「「今度一緒に見に行こう」って、ちゃんと読みました」。验收用户验完已删除。
- **affected-tests**：只有 `test_call_turns.py::test_call_hangs_up_after_its_last_allowed_turn` 失败，在基点上同样稳定失败（`one_by_one` 的时间间隔问题），不是这张票改坏的。

# 20: 圈子：其他偶像的赞和评论

**What to build:** 每条动态下面陆续出现其他偶像的赞和评论。赞的人慢慢多起来；组合伙伴在评论区说一两句，各用各的口吻，后面的人可以顺着前面的接。她们只回应这条动态和彼此之间的关系，不提正文里没写的事，也不回制作人。她生日那天，来赞和评论的人明显更多。规格见 `../spec.md`：「写一条动态」里讲圈子、素材里圈子成员的那几句、规则里讲偶像评论的几条、输出格式、名单的规矩、写坏了、露出时间；还有「存储」「接口」「前端」里讲赞和评论的几处。

**Blocked by:** 14

**Status:** done

- [x] **抽圈子**写成纯函数，给定输入和随机源，返回 4–6 人：
  - 同组合的权重最高；她角色资料「人物关系」里有一节写到的其次（「制作人」「其他偶像」两节不算）；偶尔一位别的组合的。
  - 今天过生日、和她同组合或有关系的那位必进。
  - 她生日那天扩到 8–10 人。
  - 权重是代码常量。
- [x] **提示词**：靠后那条系统消息里，「最近 5 条」后面、「地点候选」前面加一节「圈子成员」。每位写：
  - id 和名字，写成「`hiori`：風野灯織」；
  - 她资料「人物关系」里关于这个人的那一节；
  - 这个人人设里「自称」「对他人的称呼」「口癖」三节。
- [x] **规则**加上几条：
  - 偶像评论一两句，最多约 40 字，日语加字幕。
  - 只回应正文、配图里写出来的东西，以及她们之间的关系；正文里没有的事不提，也不对制作人说话。
  - 后面的评论可以顺着前面的接一句。
- [x] **解析**：
  - `<likes>` 是 id 的列表，服务器也认 `name` 和 `short_name`。
  - `<comment from="…"><ja>…</ja><zh>…</zh></comment>` 有 0–3 条，按露出的顺序写。
- [x] **名单的规矩**：
  - 赞 1–6 人，评论 0–3 人；她生日那天赞最多 10、评论最多 6。多写的按顺序截掉。
  - 圈子以外的人丢掉。
  - 某条评论缺日语或字幕，只丢这一条。
  - 赞的名单解析不了，当没人赞。
  - 每种降级都照 17 的写法记进运行记录。
- [x] **露出时间**写成纯函数，由服务器随机定：
  - 赞在动态露出后 5 分钟到 3 小时之间，各抽各的。
  - 评论在 15 分钟到 6 小时之间各抽一个，排好序后按她写的先后分给各条。
  - 夜里照常露出。之后好感度、冷却怎么变，都不影响已经定好的赞和评论。
- [x] **存储**：新表「其他偶像的赞和评论」，记所属动态、偶像、是赞还是评论、评论的日语和字幕、先后顺序、露出时间。登记进 `USER_DATA`。
- [x] **时间线接口**：只给已经露出的偶像的赞（按露出的先后）和评论（按先后，带角色、日语、字幕）。没露出的不出现，也不透露有没有。
- [x] **前端**：有赞或评论时，这一条下面多一块 `bg-muted` 圆角：
  - 第一行是心形加赞的人的名字；

## Comments

### 实现说明（票 20）

- **抽圈子**：`moment_draws.draw_circle(mates, related, others, birthdays, her_birthday, random)`，常量 `CIRCLE=(4, 6)`、`BIRTHDAY_CIRCLE=(8, 10)`、`MATE=3`、`RELATED=1`、`STRANGER=0.25`。先放过生日的（只看同组合和有关系的），再以 `STRANGER` 的概率放一位别的组合的，再按权重从认识的里抽，不够再从别的组合里补。加权抽签抽成了 `_weighted`，`draw_places` 也改用它。
- **露出时间**：`moment_draws.draw_shown(posted_at, likes, comments, random)`，`LIKES_AFTER=(5 分钟, 3 小时)`、`COMMENTS_AFTER=(15 分钟, 6 小时)`。
- **谁在圈子里**（`Moments._circle`、`moments._relations`）：同组合按 `world.unit_mates`；「有关系」是她资料里 `人物关系 / …` 小节标题里写到对方全名的，标题含 `NOT_ONE`（制作人、プロデューサー、其他偶像）的不算；事务员（`world.is_staff`）不进任何人的圈子；生日按东京今天。`Fact` 多了 `headings`、`body` 两个属性。
- **提示词**：`PostMaterial.circle`（`Member(character, relation)`）；「最近 5 条」和「地点候选」之间一节「# 圈子成员」，开头写「挑 1 到 N 位来赞，0 到 M 位来评论」（生日时 10、6），每位 `## id：名字`，下面是「你资料里关于她的」和她人设里的「自称」「对他人的称呼」「口癖」（`moment_prompt.sheet_sections`）。圈子为空时写 `NO_CIRCLE`。`POST_RULES` 加了四条规则和 `<likes>`、`<comment>` 的格式。
- **解析**：`parse_post(written, material)`（改成吃整份素材，评测也走它）。名单按 id、`name`、`short_name` 认，分隔认逗号、顿号、空白；`Post.likes`、`Post.comments`（`Comment(character_id, ja, zh)`）。降级键：`likes`（没写 `<likes>`）、`liker`（不在圈子里的赞）、`comment`（作者不在圈子里或缺日语、字幕）、`likes_over`、`comments_over`（截掉的条数）。
- **存储**：`moment_circle`（`moment_id`、`character_id`、`kind` 为 `like`/`comment`、`ja`、`zh`、`position`、`shown_at`），登记进 `USER_DATA`，排在 `moments` 前面。`_add_moment` 在同一个事务里写。
- **时间线**：每条多了 `likes`（角色 id，按露出先后）和 `comments`（`{character_id, ja, zh}`，按露出先后），只给 `shown_at` 已到的；下架角色的去掉。
- **前端**：`lib/moments.reactions(moment, nameOf)`；`MomentsPage` 的 `ReactionsBlock`；图标 `LikesIcon`（`Heart`）；文案 `likersSeparator`、`likedBy`、`commentedBy`。时间线等对话目录读到（或读失败）再显示，免得名字先显示成 id。DESIGN.md「朋友圈页」加了「赞和评论」一条。
- **判断**：
  - 「评论 0–3」按条数算，不按人数：同一位可以接着说第二句。
  - 认识的人凑不满 4 人时，用别的组合的人补满，这时不止「偶尔一位」：人数优先。
  - 赞先去掉圈子外的、去重，再截到上限；圈子本来就不超过 6（生日 10），所以 `likes_over` 实际上只有合照补人以后才可能出现，解析器的单元测试覆盖它。
  - 提示词里人数写阿拉伯数字（原先写汉字，改上限就得跟着改映射表）。
  - 「有关系」只按全名匹配小节标题。现有资料全能对上，以后用简称写标题会漏。
  - 事务员不进圈子：规格说「其他偶像」。
- **验收**：本地构建版，开发用户种了一条 2 分钟前的动态，赞在 -1、+1、+1 分多钟露出，评论在 +1.5、+2.5 分钟露出。Playwright 在 0、75、100、160 秒各看一次，宽屏和手机都是先一位赞，再三位，再一条评论，再两条，名字和字幕都对。验收用户已经删除，`moment_circle` 跟着删干净；脚本和截图都删了。
- **审查后改的**：测试不再断言规则常量本身；表注释改成引用「动态」；拆 `Fact` 格式收进 `Fact.headings`、`Fact.body`；`like`/`comment` 改成常量；降级键改名（`NO_LIKES`、`OUTSIDE_LIKER`、`BROKEN_COMMENT`），每个一条说明；去掉汉字数字映射。没改的判断题：`draw_circle` 四个列表可以收成一个类型；`parse_post` 吃整份素材，只用其中三项；细线照 DESIGN.md 写成 `h-px bg-foreground/10`，没改用 `ui/separator`（那样要在调用处改外观）；评论用下标当 key（顺序只会往后加）。

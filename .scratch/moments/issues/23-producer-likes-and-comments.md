# 23: 制作人的赞和评论、她的回复

**What to build:** 制作人能给动态点赞，也能取消；能给一条动态留一条评论（140 字以内），也能删掉。他评论之后，她过一阵用自己的口吻回一次：越亲近回得越快，最快几分钟，最慢两小时。她的回复露出之前，页面上什么痕迹都没有。她在冷淡、疏远、冷却中时不回；每天回评论的次数用完了也不回，不提示，第二天不补。赞和评论不经过判断、不改变好感度、不变成记忆，也不算一次往来。

规格见 `../spec.md`：「制作人的赞和评论、她的回复」全节；「部署者的设定」里讲回评论上限的一处；「存储」「接口」「运行记录、看板、服务状态」「前端」里讲赞、评论、回复的几处。来历是 `08-producer-interaction.md`，回复的提示词见 `13-post-prompt-and-eval.md`。

**Blocked by:** 20

**Status:** done

- [x] **后台**：「朋友圈」一项加一个字段，每位用户每天她最多回几条评论，默认 10，最少 1，只能在后台改。
- [x] **存储**：两张新表，都登记进 `USER_DATA`：
  - 「制作人的赞」：每条动态一行，只存现在赞没赞；取消就删掉这一行。
  - 「制作人的评论」：每条动态最多一行，记他的原话、时间、她回复的露出时间（不回时为空），以及她回复的日语和字幕（露出时写入）。
- [x] **赞和取消赞**：各一个接口，都是幂等的。「赞了又取消」不留痕迹，她不知道；赞也不会引来她的回复。
- [x] **发评论**：
  - 去掉首尾空白后要有 1–140 字，不合就拒绝（422）。照他打的原样存、原样显示。
  - 这条动态上已经有他的评论，就拒绝（409）。不能编辑。
  - 动态不是他的、还没露出、或者已经过期，一律按不存在处理（404）。赞、取消赞、删评论也一样。
- [x] **发评论那一刻判断一次**：
  - 她在冷淡、疏远或冷却中，就不排回复，以后也不补。
  - 否则按当时的档位抽一个露出时间，写成纯函数：亲密 5–30 分钟，亲近 15–60 分钟，信任 30–120 分钟。没开好感度的部署按信任算。夜里照回。
- [x] **到点那一刻再判断一次**，在「跑一遍」里做：
  - 到点的回复和到点的动态合在一起，按时间先后逐条生成。
  - 以下几条有一条不满足，这次就不回，也不留运行记录：
    - 评论还在；
    - 部署者开着朋友圈；
    - 她不在冷淡、疏远、冷却中；
    - 他当天她回评论的次数还没到上限。上限按东京日期、按回复露出的那天数，从 `moment_reply` 成功的运行记录里数。不从评论表数，因为删评论会把额度退回来。
  - 用户自己的开关：24 已经做了，就在这一张加一条「他没关自己的朋友圈」；还没做，就由 24 加。
- [x] **回复的提示词**照搭话的排法，依次是：
  1. 人设、世界设定；
  2. 制作人资料；
  3. 当前对话最后几个回合，截取照搭话；
  4. 一条靠后的系统消息，依次放：
     - 此刻（「朋友圈」场合）；
     - 记忆（`for_reaching_out`，只用她自己听来的）；
     - 这条动态的正文和配图的 `note`；
     - 到这一刻已经露出的偶像的赞和评论；
     - 他赞没赞；
     - 一节「# 回评论」规则：一两句，评论区的口吻，不发照片，不带语气提示。
  5. 用户那句话的位置放「（制作人在你这条动态下面评论：）」，后面接他的原话。
- [x] **输出**只要一对 `<ja>…</ja><zh>…</zh>`，不另包标签，语气提示照字幕的做法剥掉。缺日语或缺字幕算失败：这次不回，不重试，失败不占上限。
- [x] **模型**：用部署者的对话模型，自带 LLM 的用户也一样，不计入用户的任何限额。
- [x] **写下**：在同一个事务里再查一遍评论还在，不在就作废。写下的那一刻就是露出时间。
- [x] **删评论**：
  - 她的回复还没露出时删：这次回复作废，不生成，不占上限。
  - 已经露出了再删：她的回复跟着删掉。
  - 删了以后可以再评论，算一条新评论，照样判断、照样占上限。
- [x] **运行记录**：新增一类 `moment_reply`，记在这位用户和这位角色名下。
  - 「用了自带密钥」总是否。
  - 写下时评论已经被删，记「被拒绝」。
  - 现有按种类计数的地方都不把它当成回合或通话。
- [x] **时间线接口**：每条动态再给出他赞没赞、他的评论（原话、时间），以及她已经露出的回复（日语、字幕）。没露出的回复不出现，也不透露有没有。
- [x] **前端**：
  - 行尾加一个「⋯」，弹出「赞」（赞过了显示「取消赞」）和「评论」。
    - 他评论过以后「评论」不能点，另多一项「删除评论」，点了先确认，因为她的回复会一起删。
  - 点「评论」，在这一条下面展开输入框和发送键，最多 140 字；发不出去时保留打的字，并提示。
  - 赞的一行里，他赞了就排最前，写「制作人」。
  - 评论区里：
    - 他的评论写「制作人：内容」；
    - 她的回复写「<她的名字> 回复 制作人：日语」，下面一行字幕；
    - 回复露出之前什么都不显示：没有「正在输入」，也没有「已读」。
  - `moments.test.ts` 测：赞的一行的顺序；评论和回复的写法；「⋯」里各项能不能点。
  - `DESIGN.md` 补上「⋯」菜单和评论输入。
- [x] **测试**：
  - 回复延迟的纯函数用 `FakeRandom` 逐个给数。
  - 经过 HTTP 接口和「跑一遍」：
    - 赞和取消赞，只存现在的状态；
    - 评论的 140 字、每条一条、409、422、404；

### 实现说明（票 23）

- **后台**：`MomentSettings.replies_per_day`（`config.DEFAULT_MOMENT_REPLIES_PER_DAY = 10`），`_Moments` 多一个字段，最少 1；保存时不给就不改（同 `map`）。前端 `adminConfig` 的朋友圈一项多一行「每位用户每天她最多回几条评论」。
- **存储**：`moment_likes`（只有 `moment_id`，取消就删行）、`moment_comments`（`id` 自增，`moment_id` 唯一；`text`、`commented_at`、`reply_at`、`reply_ja`、`reply_zh`）。`reply_at` 在回复露出前是到点时间，露出后是露出时间，不回时为空；回复露出看 `reply_ja` 不为空。都登记进 `USER_DATA`。
- **接口**（`moments_api.py`）：`PUT/DELETE /api/moments/{id}/like`（204）、`POST /api/moments/{id}/comment`（201，回 `{text, commented_at}`；409 已评论、422 字数）、`DELETE /api/moments/{id}/comment`（204，没评论也 204）。不在他时间线上的一律 404（`NoMoment`）。时间线每条多 `producer_liked`、`producer_comment`、`reply`。
- **两次判断**：发评论时 `moment_draws.draw_reply`（`REPLY_AFTER`：亲密 5–30、亲近 15–60、信任 30–120 分钟），冷淡、疏远、冷却时为空。到点在 `Moments.run_due` 里和到点的动态按时间合并逐条跑（`_reply`）；不回的把 `reply_at` 清空，不留记录。每天的上限用 `activity.read_replied_between` 按东京那天数 `moment_reply` 成功的记录（按记录开始的时刻算，跨零点生成的那几秒算前一天）。
- **提示词**：`moment_prompt.ReplyMaterial`、`reply_prompt`、`parse_reply`、`REPLY_RULES`、`COMMENTED`，评测（票 29）可以直接用。第一条系统消息只有人设、生日和世界设定（同发动态，不带回合的回复格式）；历史用 `engine.chat_history` 截取，转成 `ChatMessage` 时不带照片标签。「朋友圈」场合多一个 `replying`：此刻那行写「你这会儿在看自己朋友圈下面的评论」，制作人生日那句不提祝福。
- **前端**：`lib/moments` 的 `reactions`（多一个必填的 `herName`；评论区的一条分 `idol`、`producer` 两种）、`momentActions`、`canSendComment`/`commentLength`（按码点数，emoji 一个算一个，同后端 `len`）；`MomentsPage` 的「⋯」菜单、删评论的确认框、`CommentBox`。`DESIGN.md` 的朋友圈页补了「行尾「⋯」」「评论输入」，改了「赞和评论」。
- **判断**：
  - 评论照他打的原样存（含首尾空白），只在数字数时去掉首尾空白。
  - 停机：到点早于这次后端启动的回复也不生成，同动态的「停机不补」。
  - 部署者关掉朋友圈期间到点的回复，重新打开时作废（`_forget_plans` 一起清），符合「到点那一刻部署者关着就不回」。
  - 记忆用 `for_reaching_out(..., posting=True)`：评论区大家都看得到，用「最多隐约呼应一件、私下的事不点明」那段开头。
  - `REPLY_RULES` 比规格多两句：「别重复别人评论里已经说过的话」（对应票 13 的评测场景）、「评论区大家都看得到：关系再亲近也不写成情侣的口吻，他私下告诉你的事不要点明」（同发动态的规矩）。
  - 历史只放回合本身，不带送礼等事件的旁白（规格只说「截取照搭话」）。
  - 评论区里他的评论排在偶像的评论后面，她的回复跟在他后面；偶像的评论在时间线接口里没有露出时刻，排不出真正的先后。
  - 读素材时（记忆、此刻）出错的回复作废，不留运行记录；只有模型出错和解析不了记「失败」。

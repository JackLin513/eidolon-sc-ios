# 14: 走通一条纯文字动态

**What to build:** 部署者在后台打开「朋友圈」后，最近 7 天来过的用户，在导航第四项「朋友圈」里看到和他聊过的角色发的动态：日语原文、一行字幕、发的时间。这一张走通整条路：只有日常那条，不带地点、天气、配图，也没有赞和评论，这些由 17–23 补上。规格见 `../spec.md`，尤其是「部署者的设定」「存储」「节奏：到点的跑一遍」「写一条动态」「此刻：『朋友圈』场合……」「接口」「运行记录、看板、服务状态」「前端」几节，以及 Further Notes 实现顺序的第 1 条。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] **后台设定**：新增一项「朋友圈」（ADR-0013 的 `_Item`，写法照「搭话」那一项），放在配置页「限额与玩法」标签里「搭话」后面，不试调。这一张有两个字段：
  - 总开关：`.env` 的 `EIDOLON_MOMENTS`，默认关；`.env.example` 加一行。
  - 每位用户每天合计最多几条：默认 3，最少 1，只能在后台改。
  - 「回评论上限」由 23 加，「地图」由 17 加。
- [ ] **存储**，旧库启动时照 `IF NOT EXISTS` 建表，全部登记进 `USER_DATA`：
  - **动态表**：这一张就建全规格里的各列。配图规格、地点、天气这一张一律为空，由 17、18、21 接上。
  - **发布计划表**：用户、角色、计划那天（东京日期）、到点时间、工作那条还是日常那条、是不是她的生日。这一张都写成日常那条，工作那条由 19 接上。
  - **每位用户一行**：计划排到了哪天、上次打开朋友圈页的时刻。后者这一张不用，由 26 接上。
- [ ] **跑一遍**：新模块对外只有一个方法，「把现在到点的都跑一遍」。
  - 后端启动时起常驻循环，每分钟调一次，写法照搭话的循环：在 assembly 里启停，异常只写日志。时钟、随机数都用注入的。
  - 守 ADR-0028：读写都经过 `Database`。
  - 部署者关着朋友圈，或者没配对话模型时，什么都不做。
- [ ] **排计划**（写成纯函数：给定输入和随机源，返回当天的计划）：
  - 活跃的用户照搭话的「联系」：7 天内和任意一位角色有过回合，或者有过接通的通话；送礼不算。还要没被封禁、管理者没把他用部署者 key 的回合限额设成 0。
  - 够格的角色：这位用户和她现存的对话里有过回合，信任及以上，不在冷却中；没开好感度的部署按信任算。
  - 每位够格的角色每天掷一次：亲密约 80%，亲近约 50%，信任约 25%。她的生日（东京日期）必发。掷中的超过 N 位时先留生日的，其余随机。
  - 时间按时段加权抽（东京时间）：早 7–9 点权重 2，午休 12–13 点权重 2，下班后 18–24 点权重 4，深夜 0–2 点权重 1。同一位用户的几条至少隔 1 小时；剩下的时段里抽不出就今天不发。
  - 什么时候排：东京 0 点后第一次 tick 给活跃的用户排；这时不活跃、白天才回来的（或者部署者白天才打开的），在他够格后的第一次 tick 排，只从当天剩下的时间里抽。排过就记下，当天不再排；当天才第一次聊、才升档的角色等第二天。计划存进库，重启后接着读。
  - 各档概率、时段权重、活跃天数都是代码常量。
- [ ] **到点**：
  - 这一刻再判断一遍：部署者开着、配了对话模型；用户仍然活跃、没被封禁、限额没设成 0；她不在冷却中、信任及以上；这位用户按计划那天数的动态还没到 N 条。
  - 不满足就跳过、删掉这一行计划，不改期，不留运行记录。
  - 到点早于这个进程启动时刻的，跳过，不补。
  - 到点的按时间先后逐条生成，不并发。处理完（生成了或跳过了）就删掉这一行计划。
- [ ] **生成**：
  - 从部署者的配置借出对话模型（文字回合那组设定和思考强度），用完归还。自带 LLM 的用户也一样：不经过自带密钥、限额和免限额密钥那一套，不计入用户的任何限额。
  - 提示词照 ADR-0020 的形状，依次是：
    1. 共用固定部分：和回合一字不差的人设、世界设定；回合的格式说明换成一节「# 发朋友圈」。
    2. 制作人资料：称呼、生日。
    3. 不带历史。
    4. 一条靠后的系统消息，依次放：
       - 此刻：新的场合「朋友圈」，带东京的现在几点、`today_lines`、档位的语气、周期、制作人的生日（按他的时区）；不带日程和上次往来。
       - 从她的角色资料里随机抽 3 条当日常的种子，不抽「人物关系」一节的。
       - 记忆：调 `for_reaching_out`，只取她自己听来的，拿当前对话的最后一个回合当查询；当前对话里还没有回合时，只取最近的。
       - 她最近 5 条自己的动态（日语正文）。
    5. 用户那句话的位置放「（你想发一条朋友圈。）」。
  - 她生日那天另外告诉她今天是她的生日，正文围绕生日写。
  - 拼提示词的函数接受一份写好的素材，不自己读库。后台循环读库、攒出素材再调它；29 的评测会直接喂素材。
- [ ] **规则**（这一张只写和正文有关的几条，每条一句，照规格「规则要点」）：
  - 日语 1–3 句、最多约 100 字，服务器不截断。
  - 表情和颜文字按她的性格。
  - 不用 `#` 话题标签，不用 @，不带语气提示。
  - 资料种子可用可不用；换个话题，别和最近 5 条重复。
  - 记忆只隐约呼应、不复述；他私下告诉她的事不点明。
  - 可以提「プロデューサーさん」，但不写成情侣口吻。
- [ ] **输出和解析**：
  - 整段写完再解析，不走流式。只认 `<post><ja>…</ja><zh>…</zh></post>`，别的标签这一张先不管。
  - 缺日语或缺字幕算失败。语气提示照字幕的做法剥掉。
  - 失败不重试，当天不补。
- [ ] **写下**：写下的那一刻就是露出时间，时间线上显示的就是它。
- [ ] **运行记录**：新增一类 `moment`，记在这位用户和这位角色名下。
  - 「用了自带密钥」总是否；对话模型的调用记在这条下面，用量和花费自动进看板。
  - 成功或失败；被跳过的不记。
  - 留一个「降级了哪几部分」的字段，只记部分的名字和条数。这一张写成空，17 起开始写。
  - 现有按记录种类计数的地方都不把它当成回合或通话：回合趋势、按角色、用户页的最近用量、限额结算。
- [ ] **服务状态**：输出解析不了（调用本身成功）不算对话模型失败。
- [ ] **接口**：
  - **时间线**：这位用户 30 天内已经露出的动态，最新的在前，一次全给。每条有 id、角色、日语、字幕、露出时间；配图、地点、天气这一张为空。
  - 部署者关着时返回 409。
  - **账号**多一个字段 `moments`：部署者关着时为空，开着时为真。24 会把它换成用户自己的开关。
- [ ] **前端**：
  - **导航**：电脑的导航栏和手机的 dock 都加第四项「朋友圈」，顺序是对话、朋友圈、玩法、设置，图标用 Lucide `Aperture`。账号里朋友圈为空时这一项不出现。
  - **`/moments`** 是第一级地址，在外壳里：去那里不挂断，通话条照常。
  - **页面**照原型 A「时间线」：一栏，宽度 `max-w-3xl`，一条一行。左边头像；右边依次是名字（Row name）、日语正文（Body）、一行字幕（照对话气泡的做法）、Meta 字号的时间。
  - 没有动态时一行短短的空状态。打开页面时读一次时间线。
  - 照 `frontend/AGENTS.md` 的 shadcn 纪律。`DESIGN.md` 改两处：导航四项和 dock 的宽度、时间线的一行。
- [ ] **测试**：
  - 后端：推进假时钟后直接调「跑一遍」，照 `test_reach_outs.py` 的写法。新加一个每次都给同一个数的随机源替身，给这些测试用；最近一次往来的时间直接改库里的。要覆盖：
    - 活跃的定义（回合、接通的通话算，送礼不算，7 天）和够格的角色。
    - 0 点后第一次 tick 排；白天才回来的只从剩下的时间里抽；当天才升档的等第二天；重启后接着读计划。
    - 到点前不来，到点后来；到点那一刻的各条条件；停机错过的不补；失败不重试。
    - 部署者关着、没配对话模型、封禁、限额为零都不发。
    - 请求里有什么：「朋友圈」场合的此刻、3 条资料种子、只有她自己来源的记忆、最近 5 条、那句用户位置的话；没有历史、没有工具。
    - 用的是部署者的模型，用户自带了 LLM 也一样。
    - 解析失败记失败；时间线接口；账号字段；后台设定的保存和校验；运行记录；新表登记（`test_database.py`）。
  - 排计划的纯函数：`FakeRandom` 逐个给数，测各档掷中、生日必发、超过 N 先留生日、时段权重、隔 1 小时、剩下的时段为空。
  - 前端：`navShell.test.ts` 测四项的顺序、`/moments` 在外壳里、当前项、关着时没有这一项；新的 `moments.test.ts` 测时间线一行的 Meta。
- [ ] **验收**：按 `docs/agents/local-acceptance.md` 在本地构建版上看。本地库里有真的对话，改用一份副本：改好时间，调一次「跑一遍」，用真模型造出一条动态。用 Playwright 在宽屏和手机上各看一次：导航的四项、时间线的一行、通话中切过去不挂断。看完删掉副本、脚本和截图。
- [ ] 表结构有改动，部署前手动备份数据库。
- [ ] `sh scripts/affected-tests.sh <基点>` 通过，推送后 CI 全绿。

# 06: 拍板：一条动态里有什么、素材怎么挑

Type: grilling
Status: resolved
Blocked by: 01, 04, 10

## Question

一次对话模型调用写完一条动态。要定：

- **输入**：给她哪些素材、各带多少——今天做完的日程工作（一天几项时全给）、此刻里的哪几行、角色资料和剧情库里的日常（要不要检索）、她自己听来的记忆（几条、多近）、最近几条自己发过的动态（防重复）、地点池里给她挑的候选地点（几个、怎么按她筛、怎么保证 30 天不重复）。
- **输出**：动态文字的长度和语言（日语原文加字幕，还是只写中文？朋友圈里她用什么语言发）、配图规格（构图枚举和几栏 tag，按原型结论）、是纯文字还是带图由谁定、地点选哪个、谁赞、0–3 条评论各是谁写的、各自往后错开多久露出来。
- **合照**：如果原型说合照能进 v1，合照里的人由谁定（只能是这条动态里提到的偶像？同组合？），和「评论的偶像」是不是同一拨人。
- **生日动态**：她生日那天的那条，以及其他偶像生日时她要不要发一条祝福；生日当天评论区「更热闹」到什么程度（评论数上限放宽？）。
- **写坏了**：输出解析失败、配图生成失败时，这条动态是改成纯文字照发、整条不发，还是重试。

## Comments

### 页面原型交接

「原型：入口和朋友圈页面」定的页面（A 时间线）按一段中文正文做的。这里如果定成日语原文加中文字幕，时间线的文字区要多一行字幕（照对话气泡的做法），写规格时回头补上。

### 「拍板：制作人的赞和评论、她在对话里怎么知道朋友圈」交接

- 她回制作人评论用什么语言，跟这里定的动态语言走，那张票没另定。其他偶像的评论同理。
- 此刻里要列她最近 3 天的动态，包括「配图拍了什么」，她回评论时也要看配图的描述。所以输出里除了生图用的 tag，还要留一句给她自己看的配图描述（或者能从配图规格拼出来），定输出格式时一起定。

### 「拍板：地点池怎么整理」交接

地点池的形状定了（字段、14 类、`jobs.toml` 的 `places`、`characters.toml` 的 `place_likes`），这里定怎么挑：

- 给她几个候选（调研建议 3–5 个）、怎么筛：素材的类别（工作有 `places` 就按它，没写的工作那条不带地名）、`seasons`、`slots`、`place_likes` 和圣地 `idols` 加权；下雨时偏室内类别要不要做（室内室外由类别决定）。
- 30 天内同一位用户不重复（硬性排除），同一位偶像跨月少重复（降权）要不要做。
- 「她自己的日常」「此刻」这类素材没有现成类别时，候选怎么铺开；哪些动态干脆不带地名（调研估约 1/3）。
- 演出场馆只给「往年今天的演出」用。
- 她选错 id 或没选时由服务器随机定一个，还是这条不带地名。
- 她在正文里怎么提地名（地名显示只用日文原名，正文随这里定的动态语言）；圣地只借景，不说「这是我那张卡拍的地方」。
- 动态存地点时要不要连地名、坐标一起存一份：维护者以后改名、删掉条目，已发的动态还显示原来的。

## Answer

用户 2026-10-31 拍板（grilling 两轮，建议全部采纳）：

- **语言和长度**：动态正文、其他偶像的评论、她回制作人的话都是日语原文加中文字幕，和对话、搭话一样；时间线每条正文下多一行字幕（照对话气泡）。制作人的评论照他打的原样显示。正文按日语 1–3 句、最多约 100 字，像随手发的一条；偶像评论一两句、最多约 40 字。都是提示词里的要求，服务器不截断。表情和颜文字按她的性格，人设里爱用就用；不用 `#` 话题标签，不用 @。不带语气提示，写了照字幕的做法剥掉。
- **每条都有文字**：不做只有配图的动态（配图失败要能退成纯文字）。术语表「动态」已改成「日语原文连同字幕，可以带一张配图」。
- **带不带图**：服务器在调用前先掷，约 2/3 带图；部署者没配生图时全部纯文字。掷到带图时，服务器告诉她这次允许的构图（合照只在 NovelAI 形态下允许），她从中选一种。
- **两种动态，给她的素材**（工作那条、日常那条由「拍板：发布节奏和调度」排计划时就定了）：
  - 都给：人设、世界设定；此刻里的现在几点、`today_lines`（东京今天的生日、节假日、往年今天的演出）、好感度档位、周期、制作人的生日（那天她可以发一条祝他）、发的那一刻东京的天气（取不到就不给）。不给本周和下周的日程、上次往来的时间。
  - 工作那条：今天做完的全部工作（名字和 `note`），一条串起来。
  - 日常那条：从她的角色资料里随机抽 3 条（不抽「人物关系」一节）当日常的种子，可用可不用。不检索剧情库。
  - 记忆：照搭话调 `for_reaching_out`，拿当前对话的最后一个回合当查询；只能隐约呼应，不复述。
  - 防重复：她最近 5 条自己的动态（正文和配图描述），要她换个话题。
- **地点候选**：
  - 工作那条只从这几项工作的 `places` 类别里挑，都没写就不带地名；日常那条全部类别都可以，按 `place_likes` 加权，`idols` 里有她的圣地加权。
  - 都要满足当季的 `seasons`、发布时段的 `slots`；30 天内这位用户用过的地点硬性排除；跨用户少重复不做。
  - 生成时先取天气，有降水就只给室内类别（室内室外按类别写死）。演出场馆只在 `today_lines` 里有她往年今天的演出时加进来。
  - 给 4 个候选外加「不带地名」；在家、宿舍时她选不带，不硬配比例。她写的 id 不在候选里就不带地名，不随机补。
  - 存动态时把地名和坐标复制一份，维护者以后改名、删条目，已发的照旧显示。正文里提不提地名随她，用日文自然地提；圣地只借景。
- **圈子：谁赞、谁评论、合照里有谁**：服务器给每条动态抽一个 4–6 人的圈子：同组合权重最高，她角色资料「人物关系」里写到的其次，偶尔一位别的组合；今天过生日、和她同组合或有关系的那位必进。提示词里写每位成员的 id 和名字、她资料里关于这个人的那一条、这个人人设里的「自称」「对他人的称呼」「口癖」三节。同一次调用里由她选：赞的 1–6 人；评论的 0–3 人和先后顺序（后面的可以顺着前面的接一句，不对制作人说话）；掷到合照时合照里的 1–2 人（只能选配了 `photo_tag` 和 `photo_appearance` 的），合照里的人必定算进赞的人。圈子以外的人服务器丢掉。
- **露出时间**：服务器随机定，不让模型写。赞在发出后 5 分钟到 3 小时，评论 15 分钟到 6 小时、按她排的顺序依次往后，夜里照常露出。代码常量，上线后看数据再调。
- **生日**：她生日那天圈子扩到 8–10 人，赞最多 10，评论最多 6，正文围绕生日写。别的偶像生日不另排祝福动态，日常那条她可以拿 `today_lines` 里的生日当素材；过生日的那位和她有关系时进圈子（见上）。
- **分寸**：写评论的偶像只靠提示词约束：只回应正文、配图里写出来的东西和她们之间的关系，不提正文里没有的事（一次调用里模型看得到她的记忆，不拆成两次）；评测里专门看这一条。动态在故事里是同事朋友都看得到的：可以提「プロデューサーさん」（谢他排的工作、他生日时祝一句），他私下告诉她的事只隐约呼应、不点明，关系再亲近也不写成情侣口吻。
- **输出格式**：沿用回复的标签写法，不用 JSON 或结构化输出（部署者的模型不一定支持，各中转支持不一；日语、中文的自由文本在 JSON 里要转义，更容易坏；后端所有对话模型调用都没用过 `response_format`）。整段写完再解析，不走流式：

  ```
  <post><ja>…</ja><zh>…</zh></post>
  <image>…</image>          只在掷到带图时写
  <place>候选 id 或 none</place>
  <likes>hiori, meguru</likes>
  <comment from="hiori"><ja>…</ja><zh>…</zh></comment>   0–3 条，按露出顺序
  ```

  正文只有一对 `<ja><zh>`，不分段。名单写 id（提示词里写成「`hiori`：風野灯織」），服务器也认 `name` 和 `short_name`。
- **`<image>` 的栏**：照照片标签分栏：`composition`（七种之一，只能是这次允许的）、`framing`（有人的构图才写）、`place`/`outfit`/`action` 三栏英文 tag（无人构图只用 `place` 和 `action`）、`with`（合照里的人，圈子里的 id）、`note`（一句中文，这张图拍了什么，不发给生图服务）。`note` 就是此刻里「最近的动态」和她回评论时看的配图描述。各构图怎么清洗、前后缀、风景怎么补「在日本」，交给「拍板：配图的提示词细节」。
- **写坏了**（整段解析不了就跳过、配图失败照发纯文字，「拍板：发布节奏和调度」已定）：正文缺日语或字幕算整条失败；其余各自降级：`<image>` 坏了改纯文字，地点错了不带，某条评论缺字幕或作者不在圈子里只丢这一条，赞的名单坏了当没人赞。降级记进运行记录，不重试。
- **用的模型**：部署者的对话模型，和搭话一样，不计入限额。

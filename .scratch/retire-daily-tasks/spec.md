# 下线每日任务：整块拆掉，成就留着，每天发的抽奖 1 → 2

Status: ready-for-agent

术语以 `GLOSSARY.md` 为准，特别是「每日任务」（这一块删掉这条）「成就」「抽奖」「重置卡」「运行记录」「看板」「数据包」「玩法」。说每日任务、成就、抽奖次数、玩法页、卡、子页，不说日常、委托、签到。所有决定的来历在 `.scratch/play-and-schedule/map.md` 和「拍板：下线每日任务」（票 10）里；为什么下线见地图 2026-10-23 的重画：日程做完的工作加好感度，日程不接手发抽奖，每日任务就不再需要。这是四块里的第四块，前提是日程（`.scratch/schedule/spec.md`）已经合进 main、部署；它是单独一块，不塞进日程那一块。每日任务原来的规格是 `.scratch/daily-tasks/spec.md`，玩法页那一块把它搬进了「每日任务与成就」子页，位置以玩法页规格为准。前端先读 `frontend/AGENTS.md` 的「shadcn 纪律」，视觉以 `DESIGN.md` 为准；给用户看的文案要少。

## Problem Statement

- 每日任务当初是为了多一条拿礼物的路、让常来的人多拿抽奖。日程上线后，制作人每周有了真正要做的事（排日程），而且做完的工作让她的好感度上升；每日任务那三项「说一句话、送一件礼、十个回合」成了多余的打卡。
- 它留着就要维护：界面一节、进度表、运行记录一种、看板三格、隐私政策和文档的条目、玩法页卡名里的半截。拆掉比改头换面接到日程上干净。
- 拆掉以后抽奖只剩每天发的 1 次加成就给的，拿礼物的速度掉一截；按票 11 的尺子，每天发 2 次时认真处的人信任到亲近约 11 天、到亲密约 25 天，仍在目标附近。

## Solution

- 删干净每日任务：三项任务的常量、进度表和它的迁移、运行记录的种类和汇总行、礼物状态接口里的字段、前端的一节和它的纯函数、文案、截图脚本里的假数据。到账记录留着（它是幂等发奖的凭证，成就还在用同一张表）。
- 留下成就要用的：往来记账、幂等的发奖入口、导航「玩法」上的点、超过 7 次时「+n」的显示、空圈图标。
- 每天发的抽奖 `DRAWS_PER_DAY` 1 → 2，上限 `MAX_DRAWS` 7 不动，抽奖台的 7 个圆点不动。
- 玩法页「每日任务与成就」卡改名「成就」，路由 `/play/tasks` 改成 `/play/achievements`、旧路径跳转；子页只剩成就。看板「每日任务和成就」改回「成就」，去掉三格。
- 隐私政策、使用条款、`docs/configuration.md` 三语、`docs/deploy.md`、`docs/data-package-format.md`、README 三语和截图、词汇表、`DESIGN.md` 都去掉每日任务。发一条短公告。部署前备份；取完规格以后删计划分支。

## User Stories

### 用户看到的

1. 作为用户，我想玩法页上那张卡叫「成就」，状态写「已解锁 n 个阶段」，有新解锁时写「n 个新解锁」，这样卡上说的就是里面有的。
2. 作为用户，我想点进「成就」子页只有成就那一块，页首返回键照旧，这样不再看到做不了的任务。
3. 作为用户，我想收藏过的 `/play/tasks` 打开时到 `/play/achievements`，这样旧链接不坏。
4. 作为用户，我想每天北京时间 0 点发 2 次抽奖，这样不做任务也比以前多拿。
5. 作为用户，我想抽奖台那句写「明天 0:00 再发 2 次，最多攒 7 次」，这样知道每天发几次。
6. 作为用户，我想攒到 7 次就不再发，7 个圆点不变，这样上限和以前一样。
7. 作为用户，我想成就给的次数仍能超过 7、7 个点后面照样写「+n」，这样成就的奖励不打折。
8. 作为用户，我想导航「玩法」上的点照旧表示有新到的抽奖次数（现在只有成就会到账），这样提示的意思不变。
9. 作为用户，我想部署那天下一个北京 0 点起拿到 2 次，当天做了一半的任务不补发，这样换法简单。
10. 作为用户，我想新注册的用户第一份也是 2 次，这样新老一致。
11. 作为用户，我想成就的进度、已解锁的阶段、集齐的重置卡一个都不少，这样下线任务不碰成就。
12. 作为用户，我想以前做任务得到的抽奖次数和礼物都还在，这样已经到手的不收回。
13. 作为用户，我想对话页更多菜单里的「成就」、统计页的成就一节都不变，这样成就在哪看都照旧。
14. 作为用户，我想「去对话」「挑一件」这两个任务里的按钮随任务一起消失，这样子页里没有多余的键。
15. 作为用户，我想看到一条公告：每日任务下线了，每天发的抽奖改成 2 次，成就照旧，这样知道变了什么。

## Implementation Decisions

### 先对照 main

- 第一张票先对照当时的 main：玩法页那一块把礼物页拆成了子页，每日任务一节在「每日任务与成就」子页里；日程那一块改了好感度常量和看板的「好感度」标签。按「拆什么」找，不按这份规格写的位置找。

### 后端删什么

- 每日任务的三项常量和它们的类型（`DAILY_TASKS`、`DailyTask`、`DailyTasks`）、往来记账里算进度的那部分、每日任务的进度表（`daily_task_progress`，连同它在 `USER_DATA` 里的登记）、到账结构 `Rewarded` 里的 `daily_tasks` 字段、礼物状态接口里的 `daily_tasks` 和 `renews_at`、运行记录的 `daily_task` 种类、看板里 `daily_tasks` 那一小节和它的筛选。
- 到账记录表（`gift_rewards`）留着，旧行不删：它是幂等发奖的凭证，成就用同一张表；它的键里原来每日任务的那种写法不再产生，已有的留着。
- **迁移**：启动时一次：删 `daily_task_progress` 表；删 `activity_records` 里 `kind = 'daily_task'` 的行和 `record_rollups` 里同种类的汇总行。重复启动时表不存在、行为零也不报错。看板不为旧记录留特判（旧记录已删）。库的表登记测试据此更新。
- 留下：往来记账模块（`happenings`，成就在用它接回合、送礼、通话结束、抽奖、档位变化）、幂等发奖入口 `Gifts.reward`、`rewarded_at`、运行记录的 `achievement` 种类。

### 抽奖次数

- `DRAWS_PER_DAY` 1 → 2；`MAX_DRAWS` 7 不动；补发逻辑不动（读的时候按北京日期补、`max` 保留超出的）。按现有逻辑，部署后的下一个北京 0 点起每人补 2 次；新用户第一份 2 次；部署那一刻今天的任务不补发。
- 好感度规格「推算」那段、礼物规格写抽奖次数的两处、`docs/configuration.md` 「好感度和礼物」里「每天 1 次」改成 2 次。

### 前端

- 玩法卡注册表：`tasks` 改成 `achievements`，名字「成就」，图标 `Trophy`（`AchievementsIcon`，不变），去 `/play/achievements`。状态：平时「已解锁 n 个阶段」（n 用成就合计接口的 `stages`，或礼物状态里合起来的成就算出的解锁数，取现成的那个），有新解锁时换成「n 个新解锁」；名字旁的点规则不变。
- 路由 `/play/tasks` → `/play/achievements`，旧路径在 `proxy` 里跳转（同 `/gifts` → `/play/gifts` 的写法）。子页只剩成就那一块；页首标题「成就」。
- 删掉：每日任务的一节组件、`lib/dailyTasks` 和它的测试、`Rewarded` 类型里的 `daily_tasks`、文案里每日任务一节、抽奖台说明里「每日任务给的」那几句的注释、截图脚本里每日任务的假数据。
- 抽奖台那句改成「明天 0:00 再发 2 次，最多攒 7 次」（换新时刻按制作人时区写，写法不变）；超过 7 次时的「+n」和那句「每天发的已攒满」留着（成就给的仍可超上限）。
- 留下：`lib/rewards`（「玩法」上的点）、`TaskOpenIcon`（成就「集齐」那一行在用）、`lib/achievements`。
- 看板：「每日任务和成就」小节改回「成就」，去掉三项任务的格子，`Dashboard` 类型去掉 `daily_tasks`，「好感度」标签的显示条件去掉对它的依赖（保留日程那一块加的条件）。配置页「好感度和礼物」卡的说明去掉「每日任务」半句。
- `DESIGN.md`：「玩法页」一节里卡的名字改「成就」、子页只剩成就；每日任务那一条删掉；「礼物」子页抽奖台的描述里「每日任务给的」改成「成就给的」；导航「玩法」上的点的说明改成「成就到账」；图标一节去掉每日任务相关（空圈 `Circle` 改写成成就「集齐」那一行在用）。

### 词汇表

- 删「每日任务」条目。「抽奖」里「做每日任务得到的不受上限约束」改成「成就给的不受上限约束」，仍写「每天发」、不写几次（词汇表不写数字）。「数据包」「运行记录」「看板」各去掉每日任务那半句。「成就」「统计」不动。在这一块自己的第一张票里改。

### 对外文档

- **隐私政策**：「每日任务和成就」那条改回「成就」（去掉「今天每日任务做到哪了」）；「运行记录」那条去掉「做完了哪项每日任务」；「看不到」那条去掉每日任务；改「最后更新」日期。
- **使用条款**：「玩法」那条去掉每日任务（成就给的抽奖次数和重置卡那句留着）；改「最后更新」日期。
- **`docs/configuration.md`** 三语：删「每日任务」那一条；「关掉时」、后台表格看板一行、「看不到的」一行各去掉半句；「每天 1 次」改 2 次。
- **`docs/deploy.md`**：后台那段去掉每日任务。**`docs/data-package-format.md`**：「不在数据包里」那句去掉每日任务。
- **README** 三语：功能句「做每日任务、解锁成就能多得抽奖次数」改成「解锁成就能多得抽奖次数」；玩法页截图重拍（卡名已是「成就」），图下那句和 alt 随之改。
- **每日任务规格**（`.scratch/daily-tasks/spec.md`）：Status 改成 `retired`，开头加一句「2026-10 下线，见 `.scratch/retire-daily-tasks/spec.md`」；正文不改。成就规格里提到每日任务的位置描述不动（它是历史）。

- **后端走现有的 HTTP 接缝**（`make_client` 加 `FakeClock`，判断模型照 `test_gift_draws.py` 打开好感度）：
  - 礼物状态接口没有 `daily_tasks`、`renews_at`；回合 `done`、送礼返回的「这次到账」没有 `daily_tasks`；做一个回合、送一件礼不再到账（`rewarded` 为 null、抽奖次数不变）。

## Out of Scope

- 用别的东西顶替每日任务（从池子里抽的任务、日程接手发抽奖、连续来访奖励）。
- 调 `MAX_DRAWS`、抽奖概率、成就的门槛和奖励。
- 删到账记录表里每日任务的旧行。
- 回滚已发出的抽奖次数、礼物或重置卡。
- 成就、统计、分享图的任何改动。
- 「本周排了日程的人数」旁边加格（票 09 已定看板不加「日程带来的好感度」）。

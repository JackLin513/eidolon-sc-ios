# 13: 按话题带上她的资料，不编具体的人和事

**What to build:** 光顾进门时，拿这次话题的说明去查她的角色资料，取前 3 条放进这次光顾的提示词；共用块的酒吧写法加一条防编造的规矩。同一位角色、同一个话题查过一次就记在内存里。查不到时照常进门。配置指南三语的「酒吧」一节补一句。见规格「提示词」里的「她的资料」「防编造的规矩」和 Testing Decisions 的「她的资料」。

**Blocked by:** 无

**Status:** ready-for-agent

- [ ] 进门时按话题说明用 `CharacterFacts` 查资料，重排后取前 3 条（常量），不设阈值；只查资料，不查剧情库，来意不参与查询。放进「这次光顾的块」，标题照文字回合的「角色资料」。
- [ ] 按角色和话题记在进程内存里，重启前不再查；查的那一次的服务调用挂在这次光顾的运行记录下面。没配向量化、出错或超时：照常进门、不带资料、不重试，也不记住失败。
- [ ] 共用块的酒吧写法加防编造的规矩：今天、今晚的小事和心情可以即兴；过去的经历，家人、组合伙伴和别的偶像的名字、关系和设定只用人设和资料里有的，没有的说得笼统，不编具体的名字和事件。
- [ ] 测试照 Testing Decisions 的「她的资料」：提示词里有查到的资料；同一角色同一话题第二次进门不再调用向量化和重排；向量化失败照常进门、没有资料那一段；共用块里有规矩。
- [ ] `docs/configuration.md` 三语「酒吧」一节加一句：配了向量化时，按话题带上她的资料。中文先写，英文、日文照译。
- [ ] 开发脚本 `backend/scripts/bar_visit.py` 也能查资料（用 `.env` 里的向量化和重排；临时库里资料第一次查时向量化），能指定话题。
- [ ] 用开发脚本跑「家人」「过去的事」「组合里的伙伴」各两三位角色，打印查到的 3 条资料和台词，存成文件；自己先看取出来的资料对不对题、有没有编出资料里没有的人和事，能改的直接改，再停下等用户看措辞。

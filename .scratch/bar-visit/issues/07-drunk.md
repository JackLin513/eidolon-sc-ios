# 07: 醉

**What to build:** 她喝下的酒精一杯杯累计，到了她酒量的门槛就醉了。醉的那一杯，反应照常写；同一次调用接着写一段短闲聊，用醉的写法告别（话多、犯困、情绪起伏、说心里话，护栏照定图时的），计划里后面的单不再点。这次光顾记成「醉了」，下次她可能提一句「上次喝多了」，但不会因此只点无酒精的。故意灌醉不算错，醉了不加分也不减分，界面上不显示醉意。见规格「判定」里醉那一条、「提示词」，以及票 06、07 的答案。

**Blocked by:** 05

**Status:** ready-for-agent

- [ ] 醉意每次进门从 0 开始，每上一杯加上这杯的酒精份数：大杯按翻倍后的份数，瓶装按目录里的份数，Mulan Tea 是 0。门槛按酒量：`weak` 8、`medium` 14、`strong` 20，写成常量，和别的酒吧常量放在一起。
- [ ] 到了门槛，这次上酒以后的那次调用就是告别调用。要写的是这杯的反应，再加短闲聊和醉的告别；提示词里写「从这一段起你醉了」，告别要求里写醉了。
- [ ] 光顾记录记醉了；下一次光顾的提示词里，「上次醉没醉」照实写。
- [ ] 判定只看点单条件：往能选 Karmotrine 的饮品里多加酒，仍然是那一款。醉不影响档位。
- [ ] SSE 不推醉意。
- [ ] 测试：三档门槛（各用刚好到和差一份两种情形）；大杯翻倍的份数；瓶装的份数；醉的那次调用要写的东西，以及后面的单不再点；调用次数比计划少；记录记了醉；下一次的提示词里有醉。
- [ ] 把 GLOSSARY「醉」和实现对一遍。pyright、ruff 通过；提交前跑 affected-tests。

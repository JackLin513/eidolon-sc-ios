# 02: 起草：每位角色的口味

**What to build:** 给 29 位角色每人写好酒吧口味的五样，写在 `characters.toml` 里，和 `liked_gifts` 放在一起：`bar_flavors`（喜欢的口味，1–2 种，必填）、`bar_kind`（喜欢的种类，0–1 种）、`bar_favorites`（爱喝的饮品，1–3 款饮品 id，必填）、`bar_disliked_flavor`（讨厌的口味，0–1 种，推不出来就不填）、`bar_tolerance`（酒量 `weak`、`medium`、`strong`，必填）。每位的出处文件 `facts/<id>.sources.md` 新开一节「酒吧口味」，每一条写一句理由。加载时校验这五列，写错了后端起不来。做完先停下，等用户校对。见规格「角色的口味」和票 04 的答案。

**Blocked by:** 01（饮品 id 要来自目录）

**Status:** ready-for-agent

- [ ] 依据：剧情里有饮食偏好的就引剧情，找不到的从人设推，标「人设推断」并写清理由。种类和讨厌的口味也一样，可以从人设推。酒量按年龄和性格推：刚到能喝酒年纪的偏弱，成年组、性格豪爽的偏强。爱喝的饮品从口味和种类对过去。
- [ ] 爱喝的饮品尽量分散，不让一半人都爱同一款；不要求每款都有人爱。はづき 也要写。
- [ ] 校验：口味、种类、酒量都在列表里；爱喝的都在饮品目录里，两份都加载完再查，照 `gift_catalog.check_liked_gifts`；讨厌的口味不能和喜欢的口味重合；爱喝的饮品不能是讨厌的口味。坏了报配置错误，并指出是哪一位。测试的 `CharacterConfig` 能带上这几列。
- [ ] 测试（照 `test_characters.py`）：真实的 `characters.toml` 通过校验；临时配置里缺必填项、爱喝的不在目录里、讨厌的和喜欢的重合各被拒。
- [ ] 做完停下，不往下做别的票。Comments 里列一张 29 人的总表（五样加一句话的依据），等用户校对，用户改完再关票。

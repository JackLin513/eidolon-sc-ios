# 05: 走通一次光顾：进门、点单、上酒、告别

**What to build:** 从进门到告别走通一整次光顾，用接口就能玩，测试里用假模型走。这一张的点单只出「直说饮品名」一种说法，其余说法是票 06；醉是票 07，奖励是票 08，限额和运行记录是票 09，出错和作废是票 10。

后端新开一个**酒吧模块**，对外只有几个动作：读、进门、上一杯、离开（再试一次是票 10）。接口层只做 HTTP 和 SSE。

- **状态**：每位用户同时最多一次光顾，放在内存里，有一个随机的 `visit_id`。新开一次光顾时，旧的那次作废。
- **进门时抽**：
  - 角色：这位用户今天（北京日期）还没有玩完的光顾时，是今天的角色，用用户 id 加日期做确定性散列，从 29 位里取一位；玩完过以后随机，各位同等可能，冷却中的她也照样来。
  - 来意：今天给她排的、已经做完的那项工作一半概率当来意；其余从清单里抽，避开最近 3 次玩完的光顾用过的，抽空了就放开。
  - 话题：同样去重。
  - 杯数：1 杯 20%、2 杯 60%、3 杯 20%。
- **每一单在写点单的那次调用之前抽**：目标饮品照三个桶抽（爱喝的 45%、合口味的 35%、心血来潮 20%），剔掉讨厌的口味、这次已经点过的；第一单还剔掉上次玩完的光顾点过的；桶抽空了就落到下一个桶。说法先固定为直说名字。
- **判定**：服务器重新匹配，调坏的回 422；能上的判成上对或上错，直说名字没有「上得最好」这一档。上错时错在哪先只分「口味对了种类不对 / 种类对了口味不对」「讨厌的口味」「完全不对」。
- **提示词**：照规格「提示词」四块。共用系统块和最后一条 assistant 消息各打一处缓存标记；不给工具，不检索，不调判断模型。思考强度跟文字回合那一项。
- **输出解析**：照规格「输出格式和解析」。`<her emotion>`、`<ja>`、`<zh>`、`<producer>`，点单句标 `order="true"`；边收边解析，每收完一句推一句。
- **接口**：`POST /api/bar/visits`、`POST /api/bar/visits/{visit_id}/serves`、`DELETE /api/bar/visits/{visit_id}`，SSE 推 `visit`、`line`、`memo`、`waiting`、`done`。上一杯先推一句服务器从写死的句子里挑的「请慢用」。最后一杯以 `done` 收尾，这一张里 `rewarded` 一律是 `null`。
- **玩完**：告别写完的那一刻，在写事务里写一行光顾记录。下一次光顾的提示词里带「她记得上次」：来过几次（第一次 / 来过几次 / 常客）、上次多久以前（很久没来）、上次每单的饮品和档位、醉没醉（先恒为没醉）。

见规格「一次光顾的状态」「选角色、来意、话题、杯数」「点单怎么抽」「判定」「提示词」「输出格式和解析」「接口」「玩完、光顾记录和奖励」（奖励除外），以及 Testing Decisions 接缝一的对应几条。

**Blocked by:** 01、02、03、04（只要文件在、校验能过，不必等用户校对完）

**Status:** done

- [x] 酒吧模块和四个动作中的三个；进门、上一杯、离开三个接口只给登录并同意了条款的用户。酒吧关着时进门 409（`bar_closed`），已经在进行的光顾照常走完。部署者没有对话模型、用户也没带自带 LLM 时，进门被拒的回答和文字回合一样。
- [x] 进门推 `visit`（`visit_id`、`character_id`），然后是几句 `line`、点单句、`memo`、`waiting`。上一杯先推「请慢用」，再推反应、闲聊、下一单。最后一杯推反应、短闲聊、告别和 `done`。调用次数是杯数加 1。
- [x] 选角色：同一用户同一天反复进门都是同一位，中途离开再进也是；换一天换人；玩完以后再进是随机的；冷却中的她照样能来；跨零点按进门那天算。
- [x] 来意和话题：最近 3 次用过的不再出现，抽空了放开；今天做完的工作一半概率当来意，提示词里有它的名字和说明；日程关着时没有；`not_for` 的不给はづき。来意的基调进提示词。
- [x] 目标饮品：讨厌的口味永远抽不到；同一次光顾不重复；第一单避开上次点过的；桶抽空了往下落。
- [x] 判定：直说名字只认目标这一款，上对和上错都对；调坏的 422，状态不变；不是等上酒的时候 409；瓶装能上。
- [x] 提示词：共用块里有人设、她的生日那句、世界设定、IF 的设定和护栏、酒吧的写法和输出格式。光顾块里有档案、来意、话题、杯数、好感度档位那几句（关着时不写）、`today_lines`、她在酒吧的记录、她的口味。这次要写什么的块里有点单卡（不含算对的范围）、这一杯的判定和错在哪、告别时每一杯的档位。两处缓存标记位置对。不给工具。用 `llm.prompts` 断言。
- [x] 解析：缺 `<zh>` 的拿日语那句当字幕；缺 `<ja>` 的那句丢掉；情绪不在七种里的当 calm；标签外的文字丢掉。没有标 `order` 的，取她的最后一句当点单句。这一张里，一句完整的都没有时先当作这次调用失败、结束这次光顾，重试是票 10。
- [x] 光顾记录表（用户数据，登记进 `USER_DATA`）：每次玩完写一行，字段照规格；台词不存。删账号一起删，删一段对话不碰，数据包导出里没有、导入也不动它。
- [x] 她记得上次：第二次光顾的提示词里有来过几次、上次多久以前和每单的饮品、档位。常客（玩完 5 次及以上）和很久没来（上次超过 14 天）用常量。中途离开的光顾不算。对话的提示词里没有任何酒吧的东西（先例 `test_dynamic_context.py`）。
- [x] 离开后、被新开的光顾顶掉后，旧的 `visit_id` 回 410（`visit_gone`）。不是这位用户的 `visit_id` 也回 410。
- [x] 测试走接缝一：`make_client`、`FakeClock`、`FakeRandom`、`FakeLLM` 照脚本吐标签，读 SSE 照 `test_text_turn.py`，库里的东西用 sqlite 直接查。

### 实现说明（票 05）

**模块。** 酒吧模块 `eidolon/bar.py`（`Bar`：`read`、`enter`、`serve`、`leave`），`Backend.bar` 由 `assembly.build` 建；`Backend.drink_catalog` 去掉了，`GET /api/bar` 改成调 `bar.read()`。旁边三个只给它用的模块：`bar_rules.py`（所有比例和门槛常量、`draw_order` 抽目标饮品、`judged` 判定、`Order`／`Serving`／`Had`／`Reason`）、`bar_prompt.py`（四块提示词）、`bar_reply.py`（`BarParser` 和 `BarLine`）。`bar_api.py` 只做 HTTP 和 SSE。

**SSE 事件**（`data: {json}`，每个都有 `type`）：
- `{"type": "visit", "visit_id", "character_id"}`：进门的第一个事件；
- `{"type": "line", "speaker": "her", "emotion", "ja", "zh"}`，点单句另带 `"order": true`；制作人的是 `{"type": "line", "speaker": "producer", "zh"}`，「请慢用」也是这个形状；
- `{"type": "memo", "text": "她要 Sugar Rush。"}`：跟在点单句后面；
- `{"type": "waiting"}`；
- `{"type": "done", "rewarded": null}`；
- `{"type": "failed", "message"}`：这一张里调用失败（模型报错、自带 LLM 出错、一句完整的都没有）就推它并结束这次光顾，之后这个 `visit_id` 回 410。

**上酒正文**：调制的 `{"method": "mix" | "blend", "adelhyde", "bronson_extract", "powdered_delta", "flanergide", "karmotrine", "ice", "aged"}`（份数缺省 0，冰和陈化缺省 false），和 `GET /api/bar` 里饮品的字段同名；瓶装 `{"method": "bottle", "bottle": "<饮品 id>"}`。两边都可以带 `own_keys`（和文字回合同一个形状）；进门的正文是 `{"own_keys": ...}` 或 `{}`。`method` 是 bottle 却没给 `bottle`、或反过来，是 pydantic 的 422（没有 `code`）。

**拒绝**（都是 `{"detail": "<中文>", "code": "<代码>"}`）：进门时酒吧关着 409 `bar_closed`；不是这位用户正在进行的光顾（不存在、已离开、已告别、被顶掉、别人的）410 `visit_gone`；不在等上酒 409 `not_waiting`；调坏的、没有这款瓶装 422 `broken_drink`。离开 `DELETE` 成功是 204。

**光顾记录表** `visit_records`：`id`、`user_id`、`character_id`、`entered_at`、`left_at`（告别那一刻）、`entered_on`（进门那天的北京日期）、`reason`（来意 id；日程当来意时是工作的名字）、`topic`、`orders`（JSON 列表，每单 `{"target", "phrasing", "served", "big", "tier"}`）、`drunk`、`rewarded`（这一张恒为 0）。索引按 `(user_id, character_id, id)` 和 `(user_id, entered_on)`。登记进 `USER_DATA`；数据包和删一段对话都不碰它。

**随机源的问法**（测试按这个顺序给 `FakeRandom`，见 `test_bar_draws` 的模块说明）：进门：这一天已经玩完过才抽角色；来意（她今天有做完的工作时先抛一次 `random(2)`，0 就用工作）；话题；杯数 `random(100)`；第一单的桶 `random(100)` 和桶里第几款。上一杯：「请慢用」第几句；还有下一单时再抽桶和第几款。

**判断题：**
- 部署者的对话模型是启动必填项（`CHAT_LLM_*`），「部署者没有对话模型」这种情形现在不存在；钥匙照文字回合用 `own_keys.for_turn`，每次调用拿一次、写完放掉。「只能用自带密钥」那种拒绝要等票 09 的光顾限额（设成 0）。
- 点单那次调用里，她的每一句都先扣到下一句她的台词来了再推（可能就是没标 `order` 时的最后一句）；标了 `order` 的那句起全部扣到调用写完，再连同备忘推。所以第一句会晚一句出来。
- 离开或被新光顾顶掉以后，正在写的那次调用在收到下一块时停下，不再推任何事件（不推 `failed`）；它写的东西不进状态，也不写记录。
- 上错时口味和种类都和目标一样、只是不是那一款的，归「完全不对」，提示词写「不是你点的那款，完全不对」，模型同时看得到上的那杯的口味和种类。
- 「今天做完的工作」的「今天」照 `schedule` 的算法按制作人所在的时区（`HerSchedule.local`），光顾本身按北京日期；两者跨零点时可能差一天，没有改。
- 「抽空了放开」写了，但现在的清单走不到：启动时已保证每位角色能用的多于 3 条，日程当来意的记的是工作名，不占清单的号，所以没有测试。
- 共用块里的世界设定按进门那天的北京日期取（文字回合是制作人当地日期），这样同一天所有用户都一样，缓存得上。
- `today_lines` 的 `talking` 传的是 `"apart"`：它现在各种说话方式都一样。

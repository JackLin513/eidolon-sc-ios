# 05: 走通一次光顾：进门、点单、上酒、告别

**What to build:** 从进门到告别走通一整次光顾，用接口就能玩，测试里用假模型走。这一张的点单只出「直说饮品名」一种说法，其余说法是票 06；醉是票 07，奖励是票 08，限额和运行记录是票 09，出错和作废是票 10。

后端新开一个**酒吧模块**，对外只有几个动作：读、进门、上一杯、离开（再试一次是票 10）。接口层只做 HTTP 和 SSE。

- **状态**：每位用户同时最多一次光顾，放在内存里，有一个随机的 `visit_id`。新开一次光顾时，旧的那次作废。
- **进门时抽**：
  - 角色：这位用户今天（北京日期）还没有玩完的光顾时，是今天的角色，用用户 id 加日期做确定性散列，从 29 位里取一位；玩完过以后随机，各位同等可能，冷却中的她也照样来。
  - 来意：今天给她排的、已经做完的那项工作一半概率当来意；其余从清单里抽，避开最近 3 次玩完的光顾用过的，抽空了就放开。
  - 话题：同样去重。
  - 杯数：1 杯 20%、2 杯 60%、3 杯 20%。
- **每一单在写点单的那次调用之前抽**：目标饮品照三个桶抽（爱喝的 45%、合口味的 35%、心血来潮 20%），剔掉讨厌的口味、这次已经点过的；第一单还剔掉上次玩完的光顾点过的；桶抽空了就落到下一个桶。说法先固定为直说名字。
- **判定**：服务器重新匹配，调坏的回 422；能上的判成上对或上错，直说名字没有「上得最好」这一档。上错时错在哪先只分「口味对了种类不对 / 种类对了口味不对」「讨厌的口味」「完全不对」。
- **提示词**：照规格「提示词」四块。共用系统块和最后一条 assistant 消息各打一处缓存标记；不给工具，不检索，不调判断模型。思考强度跟文字回合那一项。
- **输出解析**：照规格「输出格式和解析」。`<her emotion>`、`<ja>`、`<zh>`、`<producer>`，点单句标 `order="true"`；边收边解析，每收完一句推一句。
- **接口**：`POST /api/bar/visits`、`POST /api/bar/visits/{visit_id}/serves`、`DELETE /api/bar/visits/{visit_id}`，SSE 推 `visit`、`line`、`memo`、`waiting`、`done`。上一杯先推一句服务器从写死的句子里挑的「请慢用」。最后一杯以 `done` 收尾，这一张里 `rewarded` 一律是 `null`。
- **玩完**：告别写完的那一刻，在写事务里写一行光顾记录。下一次光顾的提示词里带「她记得上次」：来过几次（第一次 / 来过几次 / 常客）、上次多久以前（很久没来）、上次每单的饮品和档位、醉没醉（先恒为没醉）。

见规格「一次光顾的状态」「选角色、来意、话题、杯数」「点单怎么抽」「判定」「提示词」「输出格式和解析」「接口」「玩完、光顾记录和奖励」（奖励除外），以及 Testing Decisions 接缝一的对应几条。

**Blocked by:** 01、02、03、04（只要文件在、校验能过，不必等用户校对完）

**Status:** ready-for-agent

- [ ] 酒吧模块和四个动作中的三个；进门、上一杯、离开三个接口只给登录并同意了条款的用户。酒吧关着时进门 409（`bar_closed`），已经在进行的光顾照常走完。部署者没有对话模型、用户也没带自带 LLM 时，进门被拒的回答和文字回合一样。
- [ ] 进门推 `visit`（`visit_id`、`character_id`），然后是几句 `line`、点单句、`memo`、`waiting`。上一杯先推「请慢用」，再推反应、闲聊、下一单。最后一杯推反应、短闲聊、告别和 `done`。调用次数是杯数加 1。
- [ ] 选角色：同一用户同一天反复进门都是同一位，中途离开再进也是；换一天换人；玩完以后再进是随机的；冷却中的她照样能来；跨零点按进门那天算。
- [ ] 来意和话题：最近 3 次用过的不再出现，抽空了放开；今天做完的工作一半概率当来意，提示词里有它的名字和说明；日程关着时没有；`not_for` 的不给はづき。来意的基调进提示词。
- [ ] 目标饮品：讨厌的口味永远抽不到；同一次光顾不重复；第一单避开上次点过的；桶抽空了往下落。
- [ ] 判定：直说名字只认目标这一款，上对和上错都对；调坏的 422，状态不变；不是等上酒的时候 409；瓶装能上。
- [ ] 提示词：共用块里有人设、她的生日那句、世界设定、IF 的设定和护栏、酒吧的写法和输出格式。光顾块里有档案、来意、话题、杯数、好感度档位那几句（关着时不写）、`today_lines`、她在酒吧的记录、她的口味。这次要写什么的块里有点单卡（不含算对的范围）、这一杯的判定和错在哪、告别时每一杯的档位。两处缓存标记位置对。不给工具。用 `llm.prompts` 断言。
- [ ] 解析：缺 `<zh>` 的拿日语那句当字幕；缺 `<ja>` 的那句丢掉；情绪不在七种里的当 calm；标签外的文字丢掉。没有标 `order` 的，取她的最后一句当点单句。这一张里，一句完整的都没有时先当作这次调用失败、结束这次光顾，重试是票 10。
- [ ] 光顾记录表（用户数据，登记进 `USER_DATA`）：每次玩完写一行，字段照规格；台词不存。删账号一起删，删一段对话不碰，数据包导出里没有、导入也不动它。
- [ ] 她记得上次：第二次光顾的提示词里有来过几次、上次多久以前和每单的饮品、档位。常客（玩完 5 次及以上）和很久没来（上次超过 14 天）用常量。中途离开的光顾不算。对话的提示词里没有任何酒吧的东西（先例 `test_dynamic_context.py`）。
- [ ] 离开后、被新开的光顾顶掉后，旧的 `visit_id` 回 410（`visit_gone`）。不是这位用户的 `visit_id` 也回 410。
- [ ] 测试走接缝一：`make_client`、`FakeClock`、`FakeRandom`、`FakeLLM` 照脚本吐标签，读 SSE 照 `test_text_turn.py`，库里的东西用 sqlite 直接查。
- [ ] 把 GLOSSARY「光顾」「来意」「话题」「点单」和实现对一遍，要补就调 `domain-modeling`。pyright、ruff 通过；提交前跑 affected-tests。
- [ ] 收尾：Comments 里写下 SSE 事件的字段、上酒正文的形状、410 / 409 / 422 的回答、光顾记录表的列，给票 06–10 和第二份规格用；推一次让 CI 跑，跑 `code-review`。

# 02: 拍板：她真实的周期怎么生成

Type: grilling
Status: resolved
Blocked by: 01

## Question

每个「用户 × 角色」各自一套周期，不存库、用种子加日期现算（地图 Notes 已定）。要定：

- 参数从哪个范围里抽：周期长度、经期天数、经前几天；分布用均匀还是偏向常见值。
- 每个周期的抖动多大、怎么做到「现算」也稳定（同一天无论什么时候算，结果都一样；已经过去的周期不能因为后来算而改变）。
- 未成年的角色要不要更不规律（看票 01 的青春期结论），还是一视同仁、只在页面上讲。
- 种子怎么派生：用户 id 加角色 id，配 `EIDOLON_SECRET_KEY` 走 HKDF（先例 `accounts._ban_list_key`）；没设密钥的部署怎么办；换登录方式、导入数据包后是不是同一个她。
- 起点：功能上线那天每个人的她落在周期哪一天；部署者或用户关掉再打开，周期是接着走（一直在走、只是不表现）还是重来。
- 「今天是她周期第几天、在哪个阶段」这件事对外只给后端用，前端拿不到。

## Answer

2026-10-25 grilling 定下（另见 [ADR-0029](../../../docs/adr/0029-her-cycle-is-derived-not-stored.md)）：

- **基准周期**：每位「用户 × 角色」抽一次，权重表 25–34 天依次为 3/6/12/20/20/14/10/7/5/3（%）。
- **经期天数**：基准 4–7 天，权重 20/40/28/12；每个周期在基准上 −1/0/+1（25/50/25），限制在 3–8 天。
- **每周期抖动**：周期长度 = 基准 + 抖动。成年 −3…+3，权重 5/10/20/30/20/10/5；未满 18 岁 −5…+5，权重 3/5/7/10/15/20/15/10/7/5/3。结果限制在 21–40 天。前后周期互不相关，不回补。
- **经前**：每位她在 3–5 天里均匀抽一次，固定不变。后端给出「经期第几天」「经前还剩几天」，强弱怎么用归票 03、04。
- **未满 18 岁**：`characters.toml` 每位角色加整数字段 `age`（照 facts 核对），按 `age < 18` 判断。
- **现算**：固定纪元日（如 2026-01-01，按制作人档案时区的日历日）；第 0 个周期的开头 = 纪元 − 偏移，偏移在 [0, 基准) 均匀抽，所以上线那天每位她落在随机一天；第 k 个周期的长度和经期天数只由（种子, k）的哈希决定，逐个累加到今天。纪元、权重表、哈希方式都冻结，改了所有她会整体跳变，代码里注明。
- **种子**：有 `EIDOLON_SECRET_KEY` 时 HKDF 派生（info `b"eidolon cycles"`，照 `accounts._ban_list_key`）出钥匙，对 user_id + character_id 做 HMAC-SHA256；没设密钥时直接 SHA-256，功能照常开。
- **同一个她**：关联、换登录方式时 user_id 不变，还是她；删账号重注册、数据包导入别的账号或部署、改密钥，都重抽，记录照带，不迁移。
- **开关**：周期从纪元起一直在走，开关只管表不表现；关掉再开她在本来的位置，不重来。
- **可见性**：阶段只给后端（上下文、判断、挂断、对话事件）用，任何接口、后台、看板、数据包都不出现。开发模式下（同开发登录）留一个强制某位角色处于某阶段某天的口子，生产不认；测试注入时钟和种子。

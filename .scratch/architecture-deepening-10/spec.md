# 架构加深（第十轮）：「此刻」由 HerNow 一处给出

Status: ready-for-agent

术语以 `GLOSSARY.md` 为准，本轮在 GLOSSARY 新加了「此刻 (Now)」一条。设计词汇（module、interface、seam、adapter、depth、locality）取自 `codebase-design` skill。这是 2026-10-27 架构审查的候选 1（报告里还有一个「做完的规则写了三遍」，已并进本轮），设计经 grilling 定下。只改后端。

## Problem Statement

她每次开口前都会被告知「此刻」：现在几点、今天是谁的生日、是不是节假日、往年今天她站过的演出、她这周的日程、她的周期到了哪、她对制作人的态度。现在有三个地方各拼一遍：

- **文字回合和通话**：engine 的回复流程先读她的日程，再读好感度、制作人档案和上次联系，最后拼成「此刻」一节。
- **搭话**：engine 的搭话流程同样再拼一遍，场合换成「不在说话」。
- **光顾**：酒吧进门时又拼一遍。它读日程只是为了找「今天做完的那项」当来意，然后读好感度，把好感度几行和「今天」几行放进「这次光顾」一节。

拼法一样的部分，三处都各写了一份：

- **改「今天」就要改遍所有调用方**。「今天」那几行收的是世界设定的零碎字段（她站过的演出、她的组合伙伴），不是世界设定本身；还收了一个没用到的「怎么在说话」参数。#198 只给它加了「组合伙伴」，就同时改了 engine、酒吧、今天、世界设定四处和三份测试。
- **先后顺序只写在注释里**。读日程的时候会顺带把做完的工作计入好感度，所以必须先读日程、再读好感度。这条规则只在 engine 的一条注释里写着，酒吧碰巧也照这个顺序写，但没有任何说明。
- **各场合带哪几样，没有地方写**。光顾时她不被告知时间、制作人的生日和周期，这是有意的（酒吧的故事只发生在夜班），可是代码里看不出来。以后再加一样「她知道的事」，很容易只加进对话那一边，或者误加进光顾。
- **「工作做完了没有」写了三遍**：计入好感度时、告诉她日程时、酒吧找来意时，各有一份。酒吧还要伸进她日程的内部去找今天的那项。
- **测试只能走完整的路**。要测「此刻」里某一行写了什么，得整套起后端，在文字回合、通话、搭话三条路上各走一遍；光顾「不带哪几样」没有任何测试守着。

## Solution

新 module `HerNow` 回答「这一刻她知道什么」，对打字、通话、搭话、光顾四种场合都适用：

- 由它保证先把做完的工作计入，再读好感度。
- 由它向世界设定要她站过的演出和组合伙伴。
- 每种场合带哪几样，写在它自己的一张表里。
- 「工作做完了没有」只在日程里判断一处，酒吧向它要「今天做完的那项」。

engine 和酒吧只负责把它给的几行排进提示词。

她被告知的内容、几行的顺序和措辞都不变，只有一处可能不同：「此刻」里的周期按排提示词那一刻算，而判断仍按判断前那一刻算，两者只在恰好跨过零点的那几秒里可能差一天。

## User Stories

1. 作为制作人，我想打字时她知道现在几点、今天是不是我的生日、我们上次往来是什么时候，和现在一样。
2. 作为制作人，我想通话时她被告知的「此刻」和打字时一样，只是知道我们在通话。
3. 作为制作人，我想她来搭话时知道我们没在说话、上次往来是什么时候，和现在一样。
4. 作为制作人，我想她生日那天（按东京的日期），不论我在哪个时区，她都知道今天是她的生日。
5. 作为制作人，我想别的角色过生日时她知道是谁，只主动提组合伙伴的，别人的我提起时她能接上。
6. 作为制作人，我想日本的节假日那天她知道是哪个节日，我提起再说。
7. 作为制作人，我想往年今天她站过某场演出时，她知道那是过去的事，不会说成今天的事。
8. 作为制作人，我想打字、通话、搭话时她都知道我给她排的这周和下周的工作，哪项做完了、哪项正在做。
9. 作为制作人，我想她做完的工作照常计入好感度，并且在她这一回合的态度里已经体现出来。
10. 作为制作人，我想打字、通话、搭话时她的周期照常影响她的状态。
11. 作为制作人，我想好感度的档位照常决定她对我的态度；文字回合里判断之后的警告和结束对话照常进入「此刻」。
12. 作为制作人，我想在酒吧里她知道今天是谁的生日、是不是节假日、往年今天的演出，和对话里一样。
13. 作为制作人，我想在酒吧里她对我的态度照常按好感度档位。
14. 作为制作人，我想在酒吧里她不被告知现在几点，因为酒吧的故事都发生在夜班。
15. 作为制作人，我想在酒吧里她不知道今天是我的生日。
16. 作为制作人，我想在酒吧里她不受周期影响。
17. 作为制作人，我想在酒吧里她不被告知这周排了哪些工作；只有今天做完的那项会成为她来店里的缘由，和现在一样。
18. 作为制作人，我想她在酒吧里因为做完工作而来的那次光顾，也会让那项工作照常计入好感度。
19. 作为制作人，我想好感度或日程关着时，「此刻」里就没有对应的几行，和现在一样。
20. 作为制作人，我想周期关着时（部署者没开，或我自己关了），「此刻」里没有周期的几行，和现在一样。
21. 作为部署者，我想没有世界设定的部署里，「今天」照常只说生日和节假日。
22. 作为开发者，我想以后再加一样「她知道的事」时，只改 HerNow 一处，并在场合表里决定哪些场合带它。
23. 作为开发者，我想「先计入做完的工作、再读好感度」由 HerNow 的 interface 保证，调用方不用记得这条规则。
24. 作为开发者，我想「工作做完了没有」只在日程里判断一处。
25. 作为开发者，我想直接对 HerNow 测「此刻」每一行的内容，不用在三条路上各起一遍回合。
26. 作为开发者，我想有一条测试守住「光顾不带时间、制作人生日、日程和周期」。
27. 作为开发者，我想「今天」那几行直接收世界设定，世界设定再加一样东西时，不用改调用方。

## Implementation Decisions

### HerNow 的范围

- HerNow 只管每次都可能不同的「此刻」那几行。开头共用的部分（人设、她的生日、世界设定）不归它管：这部分要配合服务商缓存（ADR-0020），engine 和酒吧在它后面接的内容也不一样。
- engine 和酒吧各写了一份开头共用部分，抽成一个小函数两边共用，不进 HerNow。
- 「此刻」放在提示词哪里（ADR-0020 规定的「每回合变化的放在历史后面」、光顾放在「这次光顾」一节里），仍由 engine 和酒吧自己决定。

### interface 分两步

- 为什么分两步：engine 读好感度时，是和对话记录、制作人档案、上次联系等放在同一次读库里一起读的；而计入做完的工作必须排在这次读库之前。所以 HerNow 不能一步给出全部内容。
- **第一步「读」**：给它用户、角色和这台设备的时区（搭话时没有，传空）。调用方读好感度之前必须先调它，这条先后写进它的 interface。它做这几件事：
  - 计入做完的工作，读出她这周和下周的日程。日程关着时没有日程。
  - 读出她的周期，带回给 engine：判断和对话事件也要用到周期。周期关着时，周期哪天都不在任何阶段。
  - 带回今天做完的那项工作（没有就是空），给酒吧定来意。
  - 光顾时把好感度档位也一起读出来，因为酒吧没有别的读库要做。好感度关着时没有档位。
- **第二步「这几行」**：调用方给出场合（打字、通话、搭话、光顾）、排提示词的那一刻、制作人的时区、制作人档案、上次联系和好感度几行，它按场合表给出「此刻」的几行，顺序和措辞都和现在一样。
- 文字回合和通话里的好感度几行，要等判断打完分才知道要不要警告、结束，所以仍由 engine 算好传进来。几行放在哪里由 HerNow 决定。搭话和光顾没有判断，由调用方按档位传进来，做法和现在一样。
- 周期按第二步收到的那一刻现算。engine 判断用的周期仍是它在判断前自己算的那一份，两者只在恰好跨过零点的那几秒里可能差一天。决定接受这点差别，不为对齐它多开一个参数。

### 场合表

| | 时间、制作人生日、上次联系 | 今天（生日、节假日、往年演出） | 这周和下周的日程 | 周期 | 好感度几行 |
|---|---|---|---|---|---|
| 打字 | 带 | 带 | 带 | 带 | 带 |
| 通话 | 带 | 带 | 带 | 带 | 带 |
| 搭话 | 带 | 带 | 带 | 带 | 带 |
| 光顾 | 不带 | 带 | 不带（只用来定来意） | 不带 | 带 |

- 光顾不带时间和制作人生日，是因为酒吧的故事只发生在夜班。不受周期影响、不告诉她这周的日程，是 2026-10-27 和用户确认过的，GLOSSARY「此刻」一条也写了。
- 这张表写在 HerNow 里，场合逐一列出；以后新加一样「她知道的事」，要为每种场合写明带不带。

### 周边的改动

- 「今天」那几行改成直接收世界设定（没有世界设定的部署就是空），由它自己取她站过的演出和组合伙伴。没用到的「怎么在说话」参数去掉。
- 「这项工作做完了没有」只在日程里判断一处。计入好感度、告诉她日程、找今天做完的那项，都调用它。酒吧里那份自己找「今天做完的那项」的代码删掉，改向 HerNow 要。
- engine 里给文字回合、通话、搭话拼「此刻」的那个方法，以及它包着读日程、读周期的两个小方法，都由 HerNow 取代。周期 engine 还要拿来做判断和对话事件，从第一步带回的结果里取。
- 组装处把 HerNow 建好交给 engine 和酒吧；它要用到日程、周期、好感度、世界设定、全体角色和时钟。

### 不变的

- 她被告知的每一行，措辞、顺序和带不带的条件都不变。只有上面说的跨零点那一点差别。
- ADR-0020（每回合变化的放在历史后面）、ADR-0028（一个写线程，数据库不在事件循环上）、ADR-0029（周期现算，不存）、ADR-0030（体贴题只在她那几天问）照旧。
- 计入做完的工作照旧发生在读日程时：先读，有要计入的再开写。

## Testing Decisions

- 好的测试只看外部行为：她被告知了哪几行、某种场合里有没有某一行，不看 HerNow 内部怎么组织。
- **主 seam 是 HerNow 的 interface**。检查「此刻」各行内容的测试，改成直接对 HerNow 测：
  - 今天的各种情况：她的生日从东京零点开始；别人的生日、组合伙伴的生日；节假日；往年今天的演出、没上场的和还没到的演出。
  - 日程的各种情况：按今天、明天等说出是哪天；正在进行的那项单独说；早上 6 点前没有正在进行的；只有正在进行的那一项；没排时什么都不说；上周的不说；关着时什么都不说；西边时区的周日就已经知道下周。
  - 周期那几行、好感度几行放在哪里。
  - 场合表：光顾那一列不带时间、制作人生日、日程和周期。
  - 先后顺序：做完的工作在第一步里已经计入，紧接着读到的好感度档位已经体现这次计入。
  - 「今天做完的那项」：有几项时取最晚的那项，没有时为空。
- HerNow 从组装好的后端里取。日程照常经接口保存，时钟用可以拨的假时钟，数据库是真的。可以参照搭话测试里从后端取出 module 的做法，以及现有日历、日程测试准备数据的写法。
- **每种场合只留一条走 HTTP 的测试**，确认这几行真的进了提示词：打字、通话、搭话各一条；光顾一条，确认「这次光顾」一节里有今天和好感度那几行，没有时间、日程和周期。可以参照现有日历测试里从假 LLM 收到的提示词中取出「此刻」一节的做法。
- 判断和对话事件用的周期不在本轮测试范围内，现有的周期和体贴测试照旧要通过。
- 节假日接口那几条测试不动。
- 测试搬过去以后，原来那些在三条路上各走一遍、检查某一行内容的 HTTP 测试删掉，不在两层都测同一件事。

## Out of Scope

- 把「计入做完的工作」挪进读好感度的路径。这样玩法页显示的档位也会是计入之后的，但读好感度就可能要写库，还牵涉 ADR-0028，另开一题。
- 开头共用部分（人设、她的生日、世界设定）收进 HerNow。
- 光顾里她知道这周日程、时间、制作人生日或周期。
- 判断用的周期和「此刻」用的周期对齐到同一刻。
- 架构审查的其他候选：酒吧前端的场景和会话（下一轮，architecture-deepening-11）、每种受限额的使用在一处登记、酒吧的屏幕选择和音频、前端日程、玩法开关样板。

# 01: 数据访问层，先接上公告、赞赏、价格、备份、实时配置

**What to build:** 把 spec 里的数据访问层加进来，并接进后端的启动和关停：
- 一条写连接，放在专用线程上，写入按顺序排队；
- 4 条 `query_only` 读连接，从默认线程池里借用；
- 在事件循环上拿连接的检查：测试里抛异常，线上记 error 并照常执行；
- 写任务排队或执行、读池等待，超过 200 ms 记 warning。

先让最小的五个模块走通整条路径：`Announcements`、`Sponsor`、`Prices`、`Backups` 的运行记录、`LiveConfig`。管理者在后台发公告、上传收款码、改价格、点「立即备份」、保存或还原配置时，读写都经过这一层，事件循环上不碰库。行为和现在一样。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 层对外只有 async 的 `read`、`write`、`close`（`checkpoint` 留给 03）。`write` 在写线程上用一个事务跑事务体：正常返回就提交，抛异常就回滚，异常交回给 `await` 的一方。
- [ ] `read` 在一条读连接上开一个读事务跑事务体，同一次 `read` 读到的是同一份快照；长写入进行中照样能读。
- [ ] 任务一旦交给写线程就一定执行完：`await` 的一方被取消，写入照样提交。
- [ ] `close` 先跑完已交的写任务，之后再交的被拒；`Backend.aclose` 经由它关掉层的连接。
- [ ] 在事件循环所在的线程上拿连接：测试模式抛异常，线上模式记 error、照常执行。`conftest` 默认是测试模式。
- [ ] 写任务排队等待或执行超过 200 ms、读池等待超过 200 ms，各记一条 warning，带任务名（事务体的限定名）和当时队列的长度。
- [ ] 各模块要用的自定义 SQL 函数可以由层注册到每一条连接上（这张票先提供这个能力，`spread_bucket` 由 05 用上）。
- [ ] 建表和迁移作为写任务，按现在的构造顺序执行。
- [ ] 五个模块不再自己开连接、不再持有 `threading.Lock`。碰库的公开方法改成 async；调用它们的 handler、监听器（`LiveConfig` 改了配置后的 `gifts.notice` 等）改成 await，碰库的同步 handler 改成 `async def`。
- [ ] 层自己的规则（顺序、回滚、取消、关停、检查、日志）有层自己的测试；五个模块现有的测试改成 async 后照样通过。
- [ ] 受影响的测试通过，CI 绿。

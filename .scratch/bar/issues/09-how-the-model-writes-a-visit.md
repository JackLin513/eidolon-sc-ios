# 09: 拍板：模型怎么写一次光顾

Type: grilling
Status: resolved
Blocked by: 06, 07

## Question

服务器定好角色、饮品、事件和判定，模型只负责把戏写出来。要定：

- **调用的切分**：一次光顾分几次调用（开场加点单、每杯的反应、告别），每次带什么：她的人设、IF 的设定和护栏、这次抽到的事件、服务器定好的点单和判定、前面已经说过的台词。要不要提示词缓存（`prompt-caching` 那套）。
- **输出格式**：一段里有她的日语台词加中文字幕、制作人的中文台词、偶尔的选项、每句的情绪（七种之一）。情绪是让写台词的模型一起标，还是像通话那样交给判断模型；立绘照情绪动。
- **状态存在哪**：光顾进行到哪一步、抽到的东西、已经说过的台词存在服务器（存库还是内存），刷新页面能不能接着玩；光顾的记录要保留多久，用来给「最近来过就避开同样的理由」用。
- **出错**：模型超时或者输出不合格式时怎么办（重试、用写死的兜底台词、这次光顾作废但不算当天第一次）。
- **自带 LLM**：用用户自己的模型时照常写；思考强度跟文字回合那一项走还是另设。
- **限额的数**：每小时光顾次数默认几次。

### 票 07 交接

- **没有选项**：照原版撤掉了，输出格式里不用留选项，制作人的台词全由模型写。
- **上酒后的反应**那一段，服务器交给模型：这一杯上的是哪款（名字、口味、种类、大小、含不含酒），判成哪一档（上得最好、上对、上错）；上错时再交错在哪：口味对了种类不对或反过来、她讨厌的口味、说了不要酒却有酒、完全不对、不是上次那款。讨厌的口味和不要酒却有酒要写成明显的不喜欢。

## Answer

2026-10-26 拍板。服务器定好一切，模型一次调用写到玩家下一次动手为止。

**调用怎么切**：玩家只在上酒时动手，所以按上酒切。第 1 次调用写进门加第一单的点单；之后每上一杯调用一次，写这杯的反应、闲聊、下一单的点单；最后一杯（或醉了）写反应、短闲聊、告别。一次光顾「杯数 + 1」次调用，也就是 2 到 4 次，比定图时估的 4 到 6 次少。流式输出，反应那几句先出来。「请慢用」照票 06 由服务器挑，不在模型的输出里。

**每单什么时候抽**：每次要写点单的那次调用之前，服务器抽这一单的目标饮品和说法，存进这次光顾的状态里再调模型；重试时用存下的，不重抽。开始时只抽来意、话题、点几杯（票 06）。

**输出格式**：沿用文字回合的标签格式（`reply_format.py`），加上说话人和情绪，一句一组：

```
<her emotion="happy"><ja>…</ja><zh>…</zh></her>
<producer>…</producer>
```

- 不用 JSON 模式：模型那一层没有，ADR-0019 也不维护按服务商的兼容表。
- 解析器照 `ReplyParser`，边收边解析，每收完一句推给前端。
- 情绪由写台词的模型一起标，七种之一（calm、happy、shy、surprised、sad、angry、thinking），不再调判断模型；不在七种里就当 calm。立绘照标签换动作，制作人的台词不标。
- 她的台词缺 `<zh>` 就拿日语那句当字幕；一句完整的都解析不出来算格式不合格，走下面的出错规则。

**提示词怎么排**：酒吧有自己的一套，不和文字回合共用前缀，也不给工具（没有回忆工具）。
1. 共用的系统块：她的人设和世界设定、IF 的设定和护栏、酒吧的写法和输出格式。同一天她对所有用户都一样，打缓存标记。
2. 这次光顾的块：来意（来自日程时带那项工作的 name 和 note）、话题、点几杯、好感度档位（关着时按正常值）、`today_lines`、她在酒吧的记录（来过几次、上次多久以前、上次每单点了什么和档位、醉没醉）。整次光顾不变。
3. 前面已经写好的台词，以助手消息接在后面，末尾打缓存标记。
4. 最后是这次要写什么：点单卡（票 05）、这杯的判定和错在哪（票 07）、「从这一段起醉了」、要不要告别以及每杯的档位。

缓存照 ADR-0020：Anthropic 显式打标记，其余靠服务商的自动前缀缓存。

**状态放内存，不接着玩**：
- 每位用户同时只有一次光顾在进行，放在后端内存里，跟通话一样。
- 刷新、关掉页面、断网、30 分钟没动作、后端重启，这次光顾就没了。再打开从开店画面重新开始，不算玩完，什么都不给，也不进「她记得上次」的记录。另一个标签页开了新的光顾，旧的作废。
- 当天第一次的角色按日期定，重新开始还是她；之后的光顾重新开始会随机换人，并再占一次每小时的限额。
- 跨零点：一次光顾按进门那天算。那天还没有玩完过光顾，这次就算那天的第一次，告别时照发奖励。

**光顾的记录**：玩完那一刻往库里写一行结果：用户、角色、进门和告别的时间、来意、话题、每单的饮品和档位、醉没醉。台词不存。结果一直留着，「来过几次」直接数行数，去重取最近 3 行，「老样子」取最近 1 行。删账号时一起删；数据包带不带交给票 10。

**出错**（超时、模型报错、格式不合格）：
- 每次调用自动重试 1 次（现在文字回合不重试，这里单独加）。
- 还不行，就在页面上显示一句短的出错提示和「再试一次」，状态停在这次调用之前；离开了就没了（见上）。
- 名字检查照票 05：不过就重写一次，再不过换成写死的模板句。
- 告别那次调用（反应加告别在同一次）重试后仍写不出来：用写死的句子顶上。反应按档位分（上得最好、上对、上错各几句），告别按醉没醉分两组，**这也算玩完**，奖励照发。
- 写死的句子由实现时起草，只写中文和日语各一份，跟模板句放在一起。

**自带 LLM 和思考强度**：用户自带 LLM 时照常用他们的模型写。思考强度跟「对话模型 · 文字回合」那一项走（自带的用他们自己设的文字回合强度），不新开一项。

**限额**：新加一种「光顾」，每小时默认 5 次，环境变量和后台限额卡能改，`user_limits` 能给单个用户另设。进门那次调用开始时计一次，重试不再计；第一次调用彻底失败、一句没写出来时退回，自己中途离开的照常计（和词汇表「限额」一致）。自带 LLM 的不计数，只记下来。超了就在开店画面上说什么时候能再来。

**词汇表**：「光顾」补上中途离开就没了、不能接着，以及跨零点按进门那天算。

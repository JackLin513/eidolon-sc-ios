# 04: 拍板：每位角色的口味和爱喝的饮品

Type: grilling
Status: resolved
Blocked by: 01

## Question

29 位角色每人在酒吧里喜欢什么。要定：

- 每位角色怎么描述口味：偏好的口味、种类，以及最爱的一款或几款饮品。从她的人设和角色资料推（比如甜食爱好者偏甜、Girly），写成仓库里的一张表，跟 `characters/gifts.toml` 里的「喜欢的礼物」并列维护。
- 每次光顾她点什么怎么抽：点最爱的、点合口味的、点「通用」的（谁都可能点的几款），还是「突然想换口味」，各占多少比例；同一位角色连着几天不要总点同一款。
- 有没有她讨厌的饮品，上了会怎样（只影响反应，好感度照「上错升得少、不降」）。
- 维护：谁来写这张表（后台模型起草加人工校对，像人设那样？还是直接手写）。

## Answer

2026-10-26 拍板。这张票只管「她这一单想要哪一款」：每一单抽出一款目标饮品；她怎么说出来、哪些算上对交给票 05。

**每位角色记五样**，写在 `characters.toml` 里，和 `liked_gifts` 放在一起，启动时校验，写错了后端起不来：

| 字段 | 内容 | 必填 |
|---|---|---|
| `bar_flavors` | 喜欢的口味，5 种里 1–2 种 | 是 |
| `bar_kind` | 喜欢的种类，5 种里 0–1 种 | 否 |
| `bar_favorites` | 爱喝的饮品，1–3 款，饮品 id | 是 |
| `bar_disliked_flavor` | 讨厌的口味，0–1 种；推不出来就不填，不硬凑 | 否 |
| `bar_tolerance` | 酒量：弱、中、强 | 是 |

- **饮品目录**：新开 `characters/drinks.toml`，和 `gifts.toml` 并排放；id 用好认的写法（`sugar-rush`），不用原版缩写。
- **依据**：出处文件 `facts/<id>.sources.md` 新开一节「酒吧口味」，每一条写理由。剧情里有饮食偏好的引剧情（「爱吃甜食，见某剧情」所以记甜），找不到的从人设推，标「人设推断」并写清理由；种类、讨厌的口味也一样可以从人设推。酒量按年龄和性格推：刚到能喝酒年纪的偏弱，成年组、性格豪爽的偏强。爱喝的饮品从口味和种类对过去。不像 `liked_gifts` 那样不收推断：饮品是虚构的，只能推。
- **谁来写**：不做起草命令。实现时由一张票让 agent 读人设、角色资料和出处文件起草整张表和各节「酒吧口味」，用户校对。爱喝的饮品尽量分散，不让一半人都爱同一款；不要求每款都有人爱。
- **每单怎么抽**：爱喝的 45%，合口味的（口味或种类对上、不算爱喝的那几款）35%，心血来潮（任一款）20%。不另设「通用款」。比例写成常量，上线后再调；某个桶抽空了就落到下一个桶。
- **讨厌的口味**：永远不出现在她的点单里，心血来潮也抽不到。上了这种口味的饮品只是反应换成不喜欢，好感度照「上错升得少、不降」，加多少交给票 07。
- **酒量**：表里只记三档；每档的门槛、醉了的戏交给票 06、07；酒量弱的会不会更常要无酒精版交给票 05。
- **别老点同一款**：同一次光顾里不重复；每次光顾的第一单避开她上一次光顾点过的饮品，按这位用户、这位角色记。她一开口点单就记下，不等玩完。这份记录归酒吧自己，不进对话；她记不记得上次点了什么是票 06 的事，这里只用来去重。
- **可见性**：界面上哪里都不显示她的口味，跟喜欢的礼物一样。写戏的模型拿得到她的口味，她可以在台词里自己说出来（「甜的我最喜欢了」）。
- 瓶装和隐藏款进不进抽奖池跟着票 05：留下就照样进池子、也能当爱喝的。

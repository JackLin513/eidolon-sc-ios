# 主动消息

Label: wayfinder:map

来源：GitHub issue #121「主动消息能力」。

## Destination

一份可以直接拆票实现的规格 `.scratch/proactive-messages/spec.md`：角色没被问到时，也会自己在当前对话里给制作人发来几句话。规格里定好主动消息是什么、什么时候生成、用谁的模型、谁付钱、发不发和发几条、她说什么、用户怎么看到和关掉、部署者在后台怎么设，以及实现顺序。

## Notes

- 术语以 `GLOSSARY.md` 为准。她没被问到就先说的话正式叫**搭话**，不是回合（见「拍板：主动消息是什么」）；票名里的「主动消息」是定名前起的，正文和规格里说搭话。说角色、对话、回合、用户、制作人，不说小偶像、聊天、账号。
- 每张拍板类（grilling）票都要调用 grilling 和 domain-modeling 两个 skill。原型票调用 prototype，原型放在 `prototype/<name>` 分支。前端相关的先读 `frontend/AGENTS.md` 的「shadcn 纪律」，视觉以 `DESIGN.md` 为准；给用户看的文案要少。
- 这张地图只做计划，交付物是规格，不是实现。地图、票和规格放在计划分支 `feat/proactive-messages`；调研结论放在 `research/<name>` 分支，只推送、不开 PR。
- 定图时已定（2026-10-19 的 grilling）：
  - 目的地是一份规格。
  - 不推送到手机：没有 Web Push、邮件，也不做 PWA。主动消息只在用户打开网站时看到；用户正开着网站时，到点的主动消息也要能出现，不必等他刷新。
  - 只做文字；主动来电、主动发照片都不在范围内。
  - 用户能自己关掉主动消息，部署者也要能控制（具体控制什么，在发不发、发几条和后台设置里定）。
  - 后台有总开关，新部署和升级后都默认关。
- 定图时查到的现状：
  - 没有任何服务器推送通道：文字回合的回复是一次性的流，对话记录只在打开对话时拉一次，对话列表只在外壳挂载、回合结束、新建对话、送礼等时候刷新，没有定时刷新。唯一的轮询是照片（每 2 秒）和服务状态（每 5 分钟、切回标签页时）。
  - 对话没有未读或已读的概念；唯一的未读是公告，存在设备上。
  - 文字回合不合成语音，语音只在通话中实时合成、不落盘。
  - 代码处处假设一个回合从用户那一段开始：`add_turn` 总是成对写入，回合号和回合数按用户那一段计，历史截取要从用户开头，对话事件插在哪里看用户那一段的时间，列表最后一句和统计也都这样算。
  - 自带密钥只在浏览器里，服务器离线时手里没有用户的 key；部署者的对话模型和后台模型在回合外可以用 `LiveConfig.lease()` 取到，回合外的服务调用照样记进看板的花费。
  - 后端单进程、单 worker；常驻的后台循环照 `service_status.keep_probing` 的写法在启动时起。抽奖次数是「谁先读到就补发」的惰性做法。
  - 离线时只知道制作人档案里填的时区：设备时区只随每个请求带来、不落库，档案没填时默认 `Asia/Shanghai`。
  - 「最后活跃」只有 `sessions.last_active_at`，最多每小时续一次；运行记录的时间也能看出最后一次回合或通话。
  - 后台设定存在 `config_overrides` 表，加一项照 `live_config.py` 里好感度那一项（`_Affinity`）的写法。

## Decisions so far

<!-- 每张关闭的票一行：名字链接加一句要点 -->

- [调研：陪伴类产品的主动消息怎么做](issues/01-companion-apps-research.md)：只有 Nomi 公开了节奏（按角色选间隔档、不回就间隔翻倍、本地 22:00–08:00 不发）；没人公开每天上限，也没人写明「关系越好越常发」；最招骂的是空洞重复和深夜打扰，最被夸的是提到真实聊过的事；各家都是离开期间生成，没有等用户回来才补的。
- [拍板：主动消息是什么](issues/02-what-is-a-proactive-message.md)：叫「搭话」，是和回合、对话事件并列的第三种记录（ADR-0026）；只在没结束、不在冷却、已有回合的当前对话里；不判断、不改好感度、不计限额、不算统计，留运行记录；跟着后面的回合截取；新增服务器上的「没看过的搭话」。
- [拍板：什么时候生成、用谁的模型、谁付钱](issues/03-when-generated-and-who-pays.md)：到点由服务器生成、记真实时间，不回来补；一律用部署者的对话模型（文字回合的设定和思考强度），自带 LLM 的用户也一样；限额为零不搭话；不回来的用户花费要有上限；失败不重试，停机错过的不补；花费归进对话模型那一行。
- [拍板：发不发、发几条](issues/04-how-often.md)：搭过话就等用户回（回合或接通的通话）才再搭；冷淡、疏远不搭，亲密 3–6 小时、亲近 8–16 小时、信任 20–36 小时后来；22:00–08:00 不来、挪到早上；7 天没往来不搭；每人每天默认最多 3 次；用户一个总开关，后台只有总开关和每天上限。
- [拍板：她说什么](issues/05-what-she-says.md)：她自己挑由头，先接着聊过的事和记忆里的近况，不发空问候；告诉她现在几点、上次往来隔了多久和之后的对话事件；记忆按最后一个回合查、加两周内的近况，只用她自己的；不检索、不调工具、不编剧情；一两段、不重复；亲近、亲密可以有一点撒娇，照人设、不要挟，回复也加「上次往来」一行；不给跳过的出口。
- [原型：用户怎么看到](issues/06-how-users-see-it.md)：列表行时间旁她颜色的小圆点（不出数字，最多一条没看过）、导航「对话」上一个小点，不弹提示；开着网站时每 60 秒拉一次列表；对话里和回复一样但另起一组，不加分隔线；开关在设置里单独一类「搭话」。原型在 `prototype/proactive-messages`。
- [拍板：看板和对外文档](issues/07-dashboard-and-public-docs.md)：看板「用量」里加一小节「搭话」（搭了几次、失败几次、被回占比）；隐私政策补四句、改日期，条款不动；README 加一行、配置指南加一节；中文文案先过 humanizer-zh、要短；上线公告到时候起草给用户确认。

## Not yet specified

- **实现顺序和分块**：后端的生成和存储、前端的显示和轮询、后台设置怎么分票、谁先谁后。交接时用 `/to-spec` 写规格时定，不另开票。普通文字回合也要改：每回合说明里加「上次往来是什么时候」一行（见「拍板：她说什么」第 7 条）。

## Out of scope

- 推送到手机（Web Push、邮件、PWA）：定图时决定只在网站里看到。
- 主动来电：通话必须用户在线，费用也高得多（定图时决定）。
- 主动发照片：每张都要花生图的钱，线上生图也还没开，以后另开一轮（定图时决定）。

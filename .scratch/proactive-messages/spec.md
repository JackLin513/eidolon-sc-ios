# 搭话：她没被问到时，也会自己在当前对话里先说几句

Status: ready-for-agent

术语以 `GLOSSARY.md` 为准（新增「搭话」「没看过的搭话」，「当前对话」「对话事件」「运行记录」随之改过）。说搭话、回合、对话事件、对话、角色、用户、制作人，不说主动消息、消息、聊天、推送。搭话为什么不是回合见 ADR-0026，每回合变的内容为什么放在历史后面见 ADR-0020。所有决定的来历在 `.scratch/proactive-messages/map.md` 和它的 7 张票里；调研全文在 `research/proactive-messages-companions` 分支，原型在 `prototype/proactive-messages` 分支（616a815）。给用户看的文案要少。

## Problem Statement

- 现在只有制作人开口，她才会说话。关掉网站一天再回来，对话停在昨天他说的最后一句，看不出她在这段时间里想过他。和一个真人偶像来往时，最打动人的往往是她先找你：「上次说的那八小节练得怎么样了？」
- 陪伴类产品的主动消息最招骂的是空洞、重复、深夜打扰，像在拉留存；最被夸的是提到真实聊过的事。随手加一个「定时发早安」会得到前者。
- 部署者要替用户出这笔钱：用户不在线时服务器手里没有他的自带密钥，只能用部署者的模型。一个再也不回来的用户不能让部署者一直花钱，部署者也要能整个关掉。

## Solution

1. **搭话是什么**：她自己在当前对话里先说的一段话，长度和回复一样，可以分几段，每段日语加字幕。它和回合、对话事件并列，是第三种记录。只在没结束、她不在冷却中、已经有回合的当前对话里搭话，不为搭话开新对话。
2. **什么时候来**：服务器到点生成，用户不在线也照样来，时间就是真实生成的时间。她搭过话就等他回（一个回合或一通接通的电话），回了才可能再搭；越亲近来得越早：从最后一次往来起，亲密 3–6 小时、亲近 8–16 小时、信任 20–36 小时；冷淡、疏远不搭。按制作人的时区夜里 22:00–08:00 不来，挪到早上 08:00–10:00。最后一次往来超过 7 天就不再搭。每位用户所有角色加起来每天最多 3 次（部署者可调），多的顺延到第二天早上。
3. **她说什么**：她自己挑由头，先接着最近聊过的事和记忆里他的近况，不发空问候。她知道现在几点、上次往来隔了多久、这之后发生的对话事件（他送了礼还没被回应，就拿礼物当由头道谢）。一两段，别和前几次搭话一个开头。亲近时偶尔轻轻带一句「好久不来」，亲密时可以明着撒娇，都照人设，不要挟、不哭诉。不发照片、不说要打电话。
4. **谁出钱**：一律用部署者的对话模型（文字回合那组设定和思考强度），自带 LLM 的用户也一样。不计入限额，不经过判断，不改变好感度，单独一次搭话不变成记忆。花费自动归进看板上「扮演角色的 LLM · 部署者的 key」那一行。
5. **用户怎么看到**：不推送到手机，只在打开网站时看到。对话列表上她那一行排到上面、最后一句就是这次搭话，时间旁一个她颜色的小圆点；导航的「对话」上一个小点。开着网站时每 60 秒拉一次列表，正开着她的对话页时搭话直接出现在底部。对话里和她的回复一个样子，只是另起一组。打开那个对话（任何设备上）就算看过。
6. **他回了以后**：他的回复照常是一个回合，照常判断、照常记成记忆；她知道自己什么时候搭过什么话，判断模型和记忆提炼也看得到这次搭话。普通文字回合里她也知道上次往来是什么时候，亲近、亲密时也照同样的分寸撒娇。
7. **怎么关**：用户在设置里单独一类「搭话」，一个开关，存在服务器上，默认开。部署者在后台有总开关（新部署和升级后都默认关）和「每位用户每天最多几次搭话」。部署者没开时，用户的设置里没有这一类，一切和现在一样。
8. **看板和对外文档**：看板「用量」里加一小节「搭话」：搭了几次、失败几次、被回的占比。隐私政策补几句，README 加一行，配置指南加一节。

## User Stories

1. 作为制作人，我想在我没说话时，她自己在对话里先给我发来几句，这样我觉得她在想我。
2. 作为制作人，我想她搭话时接着我们最近聊过的事（「那场试镜后来怎么样了」），这样我知道她记得。
3. 作为制作人，我想她提到记忆里我的近况（我说过这周要考试），这样搭话有内容。
4. 作为制作人，我不想收到只有一句「早安」「想你了」、后面什么也没有的搭话，这样它不像群发的推送。
5. 作为制作人，我不想她每次搭话都用一样的开头、一样的由头，这样不腻。
6. 作为制作人，我想她的搭话和平常的回复一样有日语和字幕、可以分几段，这样读起来还是她。
7. 作为制作人，我想她的搭话是一两段，不写成四段的长故事，这样我好接话。
8. 作为制作人，我想她搭话时知道现在几点（按我档案里的时区），早上、傍晚说的话不一样，这样像真人。
9. 作为制作人，我想她知道我们上次往来隔了多久（几小时、两天），这样她不会把昨天的事说成刚才。
10. 作为送了礼物、之后没再说话的制作人，我想她搭话时为这份礼物道谢，这样礼物有回音；之后我回她时，她不再重复谢一遍。
11. 作为她刚挂过我电话的制作人，我想她之后照样可能搭话，而且知道自己挂过电话，这样关系是连着的。
12. 作为生日当天的制作人，我想她碰巧那天搭话时祝我生日快乐（当天只说一次），这样不会被重复祝福。
13. 作为制作人，我不想她搭话时编出原作里没有的具体剧情或别的偶像做了什么，只说泛泛的日常（练习、拍摄、在事务所）和世界设定里有日期的 live、新歌，这样不出戏。
14. 作为制作人，我不想她搭话时提起我对别的偶像说过的事，这样不像她们在背后议论我。
15. 作为和她很亲近的制作人，我想她偶尔轻轻带一句「好久不来了」，这样我感到被惦记。
16. 作为和她亲密的制作人，我想她可以明着撒娇、说想我、等我，这样「她居然会说这种话」是惊喜。
17. 作为制作人，我想她撒娇时照她的人设来（嘴硬的角色不写成直白撒娇），这样她不 OOC。
18. 作为制作人，我不想她说自己难过到哭、要我保证以后常来、或者说「那我不理你了」，这样搭话不变成要挟。
19. 作为制作人，我不想她每次都抱怨我不来：上一次搭话或回复已经抱怨过，这次就不说，这样不烦。
20. 作为信任这一档的制作人，我想她搭话时不抱怨、不撒娇，这样语气和档位对得上。
21. 作为制作人，我不想她搭话时发照片、或者说要给我发照片、打电话，这样不会落空。
22. 作为和她亲密的制作人，我想她在几小时没往来后就来找我；作为只是信任的制作人，大概隔一天多才来，这样关系越近来得越早。
23. 作为好感度在冷淡、疏远的制作人，我想她不来搭话，这样她的态度是真的。
24. 作为她在冷却中的制作人，我想她不来搭话。
25. 作为上次聊完时在疏远、之后好感度自然恢复到信任的制作人，我想她按信任的节奏来，仍从我们最后一次往来算起。
26. 作为没开好感度的部署上的制作人，我想她按信任的节奏来搭话，这样功能照样能用。
27. 作为制作人，我想她搭过话以后，等我回了才再搭，这样我不回她时不会一条接一条地来。
28. 作为看了她的搭话却没回的制作人，我不想她接着再来，这样我不觉得被催。
29. 作为接了她电话、或者给她打了电话的制作人，我想这也算回了她，这样之后她照样会搭话。
30. 作为只送了礼物、没说话的制作人，我知道这不算回了她。
31. 作为制作人，我不想夜里 22:00 到早上 08:00（按我档案的时区）收到搭话，到点落在夜里的挪到早上 08:00–10:00，这样不被半夜打扰、也不会比平常晚很多。
32. 作为档案里没填时区的制作人，我接受按 `Asia/Shanghai` 算夜里。
33. 作为一周没来的制作人，我不想回来时发现很多位角色每天都来过；最后一次往来超过 7 天的对话里她不再搭话。
34. 作为和很多位角色都聊过的制作人，我不想一天被搭话太多次：所有角色加起来每天最多 3 次（部署者可调），多的顺延到第二天早上，先到点的先来。
35. 作为制作人，我想搭话从不出现在已结束的对话里，也不会为搭话凭空开一个新对话。
36. 作为刚开了新对话、还没说过话的制作人，我不想她在这个空对话里先开口。
37. 作为正在和她打字或通话的制作人，我不想她这时冒出一段搭话；她刚想好要说的话碰上我开口，就作废，不出现。
38. 作为制作人，我想在对话列表里看到她那一行排到上面、最后一句是她的搭话，这样一眼知道她来过。
39. 作为制作人，我想在有没看过的搭话的那一行，时间旁看到一个她颜色的小圆点，不出数字，这样不吵。
40. 作为在设置页、礼物页的制作人，我想导航里的「对话」上有一个小点，这样我不会错过。
41. 作为开着网站的制作人，我想到点的搭话不用刷新就出现（最多晚一分钟），这样像真的收到了。
42. 作为正开着她对话页的制作人，我想她的搭话直接出现在底部、跟着滚到底（往上翻着时不抢），而且这一条直接算看过，这样不多余地标出来。
43. 作为制作人，我想打开她的对话后小圆点和导航上的点就消失，在另一台设备上也算看过，这样手机和电脑不用各看一遍。
44. 作为制作人，我不想开着网站时弹出提示条或响一声，这样搭话安静地来。
45. 作为制作人，我想对话里的搭话和她平常的回复一个样子（头像、名字、日语加字幕、时间），没有标签和分隔线。
46. 作为制作人，我想搭话和她几小时前的那句回复分开成两组，各带自己的时间，这样不像她一口气说的。
47. 作为制作人，我想在历史对话里照原样看到当时的搭话。
48. 作为回了她搭话的制作人，我想她的回复接着她刚才说的话，知道自己什么时候说过什么，这样不前后矛盾。
49. 作为回了她搭话的制作人，我想我的这一句照常判断好感度、照常记成记忆，判断和记忆都明白我是在回她的搭话，这样「好啊」这种短回复不被误读。
50. 作为制作人，我想普通文字回合里她也知道上次往来是什么时候，这样隔了两天再聊，她不会像刚刚还在说话。
51. 作为制作人，我想搭话不占我的限额，不算进对话标题的回合数和统计，这样她先来找我不花我什么。
52. 作为自带 LLM 的制作人，我知道她的搭话由部署者的对话模型生成、部署者出钱，可能和她回复用的模型不一样。
53. 作为不想被搭话的制作人，我想在设置里单独一类「搭话」里一拨开关就关掉所有角色的搭话，马上生效，在别的设备上也生效。
54. 作为制作人，我想在设置的一级列表上看到「搭话」那一行写着「开」或「关」。
55. 作为部署者没开搭话的部署上的制作人，我不想在设置里看到「搭话」这一类。
56. 作为制作人，我想她搭的话跟着对话一起导出、导入、删除、进备份，这样「删了就没了」是真的；导入进来的搭话算看过。
57. 作为制作人，我想没有人（包括管理者）能看到她搭话的内容。
58. 作为制作人，我想隐私政策里写清楚：开着搭话时，我不在线，服务器也会用部署者的模型读这段对话和她的记忆生成她先说的话。
59. 作为部署者，我想后台有搭话的总开关，新部署和升级后都默认关，这样我决定要不要替用户出这笔钱。
60. 作为部署者，我想在后台设「每位用户每天最多几次搭话」（默认 3 次）。
61. 作为部署者，我想一个再也不回来的用户替我花的钱有一个和时间无关的上限：每段当前对话里他每回一次，她最多搭一次。
62. 作为部署者，我想被管理者设成限额为零、或被封禁的用户不被搭话，这样我不替他们花钱。
63. 作为部署者，我想部署、重启、宕机期间错过的搭话起来后不补发，这样每次部署不会一齐冒出来。
64. 作为部署者，我想生成失败时不重试、不告诉用户，往后推一个同档的间隔再来，这样失败不会刷掉我的额度。
65. 作为部署者，我想刚打开总开关时，几个月前的对话不会一齐冒出来。
66. 作为管理者，我想在看板「用量」里的「搭话」一节看到范围内搭了几次、失败几次、被回的占比，这样我知道它有没有用。
67. 作为管理者，我想搭话的花费自动算进「扮演角色的 LLM · 部署者的 key」那一行。
68. 作为管理者，我想每次搭话在运行记录里留一条（结果、用了哪些服务、用量、快慢），不含内容。
69. 作为部署者，我想在 README 和配置指南里看到搭话是什么、默认关、每天上限默认几次、花费由我出。

## Implementation Decisions

### 存储

- **新表「搭话」**，不放进 messages（messages 的 role 有 CHECK，代码处处把 messages 当成成对的回合）：所在对话、原文、日语、字幕、分段、记下的时间、看过没有、对应的那条运行记录。原文照回复一样存演出提示，显示时去掉。
- **新表「搭话日程」**，每段对话一行：这一轮的抽签属于哪一次往来（最后一次往来的时间）、区间里的位置（0–1 之间的随机数）、挪到早上时的位置（同上）、改定的到点（失败、停机、超出每天上限时写，平时为空）。往来变了就整行重抽。
- **用户的开关**存在服务器上，只记关了的用户，默认开。
- 三张新表都登记进用户数据，「搭话」和「搭话日程」跟着对话删（加进按对话删除的那一组）；开关跟着删号删。旧库启动时建表，照现有的 `IF NOT EXISTS` 写法。部署前照例手动备份数据库。

### 对话记录和对话列表

- **对话记录接口**多一种条目：`type: "reach_out"`，带 id、原文、日语、字幕、分段、时间。它和对话事件一样，按时间排在它之后第一个用户那一段前面；最后一个回合之后的排在末尾，和对话事件按时间交错。
- **列表的最后一句**（最新对话列表和某位角色的对话列表都一样）可以是搭话：形状和她的消息一样（`role: "character"`），多一个 `reach_out: true`。现在判断最后一句的逻辑以「最后一条消息」和「最后一个用户那一段」比较，要改成在消息、对话事件、搭话里取最新的。
- **最新对话列表每一行**多一个「有没有没看过的搭话」（布尔）。
- **打开对话即看过**：读某个对话的记录时，把里面的搭话都记成看过，再返回记录。任何对话（当前的、历史的）、任何设备都一样。
- 对话标题、统计、「来过」、好感度的累计都数用户那一段，搭话天然不进。起标题用的文字不带搭话。

### 节奏：到点的跑一遍

- **一个新模块**，对外只有「把现在到点的都跑一遍」一个方法。后端启动时起一个常驻循环，每分钟调一次，写法照服务状态的探测循环（启动时起、关闭时取消、异常只写日志）。随机数和时钟都用注入的（`randomness`、`clock`），测试能固定。
- **每遍看哪些对话**：每位用户每位角色的当前对话里，最后一次往来在 7 天之内的。
- **最后一次往来**：最后一个回合记下的时间，和最后一次接通的通话结束的时间，取晚的。送礼不算。通话进行中就是正在往来。
- **不搭的情形**（这一遍跳过，日程不动，下一遍再看）：后台总开关关着；用户关了开关；管理者给他的限额设成零；用户被封禁或已删；对话已结束；当前对话里还没有回合；最后一个回合（或接通的通话）之后已经搭过话；这段对话正在进行回合或通话；她在冷却中；档位是冷淡或疏远。
- **到点**：有改定的到点就用它；否则是最后一次往来加上「到点时的档位」的区间按抽到的位置取：亲密 3–6 小时、亲近 8–16 小时、信任 20–36 小时；没有好感度的部署（没配判断模型、或关了好感度和礼物）按信任。各档区间、夜里时段、7 天窗口、早上的 08:00–10:00 都是代码常量。
- **夜里**：按制作人档案的时区（没填用 `Asia/Shanghai`，不用设备时区），到点或现在落在 22:00–08:00 的，挪到下一个 08:00 加「挪到早上的位置 × 2 小时」。
- **7 天窗口**：到点（包括挪过、改定过的）晚于最后一次往来加 7 天的，这一轮作罢，不再搭。
- **每天上限**：一天按制作人的时区划，只数成功的搭话。这一遍里到点的按到点先后排；这位用户今天的次数已经用完的，改定到点为第二天 08:00–10:00 里随机的一个时刻（仍受 7 天窗口约束）。上限由部署者设，默认 3。
- **停机错过的**：到点早于这个进程启动时刻的，不生成，改定到点为现在加一个同档区间里的随机间隔（经过夜里规则，受 7 天窗口约束）。
- **生成失败**：不重试，留一条失败的运行记录，改定到点的办法和停机一样。失败的不算一次搭话，也不占每天上限。

### 生成一次搭话

- **模型**：从部署者的配置借出对话模型（文字回合那组设定和思考强度），用完归还；不经过自带密钥、限额和免限额密钥那一套。调用照常记成服务调用，所以用量和花费自动进看板。
- **请求的排法和文字回合一样**（ADR-0020）：共用固定部分、制作人资料、历史（同样的分段截取）、一条每回合变的系统消息、最后一条用户那一边的消息。最后一条是旁白：最后一个回合之后的对话事件，加一句固定的「（制作人这会儿没在和你说话。你想先给他发几句。）」。这样所有协议都收得下（以用户结尾，不出现连着两条她的话），和对话事件旁白放在用户那一边的现有写法一致。
- **每回合变的那条系统消息**：
  - 「此刻」那一节：现在几点（制作人的时区）、生日那句照现有规矩；打字还是通话那一行换成「你们这会儿没在说话」。
  - 上次往来是什么时候、隔了多久（和文字回合新加的同一行）。
  - 好感度只带档位语气那几行（含撒娇的分寸），不带心情、警告、告别。
  - 记忆那一节（见下）。
  - 搭话的规矩：自己挑由头，先接着最近聊过的事和记忆里他的近况，其次才是时间、生日；不许只发空问候；一两段；别和前几次搭话用一样的开头和由头；她那边只说泛泛的日常和世界设定里有日期的 live、新歌，不编具体剧情或别人做了什么；不发照片、不说要发照片或打电话；让他好接话，但不规定用问句结尾。不给「这会儿没什么好说」的出口。
- **记忆**：查询用最后一个回合（他说的和她回的字幕），门槛照旧，最多 3 条；再加最近两周记下、没被取代的近况，最多 5 条（代码常量），和查到的去重。两样都只取来源是她自己的记忆。不走判断模型（没有「要不要检索」这一问），不检索剧情和角色资料，不调工具。
- **解析**：照回复的格式解析成分段；写了照片标签的，标签丢掉不生成。解析不出内容算失败。
- **作废**：生成前，这段对话在进行回合或通话就不生成。写下时，在同一个事务里再查一遍：仍是当前对话、没结束、最后一次往来没变、之后没有搭话、没有正在进行的回合或通话；不满足就作废，不记下，运行记录的结果记「被拒绝」，不算失败、不算一次搭话。
- **「正在进行回合」**要新加：现在文字回合没有进行中的标记。引擎在一个文字回合开始读记录时登记这段对话、记下或失败时撤销；通话用现有的进行中通话。

### 回合里的搭话

- **历史里的写法**：搭话写成旁白，和对话事件一起放在它之后的那个用户那一段前面，按时间排：「（M月D日 HH:MM，你先给制作人发了：）」后面接她的话，写法和历史里她的回复一样。这样截取照旧按回合数切，搭话自然跟着它后面那个回合走；最后一个回合之后还没回的那次搭话，放进这一回合用户那句话前面的旁白里。历史里的角色顺序不变，所有协议都收得下；旁白写进之后不再变，不破坏前缀缓存。
- **礼物**：搭话算她回应过之前的礼物（和她的回复一样清掉「还没回应的礼物」），之后那个回合不再要她回应。
- **判断模型**看到的上文里，她最近说的那句是这次搭话（放在用户这句话前面，作为她的话）；**记忆提炼**的这一回合也带上前面那次搭话；**记忆查询**里「她上一句」用这次搭话的字幕。
- **「上次往来」一行**：每个文字回合的「此刻」那一节加一行「上次往来是 X（隔了多久）」，按这一回合之前最后一个回合或接通的通话算；没有就不写。通话里的回合不加。
- **撒娇的分寸**：亲近、亲密两档的语气后面各加几句（亲近偶尔轻轻带一句，亲密可以明着撒娇；照人设；上一次搭话或回复里抱怨过就不说；不哭诉、不要保证、不要挟）。信任不加。回复和搭话共用这几句，所以普通回合也变了。这几句在每回合变的那条系统消息里，不影响缓存。

### 运行记录和看板

- **运行记录**多一种「搭话」，和回合、通话并列：结果（成功、失败、被拒绝）、角色、用了哪些服务、用量、快慢；「用了自带密钥」总是否。另记「被回了没有」：这次搭话之后、下一次搭话之前，用户在这段对话里有了一个回合或接通了一次通话，就把这次搭话的那条运行记录标成被回了（靠「搭话」表里记的运行记录）。
- 现有按记录种类计数的地方（回合趋势、按角色、用户页的近期用量、限额结算）都不把搭话当成回合或通话。
- **看板**「用量」标签加一小节「搭话」：范围内成功几次、失败几次、被回的占比（被回的 ÷ 成功的）。总开关关着、范围内也没有搭话的记录时，这一节不出现（接口里为空）。不按角色拆，不进用户页，不单开标签。

### 后台设定

- 后台设定加一项「搭话」，写法照好感度那一项：两个字段，总开关（默认关，`.env` 里可以开）和每位用户每天最多几次（正整数，默认 3）。放在配置页「限额与玩法」标签，好感度后面。不试调。保存后循环下一遍就按新值来。

### 用户的开关和账号

- **账号接口**多一个字段：部署者没开总开关时为空，开了时是用户自己的开关（开或关）。前端靠它决定设置里有没有「搭话」这一类。
- **新接口**设用户的开关：拨了马上存；总开关关着时拒绝（409）。

### 前端

- **接口类型**：对话记录多一种搭话条目；最后一句可以带 `reach_out`；最新对话列表的行多「有没有没看过的搭话」；账号多搭话的开关。
- **对话里**：搭话转成和她的回复一样的条目，带一个「是搭话」的标记，key 和消息的分开。分组时，搭话总是另起一组：上一条留着自己的时间，搭话重新带头像和名字。历史对话用的是同一套，自动生效。
- **轮询**：外壳里那份对话列表，标签页在前台时每 60 秒拉一次，切回前台时马上拉一次，后台标签页不拉。现有的「只在可见时定时」的钩子切回来时不马上拉，要加一个选项（或另写），不改现在的用法。
- **正开着的对话**：列表拉回来、显示正开着的那段对话最后一句比页面上的新时，这段对话重读一遍记录（重读同时让服务器记成看过）。回合进行中或通话中推迟到空闲再读，不冲掉正在进行的那一轮；页面关掉后不再读。
- **列表上的圆点**：有没看过的搭话的那一行，时间前面一个她颜色（`her-mark`）的小圆点；列表栏不在她的颜色范围里，要在这一行上套她的颜色变量（统计页有先例）。读屏有一句说明。正开着的那段对话不显示。最后一句和名字不加深。
- **导航上的点**：只要有一行有没看过的搭话（正开着的那段对话除外），导航栏和 dock 的「对话」图标右上角一个 6px 前景色小点，和公告铃铛的点一个样子。
- **打开对话后**列表上这一行的点马上消失（本地先清掉，下一次拉列表时以服务器为准）。
- **设置**：新一类「搭话」放在「通话」和「外观」之间；一级列表的摘要写「开」或「关」；二级页一个开关「她们会主动搭话」，拨了马上存到服务器，存不上就拨回去并提示；没有说明小字。账号里搭话为空时这一类不出现，直接打开它的网址时回到设置页。
- 按 `frontend/AGENTS.md` 的 shadcn 纪律和 `DESIGN.md` 写。`DESIGN.md` 跟着改：「Conversation list」里留给未读数的胶囊改成这个圆点，提到未读数的几处（她的颜色只用在哪几处的规则、字号用途、布局、正圆）一起改；导航的点；设置页的类数和网址列表。圆点在选中行和悬停行的底色上要过对比度检查。

### 数据包、删除、备份

- 数据包导出每段对话的搭话（时间、原文、日语、字幕、分段），格式版本升一号；旧版本的数据包照常能导入。导入进来的搭话算看过。用户的开关和搭话日程不进数据包。格式说明文档跟着改。
- 删历史对话、删账号时搭话和日程一起删；备份是整个数据库，自动带上。

### 对外文档

- **隐私政策**只补句子、改「最后更新」的日期，不加版本号，用户不用重新同意：「语言模型服务」说开着搭话时、你不在线，服务器也会用部署者的对话模型读这段对话和她的记忆，生成她先说的话，填了自己的 LLM 也一样；「对话」说她搭的话存在对话里，随对话删除、进备份、随数据包导出；服务器上存的东西加上「搭话」开关和看过哪些搭话；「运行记录」说每次搭话也留一条，不含内容。使用条款不改。
- **README**（三种语言）在「和她说话」那组加一行，链到配置指南；**配置指南**加一节「搭话」：总开关默认关，每位用户每天上限默认 3 次，用部署者的对话模型、花费由部署者出（包括自带 LLM 的用户）。
- 中文先写，用 humanizer-zh 过一遍再删减，每处一两句；英文、日文照中文定稿翻。

## Testing Decisions

- 只测对外的行为：接口返回什么、对话记录里有什么、发给模型的请求里有什么、运行记录和看板上的数，不测日程表里存了什么、内部怎么排。
- **后端的接缝只新加一个**：搭话模块的「把现在到点的都跑一遍」。测试不起常驻循环，推进假时钟后直接调它，照 `test_service_status.py` 手动调探测的写法。其余都走现有的 HTTP 接口（`make_client` 加 `FakeLLM`、`FakeServiceClients`）。
- `Store` 写时间用的是真实时钟，不走注入的；「最后一次往来是什么时候」照 `test_conversation_events.py` 的先例直接改库里的时间。不为这次把 `Store` 改成可注入时钟。随机数用 `FakeRandom` 固定。
- **后端要测的**：
  - 节奏：各档到点前不来、到点后来；冷淡、疏远、冷却中不来，档位恢复后按新档来；没开好感度按信任；搭过话不回不再来，回合或接通的通话之后才再来，送礼不算；夜里挪到早上；7 天窗口；每天上限和顺延、先到点的先来；失败和停机往后推、不补；总开关、用户开关、限额为零、封禁、已结束、空对话、不是当前对话都不来。
  - 生成：请求里有此刻、上次往来、档位语气、只有她自己来源的记忆和两周内的近况、搭话的规矩、对话事件旁白，没有工具；用的是部署者的对话模型，自带 LLM 的用户也一样；照片标签被丢掉。
  - 作废：进行中的回合或通话时不生成；生成完时撞上用户开口就不记下。
  - 回合里：历史里的旁白和位置、截取后跟着后面的回合走、还没回的那次带在这一回合的旁白里；礼物不再要她回应；判断模型和记忆提炼看得到搭话；每个文字回合多了「上次往来」一行；亲近、亲密的撒娇几句在回复里也有。
  - 对话记录、列表最后一句、没看过的搭话（打开即看过、任何对话都算）、账号字段、用户开关接口、后台设定、看板一节、运行记录、数据包导出导入（导入算看过、旧版本照常导入）、删除。
  - 先例：`test_conversation_events.py`、`test_gift_responses.py`（事件和旁白）、`test_conversation_history.py`、`test_dynamic_context.py`（历史和每回合变的那条）、`test_affinity_prompt.py`（档位语气）、`test_memories.py`、`test_shared_memory.py`（记忆来源）、`test_conversation_summaries.py`、`test_past_conversations.py`（列表）、`test_affinity.py`、`test_gift_draws.py`（后台开关、跨天）、`test_activity_records.py`、`test_affinity_dashboard.py`（运行记录和可选的看板小节）、`test_cost_estimate.py`（花费归类）、`test_user_limits.py`（限额为零）、`test_data_package_conversations.py`、`test_delete_past_conversations.py`、`test_database.py`（新表登记）。
- **前端**，都用现有的接缝：
  - `liveConversation.test.ts`：列表显示正开着的对话有新搭话时重读；回合进行中、通话中推迟到空闲；关掉后不读。
  - `messageLines.test.ts`、`conversationLog.test.ts`：搭话另起一组、上一条留着时间。
  - `conversationList.test.ts`：最后一句是搭话时的预览和排序、哪一行有点、导航有没有点（正开着的除外）。
  - `settingsCategory.test.ts`：「搭话」类的位置和摘要，账号里为空时没有这一类。
  - 对比度测试里加上圆点在选中、悬停底色上的那一对。
- **验收**：60 秒轮询、切回前台马上拉、正开着对话页时搭话出现在底部，按 `docs/agents/local-acceptance.md` 在本地构建版上用 Playwright 看；能用接口造出的（直接调「跑一遍」造一次搭话）就自己验，只把要人看的留给用户。

## Out of Scope

- 推送到手机：Web Push、邮件、PWA。
- 主动来电、主动发照片。
- 按角色关搭话；部署者限定哪些角色搭话；后台调各档区间、夜里时段、7 天窗口。
- 用设备时区算夜里（只用档案时区）。
- 生日、节日单独触发搭话。
- 回来时补上「不在时她说的话」；停机错过的补发；失败重试。
- 她那边的日程数据、编具体剧情。
- 看板上按角色拆搭话、用户页里的搭话。
- 通话里的回合加「上次往来」一行。
- 上线公告：部署者在线上打开总开关时，起草全文给用户确认再发，不进票。

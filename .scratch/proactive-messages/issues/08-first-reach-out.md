# 08: 走通一次搭话

**What to build:** 部署者在后台打开「搭话」后，和她聊过、关系在信任以上的用户，隔一段时间没往来，会在当前对话里看到她先说的一段话。这段话和回复一样有日语和字幕，在对话页里另起一组；对话列表的最后一句换成这次搭话，她那一行排上去。这一张走通整条路：节奏只做最基本的，内容只给基本的提示词，其余由 09–15 补全。规格见 `../spec.md`，尤其是「存储」「对话记录和对话列表」「节奏：到点的跑一遍」「生成一次搭话」「运行记录和看板」「后台设定」几节，以及 Further Notes 实现顺序的第 1 条。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] **后台设定**：新增一项「搭话」，含总开关（默认关，`.env` 可开）和「每位用户每天最多几次」（正整数，默认 3）。写法照好感度那一项，放在配置页「限额与玩法」标签里、好感度后面，不试调。每天上限这一张只存不用，由 10 接上。
- [ ] **存储**：
  - 新表「搭话」：所在对话、原文、日语、字幕、分段、记下的时间、看过没有、对应的运行记录。
  - 新表「搭话日程」：这一轮属于哪次往来、区间里的位置、挪到早上的位置、改定的到点。
  - 两张表都登记进用户数据，跟着对话删。
  - 「看过没有」这一张一律写成没看过，由 12 接上；「挪到早上的位置」和「改定的到点」先不用，由 10 接上。
- [ ] **跑一遍**：新模块对外只有一个方法，「把现在到点的都跑一遍」。后端启动时起一个常驻循环，每分钟调一次，写法照服务状态的探测循环：启动时起、关闭时取消、异常只写日志。时钟和随机数都用注入的。
  - [ ] 只看每位用户、每位角色的当前对话，而且最后一次往来在 7 天内。最后一次往来取两者里晚的那个：最后一个回合记下的时间、最后一次接通的通话结束的时间。送礼不算往来。
  - [ ] 到点 = 最后一次往来 + 一段间隔。间隔按到点时的档位、在区间里按抽到的位置取：亲密 3–6 小时，亲近 8–16 小时，信任 20–36 小时；没有好感度的部署按信任算。区间写成代码常量。往来变了就重抽。
  - [ ] 这些情形不搭话：总开关关着；对话已结束；当前对话还没有回合；最后一次往来之后已经搭过话；冷却中；档位是冷淡或疏远。不搭时这一遍跳过，下一遍再看。
- [ ] **生成**：
  - 借部署者的对话模型，用文字回合那组设定和思考强度，用完归还；不经过自带密钥和限额。
  - 请求照文字回合的排法（ADR-0020），依次是：共用固定部分、制作人资料、历史（同样的分段截取）、每回合变的那条系统消息、最后一条用户那一边的旁白。
    - 每回合变的那条系统消息里：「此刻」一节中「打字还是通话」那一行换成「你们这会儿没在说话」；好感度只带档位语气那几行；再加上搭话的规矩，照规格「生成一次搭话」那一条写全。
    - 最后那条旁白：最后一个回合之后的对话事件，再加一句「（制作人这会儿没在和你说话。你想先给他发几句。）」。
  - 不调工具、不检索、不判断。
- [ ] 照回复的格式解析成分段，解析不出内容就算失败。失败不重试，也不记下；往后推由 10 接上。
- [ ] **对话记录接口**多一种 `type: "reach_out"` 的条目，带 id、原文（去掉演出提示）、日语、字幕、分段、时间。排法和对话事件一样：排在它之后第一个用户那一段前面；在最后一个回合之后的，排在末尾。
- [ ] **列表的最后一句**可以是搭话，最新对话列表和某位角色的对话列表都一样。形状和她的消息一样，多一个 `reach_out: true`。最后一句在消息、对话事件、搭话三者里取最新的。
- [ ] **运行记录**多一种「搭话」：
  - 记结果（成功或失败）、角色、服务调用、用量、快慢；「用了自带密钥」总是否。
  - 花费自动归进「扮演角色的 LLM · 部署者的 key」那一行。
  - 现有按种类计数的地方不把它当成回合或通话：回合趋势、按角色、用户页的近期用量、限额结算。
- [ ] 对话标题、统计、「来过」都不受搭话影响；起标题用的文字不带搭话。
- [ ] **前端**：
  - 对话记录里的搭话转成和她的回复一样的条目，带一个「是搭话」的标记，key 和消息分开。
  - 分组时搭话总是另起一组：上一条留着自己的时间，搭话重新带头像和名字。历史对话里也一样。
  - 列表最后一句是搭话时，照她的话显示，她那一行跟着排上去。
  - 后台配置页上出现「搭话」这一项。
- [ ] **测试**：
  - 后端：推进假时钟后直接调「跑一遍」（照 `test_service_status.py` 的写法）；最后一次往来的时间照 `test_conversation_events.py` 直接改库里的；随机数用 `FakeRandom`。要覆盖：
    - 各档到点前不来、到点后来；上面列的每种不搭的情形；没开好感度时按信任。
    - 请求里有什么，而且没有工具；用的是部署者的模型，用户自带了 LLM 也一样。
    - 对话记录和列表的最后一句；对话标题、统计不变。
    - 运行记录和花费；后台设定的保存和校验；新表登记（`test_database.py`）。
  - 前端：`conversationLog.test.ts`；`messageLines.test.ts`（另起一组）；`conversationList.test.ts`（最后一句是搭话）。
- [ ] **验收**：按 `docs/agents/local-acceptance.md`，在本地构建版上打开后台的搭话，改库里的时间，调一次「跑一遍」造出一次搭话。用 Playwright 看对话页里另起一组、列表的最后一句，宽屏和手机各看一次。
- [ ] 表结构有改动，部署前手动备份数据库。
- [ ] `sh scripts/affected-tests.sh <基点>` 通过，推送后 CI 全绿。

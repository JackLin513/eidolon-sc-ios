# 12: 没看过的搭话和开着网站时冒出来

**What to build:** 用户开着网站时，到点的搭话不用刷新就会出现，最多晚一分钟：
- 对话列表里，她那一行就地更新、排上去，时间前面多一个她颜色的小圆点。
- 导航里「对话」上出现一个小点，在设置页、礼物页也看得到。
- 正开着她的对话页时，搭话直接出现在底部，算看过，不做标记。
- 在任何设备上打开那个对话，点就消失。

规格见 `../spec.md`：「对话记录和对话列表」里讲看过的两条；「前端」里的轮询、正开着的对话、列表上的圆点、导航上的点。依据是「原型：用户怎么看到」（`06-how-users-see-it.md`）。

**Blocked by:** 08

**Status:** ready-for-agent

- [ ] **后端**：读某个对话的记录时，先把里面的搭话都记成看过，再返回；当前对话和历史对话都算。最新对话列表的每一行多一个字段：有没有没看过的搭话。
- [ ] **轮询**：外壳里的对话列表在标签页处于前台时每 60 秒拉一次，切回前台时马上拉一次，后台标签页不拉。现有的「只在可见时定时」钩子加一个选项（或者另写一个），不改它现在的用法。
- [ ] **正开着的对话**：
  - 拉回来的列表里，正开着的那段对话的最后一句比页面上的新，就重读这段对话的记录；重读就算看过。
  - 回合进行中或通话中，推迟到空闲再读，不冲掉正在进行的那一轮；页面关掉后不再读。
  - 用户往上翻着时，不抢滚动位置。
- [ ] **列表上的圆点**：
  - 有没看过的搭话的那一行，时间前面一个 `her-mark` 小圆点，在这一行上套她的颜色变量。
  - 读屏有一句说明。
  - 正开着的那段对话不显示圆点。最后一句和名字不加深。
  - 打开对话后，本地先把这一行的点清掉。
- [ ] **导航上的点**：除正开着的那段对话外，只要有一行有没看过的搭话，导航栏和 dock 的「对话」图标右上角就显示一个 6px 的前景色小点，样子和公告铃铛上的点一样；读屏名字跟着变。
- [ ] 不弹提示条，不出声音。
- [ ] **`DESIGN.md`**：
  - 「Conversation list」里给未读数留的胶囊改成这个圆点。
  - 提到未读数的几处一起改：她的颜色只用在哪几处的规则、字号用途、布局、正圆。
  - 补上导航上的点。
- [ ] 按 `frontend/AGENTS.md` 的 shadcn 纪律写。原型分支 `prototype/proactive-messages` 里的 `RowMark`（变体 C）和 `NavDot` 可以拿来对照。
- [ ] **测试**：
  - 后端：打开对话后，列表里那一行不再标；打开历史对话也算看过；别的对话不受影响。先例：`test_conversation_summaries.py`。
  - 前端：
    - `liveConversation.test.ts`：有新搭话时重读、进行中时推迟、页面关掉后不读。
    - `conversationList.test.ts`：哪一行有点、导航上有没有点、正开着的对话除外。
    - 对比度测试加上两组：圆点在选中行底色上、在悬停行底色上。
- [ ] **验收**：在本地构建版上用 Playwright 走一遍，宽屏和手机各一次：
  - 开着列表页造一次搭话，一分钟内这一行更新、出圆点，导航出点。
  - 切到别的标签页再切回来，马上拉一次。
  - 开着她的对话页时，搭话出现在底部，列表和导航都不标。
  - 打开对话后，点消失。
- [ ] `sh scripts/affected-tests.sh <基点>` 通过，推送后 CI 全绿。

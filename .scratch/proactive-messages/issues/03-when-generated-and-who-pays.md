# 03: 拍板：什么时候生成、用谁的模型、谁付钱

Type: grilling
Status: resolved
Blocked by: 02

## Question

主动消息什么时候真正生成出来，用哪个模型，钱算谁的：

- 到点生成：服务器的后台循环到了时间就生成、写进对话。这时用户多半不在线，服务器手里没有他的自带密钥，只能用部署者的模型（对话模型还是后台模型）。
- 回来时补上：用户下次打开网站时，才补上他不在的这段时间里她「发来」的话。那时浏览器在线，自带 LLM 的用户可以用自己的 key；不再回来的用户不花一分钱。但要定补上的显示成什么时间（真实生成的时间，还是假装是之前发的），以及补上要不要让用户等。
- 两者混合：用户在线时到点生成、离线时回来补上。
- 很久没来的用户：到点生成的话，多久不来就不再给他生成。
- 计不计入用户的限额、走不走免限额密钥那一套；花费在看板上怎么归。

定图时已定：不推送到手机，主动消息只在用户打开网站时看到；用户正开着网站时到点的主动消息也要能出现。

## Comments

- 「拍板：主动消息是什么」已定：搭话不计入限额，所以这里只剩用谁的模型、花费怎么在看板上归；每次搭话留一条新的运行记录。用户正在回合或通话中时不搭话，生成完时撞上用户开口就作废。

## Answer

到点由服务器生成，一律用部署者的对话模型，钱由部署者出（2026-10-19 的 grilling）。词汇表「搭话」补了一句「始终由部署者承担，用户不能自带」；改起来不难，又有判断模型的先例，不写 ADR。

1. **到点生成**：服务器的后台循环到了时点就生成、写进对话，时间就是真实生成的时间，用户不在线也照样生成。没有「回来时补上」，也不混用两条路。
2. **用部署者的对话模型**（扮演角色的 LLM），用文字回合那一组设定和思考强度，不用后台模型：搭话是她在说话，扮演要和回复一样。
3. **自带 LLM 的用户也一样**：服务器离线时手里没有他的 key，所以他的搭话也由部署者的对话模型生成、部署者出钱，和判断模型一样；搭话和回复可能出自不同的模型，接受。搭话的运行记录里「用了自带密钥」总是否。搭话不计入限额，所以也不看免限额密钥。
4. **限额为零的用户不搭话**：管理者把限额设成零，就是部署者不替他花钱；其他限额（包括不限）照常。被封禁的用户也不搭话。
5. **再也不回来的用户，花费要有一个和时间无关的上限**。怎么做交给「拍板：发不发、发几条」；倾向于对话里还有没看过的搭话时不再搭话，这样每段当前对话最多替他花一次。
6. **生成失败**：不重试、不告诉用户，留一条失败的运行记录，这个时点就过去了，下一次照节奏来。失败的不算一次搭话。
7. **看板**：搭话调用的 LLM 和别的调用一样归到「扮演角色的 LLM · 部署者的 key」，自动算进用量和估算花费，不另开一种服务。看板要不要单独一节看搭话，留给「后台设置和看板」。
8. **停机错过的时点不补**：部署、重启或宕机期间到点的搭话，起来后不补发，只按节奏往后算下一次，免得每次部署都一齐冒出来。

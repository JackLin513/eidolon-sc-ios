# 13: 用户的「搭话」开关

**What to build:** 不想被搭话的用户，在设置里单独的「搭话」一类拨一下开关，所有角色就都不再搭话。马上生效，在别的设备上也生效。一级列表的那一行写着「开」或「关」。部署者没开搭话时，设置里没有这一类。规格见 `../spec.md`「用户的开关和账号」和「前端」里设置那一条，依据是 `06-how-users-see-it.md` 第 6 条。

**Blocked by:** 08

**Status:** ready-for-agent

- [ ] **存储**：开关存在服务器上，默认开，只记关了的用户。登记进用户数据，删号时一起删；不进数据包。
- [ ] **账号接口**多一个字段：总开关关着时为空；开着时是用户自己的开关。
- [ ] **新接口**用来设开关，拨了马上存。总开关关着时拒绝，返回 409。
- [ ] **跑一遍**：用户关了开关就不搭话，这一遍跳过，日程不动。重新打开后照节奏来，仍受 7 天窗口约束。
- [ ] **设置**：
  - 新增一类「搭话」，放在「通话」和「外观」之间，摘要写「开」或「关」。
  - 二级页只有一个开关「她们会主动搭话」，没有说明小字。拨了马上存，存不上就拨回去并提示。写法照「外观」那一页。
  - 账号里这个字段为空时，这一类不出现；直接打开它的网址，回到设置页。
- [ ] **`DESIGN.md`**：更新设置页的类数和网址列表。
- [ ] **测试**：
  - 后端：账号字段的三种情形；接口的存和取；总开关关着时返回 409；关了以后不来、打开以后会来（接缝同 08）。
  - 前端：`settingsCategory.test.ts`，覆盖这一类的位置、摘要，以及字段为空时没有这一类。
- [ ] **验收**：在本地构建版上用 Playwright 看一级列表和二级页的开关，拨了以后刷新，状态还在；后台关掉总开关后，这一类不见了。
- [ ] `sh scripts/affected-tests.sh <基点>` 通过，推送后 CI 全绿。

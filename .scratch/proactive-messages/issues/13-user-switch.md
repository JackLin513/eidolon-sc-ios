# 13: 用户的「搭话」开关

**What to build:** 不想被搭话的用户，在设置里单独的「搭话」一类拨一下开关，所有角色就都不再搭话。马上生效，在别的设备上也生效。一级列表的那一行写着「开」或「关」。部署者没开搭话时，设置里没有这一类。规格见 `../spec.md`「用户的开关和账号」和「前端」里设置那一条，依据是 `06-how-users-see-it.md` 第 6 条。

**Blocked by:** 08

**Status:** done

- [x] **存储**：开关存在服务器上，默认开，只记关了的用户。登记进用户数据，删号时一起删；不进数据包。
- [x] **账号接口**多一个字段：总开关关着时为空；开着时是用户自己的开关。
- [x] **新接口**用来设开关，拨了马上存。总开关关着时拒绝，返回 409。
- [x] **跑一遍**：用户关了开关就不搭话，这一遍跳过，日程不动。重新打开后照节奏来，仍受 7 天窗口约束。

  - 新增一类「搭话」，放在「通话」和「外观」之间，摘要写「开」或「关」。

  - 账号里这个字段为空时，这一类不出现；直接打开它的网址，回到设置页。

### 实现说明（票 13）

- 后端：开关在搭话模块（`ReachOuts`）。表 `reach_outs_off` 只记关了的用户，登记进 `USER_DATA`；数据包不读它。`switch_of(user_id)` 在总开关关着时返回 None，开着时返回用户自己的开关，账号接口的 `reach_outs` 字段就是它。`switch(user_id, on)` 在总开关关着时抛 `ReachOutsOff`，`PUT /api/account/reach-outs`（`{"on": bool}`，`StrictBool`）把它转成 409。`_due` 在限额检查之后、抽日程之前跳过关了开关的用户，所以日程不动、也不抽签。测试在 `tests/test_reach_out_switch.py`；删号连开关一起删，并进了 `test_reach_outs.py` 的删号测试。
- 前端：账号类型多了 `reach_outs`，导航外壳持有它。`accountChanged` 现在也接受按当前值改的函数，存失败拨回去时不会冲掉别处的更新。`settingsGroups(reachOuts)` 在为空时去掉「搭话」这一类。二级页 `ReachOutsSettings` 一拨就先改外壳里的账号，存的时候开关禁用，失败时拨回去并出 `FailureNotice`。账号读到、字段为空时，页面自己 `router.replace("/settings")`，因为 proxy 在服务端不知道账号。
- 验收（本地构建版，用库的副本，副本里原有用户的开关全部关掉，避免循环调模型）：搭话一类在通话和外观之间，摘要显示开或关；二级页拨了以后刷新，状态还在；存不上时拨回去并提示；后台关掉总开关后这一类不见了，直接打开网址回到 `/settings`；手机宽度下一级、二级都正常。
- 判断题（没改）：
  - 账号读回来之前一级列表里没有「搭话」，读回来后才插进去，下面几行往下跳一行（48px）。换成先占位的话，部署者没开搭话时又会反过来闪一下。
  - 部署者没开搭话时直接打开 `/settings/reach-outs`，电脑上右栏会先闪一下只有标题「搭话」的空页，再回到 `/settings`。
  - 存的时候开关禁用，这一点和「外观」页不一样（外观存在本地，不用等）。
  - `account?.reach_outs ?? null` 在设置的 layout、`SettingsValues`、`ReachOutsSettings` 里各读一次，没收成一处。

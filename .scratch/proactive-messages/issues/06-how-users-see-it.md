# 06: 原型：用户怎么看到

Type: prototype
Status: resolved
Blocked by: 02

## Question

做一个能点的原型，让用户看了再定：

- 对话列表上怎么标出「她给你发了消息」：未读的点、数字、加粗最后一句，还是只靠排到上面。
- 用户正开着网站时，主动消息冒出来是什么样：列表里那一行更新、对话页里直接出现、要不要有个轻提示。轮询多久一次。
- 对话里一条主动消息怎么显示：和她平常的回复一样，还是带点区别（例如显示时间）。
- 用户在哪里关掉：设置里的一个开关，还是也能在她的对话页里关。

前端先读 `frontend/AGENTS.md` 的「shadcn 纪律」，视觉以 `DESIGN.md` 为准，文案要少。原型放在 `prototype/proactive-messages` 分支。

## Comments

- 「拍板：主动消息是什么」已定：「没看过的搭话」记在服务器上，在任何设备上打开所在对话就算看过；这里只定怎么显示。搭话算往来，对话列表最后一句显示它、她会排上去。
- 「拍板：发不发、发几条」已定：用户的开关只有设置里一个总开关，存在服务器上，默认开，不做在她的对话页里按角色关；最后一问只剩开关放在设置的哪一页、文案怎么写。每位用户每天最多被搭话几次（默认 3 次），用户开着网站时一天里冒出来的也就这几条。

## Answer

按原型里建议的混搭定（2026-10-19，看了 `prototype/proactive-messages` 分支上的三个变体）。原型推在 origin 的 `prototype/proactive-messages`（616a815），挂在真实的对话列表、对话页和设置上，`?rv=A|B|C` 切换，右下角面板造假搭话；构建时带 `NEXT_PUBLIC_PROTOTYPE=1` 才显示。不进 main。

1. **对话列表**：有没看过的搭话的那一行，时间旁边一个她颜色（`her-mark`）的小圆点，不出数字。数字没意义：她搭过话就等用户回，一段对话里最多只有一条没看过的搭话，数字永远是 1。最后一句照常显示这次搭话（「拍板：主动消息是什么」第 5 条），她跟着排上去；名字和最后一句不加深。DESIGN.md「Conversation list」里给未读数留的胶囊改成这个圆点。
2. **导航**：只要有一位角色有没看过的搭话，导航栏和 dock 的「对话」图标右上角一个 6px 前景色小点（和公告铃铛的点同一个样子），用户在设置、礼物页时也看得到。在她的对话页上新到的搭话直接算看过，不标。
3. **开着网站时冒出来**：不弹提示条、不出声音。对话列表那一行就地更新、排到上面，导航出小点；用户正开着她的对话页时，搭话直接出现在消息区底部，和回复一样跟着滚到底（往上翻着时不抢）。
4. **轮询**：标签页在前台时每 60 秒拉一次对话列表，切回标签页时马上拉一次；后台标签页不拉。拉到的显示正开着的那段对话有新搭话时，重新读那段对话。搭话以小时计，晚一分钟看到无妨，不另开推送通道。
5. **对话里的样子**：和她平常的回复一样（头像、名字、日语加字幕、时间），不加标签、不加「新消息」分隔线。搭话总是对话里最后一条，分隔线是多余的。但**搭话另起一组**：它前面总是她自己几小时前的回复（用户回了才会再搭），照现在的分组规则同一天里会并成一组，头像名字不重复、上一条的时间也被吞掉，看着像一口气说的。所以搭话和前一条她的话之间断开分组：上一条留着自己的时间，搭话重新带头像和名字。历史对话里也一样。
6. **用户的开关**：设置里单独一类「搭话」，放在「通话」和「外观」之间；一级列表那一行下面的摘要写「开」或「关」；二级页只有一个开关「她们会主动搭话」，拨了马上存到服务器，没有说明小字。不放档案页：档案是一张要按「保存」的表单，放一个拨了就生效的开关别扭。部署者没开总开关时，这一类整个不出现（服务器告诉前端总开关的状态）。

# 15: 看板「搭话」一节

**What to build:** 看板「用量」标签里加一小节「搭话」，显示时间范围内搭了几次、失败几次、被回的占比，管理者据此判断这个功能有没有用、常量要不要调。规格见 `../spec.md`「运行记录和看板」，依据是 `07-dashboard-and-public-docs.md` 第 1 条。

**Blocked by:** 08

**Status:** done

- [x] **被回了没有**：一次搭话之后、下一次搭话之前，用户在这段对话里有了一个回合，或接通了一次通话，就把这次搭话的运行记录标成被回了。要找到是哪条记录，靠「搭话」表里记下的运行记录。运行记录表补一列，旧库在启动时补上。
- [x] **看板接口**：「搭话」一节给三个数：
  - 成功几次；
  - 失败几次；
  - 被回的占比，即被回的次数 ÷ 成功的次数。

  总开关关着、而且范围内也没有搭话记录时，这一节为空。不按角色拆，不进用户页。
- [x] **前端**：「用量」标签里加这一小节，为空时不显示。文案要短。
- [x] **测试**：
  - 后端：
    - 回合和接通的通话会把搭话标成被回了；送礼、没接通的通话不算。
    - 下一次搭话之后的回合，不算到上一次搭话头上。
    - 三个数都对。
    - 总开关关着且没有记录时，这一节为空。
    - 先例：`test_activity_records.py`、`test_affinity_dashboard.py`。
  - 前端：看板如果已有纯逻辑测试，补上「为空时不显示」。
- [x] **验收**：在本地构建版上造几次搭话，回了的、没回的、失败的都要有，用 Playwright 看这一节的数对不对。
- [ ] `sh scripts/affected-tests.sh <基点>` 通过，推送后 CI 全绿。

## Comments

### 票 08 交接

- 「搭话」表的 `record_id` 是那次搭话的运行记录 id（成功的才有搭话行）。
- 看板 `dashboard()` 里 `recorded` 是全部记录，`records` 是滤掉搭话以后的；这一节从 `recorded` 里取 `kind == "reach_out"` 的。

### 票 10 交接

- 「搭话」行先写下（`Store.add_reach_out`，同一事务里再查一遍），运行记录 `finish("success")` 之后才用 `Store.reach_out_recorded_as` 补上 `record_id`，两步不在一个事务里。中间这一瞬用户有了回合，按 `record_id` 找运行记录标「被回了」时会漏。要紧的话，标的时候按搭话行找、或在这里把两步合起来。
- 被作废的搭话运行记录 `result = "rejected"`，没有搭话行；「失败几次」只数 `failed`。

### 票 15 收尾

- 「被回了」在 `Store.add_turn`、`Store.keep_call` 的同一事务里标：按这段对话最新一次搭话的 `record_id` 把运行记录的 `answered` 置 1。票 10 交接说的空档在 `Store.reach_out_recorded_as` 补：写入 `record_id` 时，这次搭话之后已有往来就当场按这个 id 标上。数据包导入不走这两处，不会误标。
- 验收在本地库的副本上做（启动时补上了 `answered` 列）：直接往副本写了搭话运行记录，包括成功被回 2 条、成功没回 1 条、失败 1 条、作废 1 条，另有一条两天前的成功记录。24 小时一档显示「成功 3 / 失败 1 / 被回了 66.7%」，7 天一档显示「成功 4 / 失败 1 / 50%」。总开关关着、没有记录时整节不出现；手机上一行两张。没有调模型，也没打通话。
- 审查留下的判断题，只记下，没有改：
  - Store 直接写 ActivityLog 的 `activity_records` 表（靠 `tables()` 判断表在不在），换来标记和记回合、记通话在同一个事务里。更干净的做法是把这条 UPDATE 收进 `database.py`，或者让 ActivityLog 暴露一个接受连接的函数。
  - 总开关关着、范围内只有「作废」的搭话记录时，这一节照样出现，显示「成功 0 / 失败 0 / —」。这是按 spec「没有搭话的记录」的字面做的；如果要按 07「没有搭话」的意思，就把作废的记录排除掉。
  - 通话要挂断、记下以后才算被回了，通话进行中看板还算没回。通话中不会有新的搭话，所以不影响「下一次之前」这个判断。
  - `reach_out_recorded_as` 补标的那条路径没有测试：要在两个线程步骤之间插进一个回合，通过接口造不出来。
  - 「好感度」的数字卡直接写在 JSX 里，「搭话」抽成了 `reachOutTiles` 再 map（为了能做纯逻辑测试），同一页里两种写法并存。

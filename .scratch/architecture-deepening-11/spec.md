# 架构加深（第十一轮）：酒吧的场景归一处，光顾的会话搬出 React

Status: ready-for-agent

术语以 `GLOSSARY.md` 为准，本轮不改 GLOSSARY。「场景」「会话」只是代码里的结构，不是领域词。设计词汇（module、interface、seam、adapter、depth、locality）取自 `codebase-design` skill。

这是 2026-10-27 架构审查里的候选 2「光顾的场景只归 barVisit，教程只往里送台词」和候选 3「一次光顾的会话搬出 React」，设计经 grilling 定下。只改前端。画面上的叫法（文本框、调酒台、摇酒器、备忘、结束卡、店门口）沿用规格「酒吧的店面」（`.scratch/bar-room/spec.md`）。

## Problem Statement

光顾（GLOSSARY「光顾」）和教程（GLOSSARY「教程」）在画面上是同一套东西：文本框一页页打字，她的表情跟着她的台词变，点单句读完开调酒台，调好上酒。可是这套规则现在没有一个归属的地方。

- **光顾的画面状态管着两件事**。一件是场景：文本框、她的表情、调酒台、摇酒器、备忘。另一件是光顾特有的：店门口、进门中、再营业，第几次调用和重来时清掉的台词，出错和再试一次，上酒锁定，结束卡。
- **教程只要场景，却拿着整份光顾状态，还绕开它的转移直接改字段**：
  - 上酒时自己拼出「调酒台收起、杯子倒掉、下一句马上打」，比光顾的上酒少设了一个字段；
  - 开台时自己拼出「调酒台打开、摇酒器清空、备忘换成这一课的」；
  - 送台词前手动把「下一句马上打」设成真。
- **结果就是光顾状态的内部字段成了两边的约定**。「点单句要点过去才开调酒台」（783d2f9e）这一条在两边各改了一遍。
- **两边的 hook 有一段重复**：先载入像素字，再按她的名字分页；上不了酒响一种声音，上了响另一种。
- **光顾的接口调用全在一个 React hook 里**：进门、再营业、上酒、再试一次、离开，加上中止、迟到的错误、中途断了、409、410 的处理。hook 在 reducer 之外又存了一份状态：服务器那边有没有这次光顾、她是谁，还有一份手动同步的「最新状态」，上酒和再试一次时还手工改这份副本。
- **「服务器收下了没有」有三种判断法**：
  - 进门是边读边抛错的事件流，只能看「有没有收到过 visit 事件」来区分被拒和中途断了；
  - 上酒和再试一次先等回应、再给事件流，用一个局部变量来区分；
  - 另外还有「没等到 waiting、failed、done 就完了，算中途断了」。
- **这些规则都没有测试**。vitest 没配 jsdom，hook 一个都测不到；现在只能靠本地验收。
- **画面那一层要不停地问「现在是教程还是光顾」**，同样的三元判断写了 6 处。

## Solution

- **场景成为一个单独的 module**，文本框、她的表情、调酒台、摇酒器、备忘的规则都在这里，开台的规则只写这一处。光顾和教程都建在它上面：
  - 光顾只管店门口、调用、出错、上酒锁定、结束卡；
  - 教程只管按节送台词、上酒后的反应、走完去哪。
- **光顾的会话成为一个不依赖 React 的 module**。它自己保存光顾的状态，处理全部接口调用和异常情况，接口调用从外面传进来；hook 只剩接上画面。
- **进门、上酒、再试一次三个接口调用统一成同一个形状**，「收下了」只有一种判断法。
- **光顾和教程交出同一个形状的「当前场景」**，画面那一层只挑一次。

用户看到、听到的都不变。

## User Stories

### 光顾（行为不变）

1. 作为制作人，我想点店门口进门时马上响门声、开始放曲目，她进门后文本框一页页打字。
2. 作为制作人，我想她的台词以每秒 30 字打出来，点一下立刻打完，打完再点翻到下一页。
3. 作为制作人，我想她的表情跟着文本框上她那一句变，台词在打字时她的嘴在动，同时响她的打字音效。
4. 作为制作人，我想她的点单句打完以后停在框上、箭头在跳，我点过去，并且她在等我上酒，两样都到了调酒台才开；两样哪个先到都行。
5. 作为制作人，我想调酒台开着时文本框显示这一单的备忘，不显示她那一句。
6. 作为制作人，我想在调酒台上加料、摇、倒掉，和现在一样。
7. 作为制作人，我想摇酒器里的东西上不了时点「上酒」只响一声「不行」，什么都不发。
8. 作为制作人，我想上酒被收下时响上酒的声音，调酒台收起、杯子倒掉，「请慢用」一到马上顶掉点单句开始打。
9. 作为制作人，我想上酒期间调酒台锁着，连点两次也只发一次。
10. 作为制作人，我想上了一杯坏掉的（422），摇酒器显示坏了，调酒台照旧开着，可以重调。
11. 作为制作人，我想上酒时这次光顾已经没了（410），回到店门口并看到提示，之后离开不再发「离开这次光顾」的请求。
12. 作为制作人，我想上酒被拒的其他情况（比如 409 连点）一切照旧。
13. 作为制作人，我想调用出错时文本框显示那句话和「再试一次」，点了以后锁住，等服务器回应。
14. 作为制作人，我想服务器收下再试一次时，这次调用已经来的台词（打完的、没打完的）都清掉，框回到它们之前那一页；已经说过的「请慢用」不清。
15. 作为制作人，我想服务器发来「重来」（retrying）时也同样清掉这次调用的台词。
16. 作为制作人，我想再试一次时光顾已经没了（410），回到店门口；其他拒绝（409）照旧。
17. 作为制作人，我想光顾中途调用断了（抛错，或者没等到 waiting、failed、done 就结束了），回到店门口并看到「光顾没了」的提示。
18. 作为制作人，我想她告别（done）以后，读完她最后一页才出结束卡，结束卡说得了几次抽奖、好感度有没有上升。
19. 作为制作人，我想当天第一次玩完得了抽奖时，礼物那边的抽奖次数马上刷新。
20. 作为制作人，我想点结束卡上的「再营业」时只响门声、曲目接着放，下一位直接进门，不回店门口。
21. 作为制作人，我想「再营业」以后，上一位那次还没关的调用晚到的错误，不会把这一位送回店门口。
22. 作为制作人，我想进门被拒时店门口说明原因：超了限额就说几点再来；只能用自带密钥时用服务器的原话；其他情况一句短话，可以再点。
23. 作为制作人，我想进门时酒吧已经关了（409），直接回玩法页。
24. 作为制作人，我想点「离开」、换到别的页或者用浏览器返回时，这次调用关掉，服务器那边这次光顾也离开。
25. 作为制作人，我想关页面或刷新时，也尽量发出「离开这次光顾」的请求。
26. 作为制作人，我想她告别以后离开，不再发「离开这次光顾」的请求。
27. 作为制作人，我想角色列表读到之前点店门口不会进门。
28. 作为制作人，我想文本框上她的名字照她的短名写，没有短名就写全名。

### 教程（行为不变）

29. 作为制作人，我想第一次进酒吧时是 はづき 的教程：她按台词一节节说，我点着往下读。
30. 作为制作人，我想一节教调酒的台词读完、最后一页点过去，调酒台就开，文本框显示这一课的备忘。
31. 作为制作人，我想教程里上酒时，她按我调出的那款说对应的反应，调出别的就说「其他」那一句；坏掉的上不了。
32. 作为制作人，我想教程里上不了酒时响「不行」，上了响上酒的声音。
33. 作为制作人，我想教程里上酒以后调酒台收起、杯子倒掉，她的反应马上开始打。
34. 作为制作人，我想教程走完去选曲界面；没有点唱机（没有音频）时跳过那一节，直接回店门口。
35. 作为制作人，我想点「跳过」时教程立刻结束，去处和走完时一样。
36. 作为制作人，我想教程走完或跳过时记在这台设备上，中途离开不记。
37. 作为制作人，我想教程里一直循环放 Every Day is Night，结束时停下。
38. 作为制作人，我想在店门口点「教程」可以重看。

### 开发者

39. 作为开发者，我想场景的规则（打字、翻页、表情、开台、调酒、上酒后收起、清掉某次调用的台词）只写在场景这一处，光顾和教程都不碰它的内部。
40. 作为开发者，我想开台只有一条规则：标记过的那句台词被点过去了，并且「可以开台」连同备忘已经给了。
41. 作为开发者，我想直接对场景测它的规则，不用经过光顾或教程。
42. 作为开发者，我想光顾的测试只测光顾特有的规则。
43. 作为开发者，我想教程的测试只看公开的查询，不断言内部字段。
44. 作为开发者，我想光顾的会话不依赖 React，接口调用从外面传进来，可以用假的事件流在 node 里测它。
45. 作为开发者，我想「服务器收下了没有」只有一种判断法，而且只写在会话里。
46. 作为开发者，我想光顾的状态只存一份：在会话里，hook 只读它的快照。
47. 作为开发者，我想画面那一层只挑一次「当前场景」是教程的还是光顾的。
48. 作为开发者，我想「载入像素字后按她的名字分页」只写一处。
49. 作为开发者，我想会话的写法和对话页的 LiveConversation 一样（自己存状态，给 subscribe 和 snapshot），读代码的人只要认一种模式。

## Implementation Decisions

### 场景 module `barScene`

- 它的纯状态和转移管这些：文本框里排着的台词和正在显示的那一页、打到哪个字，她的表情，调酒台开没开，摇酒器，备忘。查询照现在的：文本框此刻显示什么、调酒台开着时文本框说的备忘、谁的台词在打字、她的嘴动不动、箭头跳不跳。它不管店门口、调用、出错、结束卡。
- **台词**：送进来的台词要分好页。每句可以带两样：
  - 一个标记，现在用来标是第几次调用；
  - 「点过去就开台」。

  框在等下一句时，新来的一句马上显示；不在等时排在后面。
- **点**：没打完就一下打完。打完了就翻到下一页；没有下一页就等下一句。
- **开台只有一条规则**：标记过「点过去就开台」的那句的最后一页被点过去，并且「可以开台」连同备忘已经给了，两样都到了才开，先后不限。开台时摇酒器清空，文本框换成备忘。
- **调酒**：只在调酒台开着时起作用。
- **上酒后收起**：调酒台收起、摇酒器清空，下一句马上显示。
- **清掉某个标记的台词**：带这个标记的台词，打完的、没打完的都清掉，框回到它们之前那一页（已经打完的状态），表情也回到那时的；下一句马上显示。
- 共用的分页小函数放在场景旁边：先载入像素字，再按她的短名（没有就用全名）和制作人的称呼分页。光顾和教程都用它。

### 光顾 `barVisit`

- 建在场景上面，只管光顾特有的：
  - 店门口、进门中、店里、再营业中，以及店门口的提示；
  - 这次光顾是谁；
  - 第几次调用，「请慢用」算在下一次调用里、不跟着清；
  - 重来（retrying）和再试一次被收下时，清掉这次调用的台词；
  - 出错和再试一次进行中；
  - 上酒进行中（锁定）、被收下、被拒（422 坏掉、410 没了、其他照旧）；
  - 她告别和结束卡。
- 她的点单句带「点过去就开台」。waiting 事件和 memo 事件到了，就算「可以开台」连同备忘。
- 店门口提示（超限额、自带密钥、其他）的规则不变。

### 教程 `barTutorial`

- 建在场景上面，只管按节送台词、上酒后选反应、走完或跳过去哪。不再带光顾的状态，也不再直接改场景的字段。
- 教调酒的那一节，最后一句带「点过去就开台」，「可以开台」连同这一课的备忘随这一节一起给。
- 上酒：按摇酒器调出的那款选反应，先让场景「上酒后收起」，再送反应那几句。
- 「看过」记在这台设备上的规则不变。

### 光顾的会话 `BarVisitSession`

- 不依赖 React，写法照对话页的 LiveConversation：
  - 它自己保存光顾的状态（经 `barVisit` 转移），对外给 subscribe 和 snapshot，快照只在变化后换新对象；
  - hook 用 useSyncExternalStore 读。不再有 useReducer，也不再有手动同步的那份副本。
- **建的时候传进来的东西**：
  - 接口调用：进门、上酒、再试一次、离开；
  - 分页用的东西：角色列表和量字；
  - 计时：此刻的毫秒数；
  - 几个通知：酒吧关着（回玩法页）、得了抽奖（刷新礼物那边）、要响的音效（上了酒、上不了）。
- **它对外能做的**：进门、再营业、点文本框、调酒、上酒、再试一次、离开，以及关掉（页面走开时带 keepalive）。
- **全部收在它里面的**：
  - 服务器那边有没有这次光顾、她是谁；
  - 中止上一次调用；
  - 迟到的错误不起作用（不是当前这次调用的就丢掉）；
  - 中途断了回店门口；
  - 409 时通知酒吧关着；
  - 410 以后离开不再发「离开这次光顾」；
  - 她告别以后离开也不再发；
  - 再营业时关掉上一位还开着的调用。
- **留在 hook 里的**：
  - 门声和建 AudioContext，必须在点击里同步调；
  - 打字时每个字重画一次的计时；
  - pagehide 时用 keepalive 关掉，组件卸载时关掉；
  - 路由跳转。

### 接口调用统一形状

- 进门、上酒、再试一次都改成：先等服务器回应，拒了就抛错（带状态码），收下了就返回这次调用的事件流。
- 会话判断「收下了」只看这一点；事件流在 waiting、failed、done 之外结束，算中途断了。
- 离开不变。

### 画面那一层

- 教程和光顾都交出同一个形状的「当前场景」：场景本身、此刻的时间、点、调、上。
- 画面那一层只挑一次用哪个，去掉现在 6 处「是教程就用教程的，否则用光顾的」。
- 其他（选曲界面、设置框、结束卡、店门口、侧边菜单）不变。

### 不变的

- 用户看到、听到的一切不变。
- 事件流的协议、后端、规格「酒吧的店面」里的画面规则都不变。
- ADR-0031（酒吧在本仓库里做）照旧。

## Testing Decisions

- 好的测试只看外部行为：通过各 module 的 interface（转移和查询、会话的方法和快照）看结果，不断言内部字段。
- **场景**：直接对 `barScene` 测，从现有光顾测试里搬过来，测这些：
  - 打字和翻页；
  - 等下一句时新来的马上显示；
  - 表情跟着她的台词；
  - 开台的两个条件，先后都要测；
  - 调酒只在开台时起作用；
  - 上酒后收起；
  - 清掉某个标记的台词，回到之前那一页和那时的表情；
  - 各个查询。
- **光顾**：`barVisit` 的测试只留光顾特有的：
  - 店门口、进门被拒的提示；
  - 第几次调用和「请慢用」不清；
  - 重来和再试一次；
  - 出错；
  - 上酒锁定、被收下、被拒；
  - 结束卡、再营业；
  - 点单句经场景开台：只留一条，证明光顾接上了这条规则。
- **教程**：`barTutorial` 的测试改成只看公开的查询：
  - 调酒台开着时的备忘；
  - 箭头跳不跳；
  - 文本框显示什么；
  - 走完去哪。

  不再断言光顾状态的内部字段。
- **会话**：新加 `BarVisitSession` 的测试，用假的接口调用（测试自己造的事件流，可以挂着、可以中途断）在 node 环境里跑，看它的快照和通知：
  - 进门一路到点单、开台、上酒、告别、结束卡；
  - 中途断了回店门口；
  - 409 时通知酒吧关着；
  - 进门被拒（429 等）时店门口的提示；
  - 410 以后离开不再发「离开这次光顾」；
  - 她告别以后离开也不再发；
  - 再营业时，上一位迟到的错误不起作用；
  - 上酒被拒时状态照旧；
  - 上酒被收下时通知「上了酒」，上不了时通知「上不了」，并且什么都不发；
  - 再试一次被收下、被拒；
  - 关掉时中止调用并离开。

  现有的参照：对话页 LiveConversation 的测试用假的 port 记下调用、看快照，写法照它。
- 计时、pagehide、路由和声音的接法留在 hook 里，不写单元测试，由本地验收来看。
- **本地验收**：在本地构建版上用 Playwright 验，方法照 `docs/agents/local-acceptance.md`「酒吧」一节，在页面里换掉 fetch、手里攥着事件流。
  - 票 01：走完整个教程（开台、上酒、反应、去选曲界面），再走一次光顾到上酒。
  - 票 02：再走一次光顾，并造出上酒被拒（422、410）、出错后再试一次、中途断了、再营业时上一位迟到的错误、进门被拒（429、409）。
- 按 `docs/agents/implementing.md`：本机跑类型检查和受影响的测试，其余交给 CI。

## Out of Scope

- 屏幕选择做成纯函数、声音和音乐合成一个「酒吧音频」（报告候选 5 剩下的部分）。
- 教程做成会话。教程不调接口，仍是 reducer 加 hook。

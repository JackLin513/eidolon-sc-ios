# 01: 走通一封升档的信

**What to build:** 部署者在后台打开「信」以后，制作人和某位角色的好感度第一次升到亲近（或亲密），或者集齐这位角色，过一会儿她就写好一封信。制作人点对话列表页首的信封键，在所有的信的列表里看到这封信，点了整屏出现她的信封，拆开以后她的字一个一个写在信纸上，每段写完淡出中文字幕，信末写上她的名字，点「收好」收起来，信飞回信封键。读过的信换一台设备也算读过。

这一票没有语音（03）、配乐（04）、签名图（06，信末先用信上的字体写她的名字），也不做弹出、她的对话页的入口、删除和按月分组（05）；到了日子才写的信在 02。时间先按字数估。见 spec「场合和条件」「存储」「写信的循环」「写一封信」「接口」「前端」「后台设定和看板」。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 后台设定多一项「信」，只有总开关，默认关，`.env` 的 `EIDOLON_LETTERS` 可以开；在配置页「限额与玩法」标签，搭话后面。关着时什么信都不写，关着时发生的升档和集齐以后也不补。
- [ ] 三张新表（信、信的语音、要写的信）建好、登记进用户数据，随删号删除；旧库启动时自动建表。信的语音这一票还不写入。
- [ ] 好感度第一次升到亲近、第一次升到亲密、集齐这位角色时（成就里同一处判定），在同一个事务里记一条要写的信；掉下去再升回来不再记；成就上线时的补算不记。
- [ ] 后端启动时起常驻循环，每分钟把到了时间的要写的信写出来；测试推进假时钟后直接调「写一遍」。写之前再查：总开关、她在冷淡/疏远/冷却中、封禁、限额为零，不满足的作废。
- [ ] 同一位角色、同一天（制作人档案时区，没填用 `Asia/Shanghai`）的几个场合合成一封；她今天已经写过信的，新场合顺延到第二天。
- [ ] 写信用部署者的对话模型（自带 LLM 的用户也一样），请求照 spec「写一封信」：设定和经历全文、制作人资料、档位语气、「你们之间的事」（第一次说话的日子、回合数只当背景、她自己来源的最近 30 条记忆）、跨对话最近 60 条消息、最近 3 封信、写信的规矩和场合。
- [ ] 解析出抬头和各段；出处不存；中文里的语气提示剥掉；正文去掉语气提示后超过 330 字重写一次，还超照样用；解析不出算失败（这一票失败先不重试，重试在 02）。
- [ ] 每封信一条「信」运行记录（成功、失败、角色、服务调用、用量），「用了自带密钥」为否；回合趋势、限额等按种类计数的地方不把它算进去。
- [ ] 接口：信的列表（id、角色、场合、写信那天、读没读过、弹没弹过，从新到旧）、读一封（抬头、各段去掉语气提示、签名替代文字；语音和配乐字段先为空）、标读过；别人的信一律 404。账号多一个字段说部署者开没开信；没开也没有信的用户看不到入口；关掉总开关后已有的信照样能看。
- [ ] 前端：对话列表页首、服务状态旁一个信封键，有没读过的信时带点；点开是能滚动的列表（电脑浮层、手机底部抽屉），每行她颜色的小信封、名字、场合、日期，从新到旧。拆信这一层照 `last-letter` 分支的信件层重写（整屏压暗、信封、拆开、逐字写、字幕淡出、跳过、读完「收好」、收起飞回信封键、减少动态效果时直接整封），信纸信封固定浅色，字体用 `next/font/google` 的 Klee One、不预载。拆开即标读过。
- [ ] 时间轴是纯函数（字、估出的每块起止 → 每个字的时刻、签名时刻），有单测；它的输入留出「每块的实际时长」，03 接上语音时用。
- [ ] 后端测试走 `make_client` + `FakeLLM`，升档和集齐靠现有的回合、送礼接口触发；照 `test_reach_outs.py`、成就的测试、`test_activity_records.py`、`test_database.py`。
- [ ] 本地构建版上用 Playwright 看一遍：造一次升档，「写一遍」后在列表里拆开这封信，电脑和手机各截一张（`docs/agents/local-acceptance.md`）。

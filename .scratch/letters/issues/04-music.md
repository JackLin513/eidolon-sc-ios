# 04: 配乐，签名落在高潮上

**What to build:** 读信时底下铺着这个场合的配乐，签名那一刻正好是配乐的高潮，高潮放完淡出。部署者用一条命令把配乐传到自己的存储桶；没传的部署信照样能看，只是没有配乐。

见 spec「配乐」「时间轴（浏览器里）」。这一票不依赖语音：没有语音时按估出的签名时刻对齐。

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 仓库里一份配乐清单：每个场合的文件名、高潮起点（没有为空）、淡出点、循环段，数值照 spec 的表（亲近 71、亲密 101 淡出约 148、制作人生日无高潮、她的生日 64 并循环 3–60 秒、相识纪念 212 淡出约 260、集齐 155 淡出约 200）。配乐音频不进仓库。
- [ ] 新命令 `eidolon letter-music upload <目录>`，照招呼语音的上传写法，把按场合命名的文件传到立绘存储桶 `letters/music/` 下。
- [ ] 读一封返回配乐（地址、高潮起点、循环、淡出）；几个场合合在一封时按亲密、亲近、集齐、她的生日、制作人生日、相识纪念取第一个；部署者没配立绘素材地址时为空。
- [ ] 前端对齐是纯函数，有单测：签名时刻 S、高潮起点 P；P ≥ S 时从第 P − S 秒开始放；P < S 时从头放；没有高潮的从头放；她的生日那首在 3–60 秒那段之后接回去循环，直到 64 秒的高潮落在签名上或之后，再接尾段。
- [ ] 签名之后放到淡出点淡出；没有高潮的那首签名写完几秒后淡出。她念的时候配乐压低、念完起来（03 没合并时就是一直压低到签名，音量在验收时调）。静音键同时静掉配乐。
- [ ] 取不到配乐（没上传、404）时安静地没有配乐，信照常。
- [ ] 后端测试：上传命令（照招呼语音上传的测试）、读一封里的配乐字段和合并时的取法。
- [ ] 把用户提供的六首（仓库外 `E:/tmp/bgm/src/`）传到线上桶这一步留给用户确认后再做，传完删本地原曲；在 Comments 里写明。

## Comments

### 票 01 交接

- 读一封的 `music` 现在恒为 `null`；合并时的取法可以直接用 `letter_prompt.OCCASIONS` 的顺序（亲密、亲近、集齐在前）。

### 票 03 交接

- 她的声音在 `components/letter/letterVoice.ts` 的 `LetterVoice` 里：拆开那一下建的 `AudioContext` 和一个总音量 `GainNode`（静音键就是把它设成 0）。配乐接同一个上下文、接在这个总音量后面，静音键就能一起静掉；或者把 `LetterVoice` 扩成管整封信的声音。浏览器只让在点击里建的上下文出声，配乐别另建。
- 每块语音在开口算起的第几秒放就是 `partsOf(letter, durations)` 各块的 `start`，到 `end` 念完：「她念的时候配乐压低」照这些时刻在配乐的音量上排 `setTargetAtTime` 即可。签名时刻 `signsAt(parts)` 已经是按实际时长排的。
- 音频时钟停住时拆信层改按时钟写并 `stop()` 声音（`lib/letter` 的 `tick`）；配乐也要跟着停或淡出。

# 03: 她的声音念信

**What to build:** 拆开信以后，她用自己的声音念，字跟着她念到哪里写到哪里；重看时一样有声音。部署者没有语音合成、或者合成失败时，信照样来，只是没有声音，字按估的时间写。读信时能静音。

见 spec「写一封信」的语音一条、「时间轴（浏览器里）」「接口」。

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 信写好后，用部署者的语音合成和它的模型，把抬头和每段分别合成成 mp3（照朗读的请求写法：语气提示按模型的规矩、读音词典、`latency: normal`），存进「信的语音」；自带语音合成密钥的用户也用部署者的。
- [ ] 语音合成失败或部署者没有语音合成时，信照样存下来，读一封里语音为空；不算写信失败，运行记录里记下没合成；合成的服务调用挂在这封信的运行记录下，用量和花费进看板。
- [ ] 读一封返回每块语音的地址；取语音的接口只给信的主人（别人 404），`Cache-Control: private` 加长期缓存（照照片）。
- [ ] 前端拆开时取下全部语音，用 Web Audio 解码，按每块时长排时间轴：信纸展开后 1.2 秒开口，抬头后停 0.6 秒、段间停 0.9 秒，最后一块念完 0.8 秒后签名，签名 1.6 秒（和旧版一致）。取不到或解码失败时退回按字数估。网络卡住时不让字和声音对不上（旧版有处理，照着做）。
- [ ] 右上角静音键。
- [ ] 时间轴按实际时长排的情形补进 01 的纯函数单测。
- [ ] 后端测试用 `FakeFishAudio` 经 `fish_transport` 传进 `make_client`（照 `test_read_aloud.py`）：抬头和每段各一次请求、用部署者的 key 和模型、拒绝时信照样存。
- [ ] 本地构建版上自己验声音能放、字跟着走；好不好听留给用户在本机浏览器里听。
